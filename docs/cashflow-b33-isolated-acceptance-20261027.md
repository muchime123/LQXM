# B-3.3 年度期初更正隔离验收（2026-10-27）

## 实现

- 迁移 `V414__cashflow_opening_correction.sql` 增加追加式更正记录及独立 `cashflow.opening.correct` 权限；迁移不自动授予任何正式角色。
- `POST /api/cashflow/accounts/opening/{id}/corrections` 保存待应用申请；`POST /api/cashflow/accounts/opening/corrections/{id}/apply` 原子应用；`GET /api/cashflow/accounts/opening/{id}/corrections` 查询历史。两个写操作均要求请求键、独立权限和 `CASHFLOW=ALL` 范围。
- 申请保留旧金额、新金额、原确认状态、原确认记录 ID、原因、外部依据编号、申请人及时间；应用记录操作人及时间。旧 `cashflow_opening_confirmation` 历史不修改。应用保持 `active=1`，金额变化后重置 `finance_confirmed=0`，新金额须重新确认。
- 更正申请和应用的业务写入、幂等结果及审计处于同一事务。更正表一次只允许同一期初存在一条待应用申请；金额和确认状态变化时应用返回冲突。
- 页面在年度期初弹窗展示更正历史、申请表单及应用确认；应用后刷新账户报表。预览与更正历史金额以十进制字符串传输。

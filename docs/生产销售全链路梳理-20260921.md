## 1. 结论先行

### 1.1 利强不是"一个工厂"，而是两条生意共用一套销售出库

| 产品线 | 性质 | 出库明细行 | 销售额 | 占比 |
|---|---|---:|---:|---:|
| **A 自制机器 + 模具 + 配件** | 车间生产后销售 | 8,939 | **3,087.1 万** | **45%** |
| **B 贸易包装耗材** | 采购后直接销售 | 20,571 | **3,447.8 万** | **50%** |
| C 费用（运费 / 制版费） | 随单附加 | 4,755 | 154.0 万 | 2% |
| D 未归类（其他 / 空） | — | 894 | 168.1 万 | 2% |
| **合计** | | **35,159** | **6,857.8 万** | 100% |

统计窗口：销售出库 2026-01-01 ~ 2026-09-17（出库台账**只有 2026 年**）。
收款：已收 5,789.6 万，未收 1,068.2 万。

**只有 A 线有生产环节。B 线是纯贸易，没有工单、没有报工。**

### 1.2 三条关键判断

1. **生产域内部是完整的**：工单 → 报工 的关联 100% 精确（12,252 行报工、零孤立、命中 4,997/5,691 工单）。这一段的氚云数据质量是全部 20 类里最好的。
2. **销售 ↔ 生产 是断的**：工单上的「销售订单编号」「关联销售订单」「产品订单子 OBJ id」**全部为空**，`计划类型` **100% = 「非合同生产」**；反过来，出库单里搜工单号 **0 处命中**。这条链目前**靠人在脑子里对**，系统里不存在。
3. **"采购入库"不是纯粹的采购**：它同时承载**外部采购**（包材厂）和**内部车间完工入库**（永铭 / 强子 → 利强）。机器和模具本身也是从这张表"买"进来的。

## 4. ★ 工序详解（你问的核心）

### 4.1 氚云里的"零部件"其实是工序模板

报工表有个字段叫「**零部件流水号**」，容易被误读成 BOM。**它不是 BOM —— 全氚云只有 10 个值，是 10 个固定工序。**

| 流水号 | 工序名 | 报工行数 | 工单构成行数 |
|---|---|---:|---:|
| 202500000001 | 电和气安装 | 564 | 621 |
| 202500000002 | 零部件组装/所有组件 | 564 | 621 |
| 202500000003 | 控制板面板 | 29 | 29 |
| 202500000005 | 表面处理/氧化 | 564 | 621 |
| 202500000006 | 模具加工 | **4,692** | **5,503** |
| 202500000007 | 钣金加工/机壳 | 564 | 621 |
| 202500000008 | 采购/下料 | 567 | 625 |
| 202500000009 | 设计/画图 | 2,407 | 2,649 |

| 202500000013 | 安排组装 | 1,731 | 2,450 |
| （空） | | 6 | 6 |

**关键判断**：
- 工序是**固定枚举模板**，不是可增长的主数据

- **氚云从未启用领料** → 材料实耗、损耗率**无源**

### 4.4 检验环节：已拍板（U4 ✅ 09-21）—— 且比预想严重

对比 §4.2 和 §4.3 可以看出：

> **规范路线里的第 12/13/14 道（调试检验 / 试模检验 / 完成确认）在氚云报工里完全没有数据 —— 一道都没有。**

气调机模板 9 道，氚云实报 8 道，**差的正是最后那道「调试检验」**。

也就是说：**这三道检验工序是设计阶段补出来的，不是从实测数据里发现的。**

**LQ 已确认（09-21）**：车间**实际没有出厂检验动作**（无签字/打勾），只有出厂前的机器调试。

**⚠️ 但这不只是"建还是拆"的选择题 —— 它是个会卡死闭环的硬闸门：**

| 事实 | 证据 |
|---|---|
| 订单级检验是**必经过渡态** | `recalculate()` 在 `remaining==0` 时**无条件**置 `PENDING_INSPECTION`，只能由 `inspect()` 推进 |
| 而 `inspect()` **要求填检验员 + 合格数** | 无检验岗 → 无人调用 |
| **7 条路线的末道工序全是检验类，且 `required=1`** | 车间报完就掉进闸门 |
| **活体证据** | `MO00000018` 三道工序全 COMPLETED → 卡 `PENDING_INSPECTION` **17 天**，`inspection_at` 仍为 NULL；全库 `manufacturing_inspections` **0 行** |

**已定处置（决策登记 #16）**：**模块保留不删，订单级检验改为「末道工序报工即自动确认」**；开关 = 末道工序的 `requires_inspection`（当前三道全 = 0 → 全自动），将来增设检验岗改 1 个字段即可切回人工。

> 完整推导、实现要点与口径声明见 **`检验环节处置方案-20260921.md`**。
> ⚠️ 该自动记录的语义是「**工序完成事实**」，**不是内控检验** —— 页面/报表不得写成"已检验合格"。
> 另：LQ 说的"机器调试"= 系统里的 `ASSEMBLY_DEBUG 组装调试`（氚云 **564 行 / 794 台** 真实数据，是气调机 8 道链的最后一道）。**这一道不需要新建任何东西。**

> 另：氚云的「控制板面板」(29 行) 与「安排组装」(1,731 行) 在 14 道规范工序里**没有一对一对应**（推测「安排组装」→ 整机装配，但设计侧未标注）。落地前需补一张**原始工序 → 规范工序的映射表**并标注未映射项。

**真实形态**：

```
永铭 / 强子（生产主体）
    │  车间生产 → 完工
    │
    └── 通过「采购入库」内部结算给利强（含独立「加工费」1,244 行）
              │
              ▼
        利强（经营主体）库存 → 销售出库 → 客户 → 收款
```

> 即：**A 线在系统里的表现是"利强向永铭/强子采购机器"**，不是"利强自己生产机器"。报工记录挂在永铭/强子名下，销售回款挂在利强名下。这是理解整条链最关键的一点。

⚠️ **ERP 不得照搬这张表结构** —— 一张表混外部采购 + 内部完工入库，是 C4「一行多角色」的又一实例。

## 6. ★ 断点清单（最该看的一节）

| # | 断点 | 实证证据 | 后果 |
|---|---|---|---|
| **B1** | **销售订单 → 生产工单** | `linked_sales_order_no` **0 / 5,691**；`product_order_external_id` **0**；`linked_sales_order_ref` 空；`plan_type` **100%「非合同生产」**；`sales_contracts` 表 **0 行** | 无法回答"这张工单是哪笔生意带来的"；订单占用 / 交期承诺 / 执行进度全无从建立 |
| **B2** | **生产工单 → 销售出库** | 出库单表与明细表搜 `SCGD` **0 处命中**；两侧无任何 ID 关联字段 | 无法回答"这台机器发给谁了"；售后追溯、质保、召回全部做不了 |
| **B3** | **产品名称粒度不一致** | 工单产品名 40 个（如"手动片膜"）；出库明细产品名是具体规格（如"250手动片膜"）→ **匹配 0 / 40** | 连"按名称猜关联"都做不到 |
| **B4** | **客户名不可靠** | 工单客户 1,484 个，仅 **243 个（16%）**能在出库客户里按名称对上。工单里写的是简称：`L`、`LEO`、`武汉 刘总`、`宏展涂晓飞` | 客户维度也无法反推 |
| **B5** | **完工入库无独立单据** | 只是工单的 `warehoused_quantity` 字段；无入库单号、无入库时间 | 与"报工完成"不可区分；检验/待检状态无处表达 |
| **B6** | **领料完全不存在** | `manufacturing_material_movements` **0 行**；`生产工单中是否有该零部件` 全 0；`是否使用零部件库存` 全「否」 | 材料成本、损耗率无从归集 |

**一句话总结**：氚云把 **"厂内生产"这一段做得比较扎实**（工单 → 报工精确可关联），但 **"生意"这一段是空的** —— 既没有订单，也没有工单与出库的关联。**中间靠人。**

> 这正是 ERP 首批切片（决策登记 #1：浙江利强 + 温州仓 + 全自动气调机）的价值所在：**它要新建的正是这两条断链**，而不是把氚云搬一遍。

## 7. 数据质量提醒（别当 bug 报）

1. **`sales_outbound_items.category` 一列混了三种语义**（54 个值）：
   - 包材材质：塑料盒 / 铝箔盒 / 透明膜 / 铝箔盖 / 圆碗
   - 机器类型：手动片膜 / 气动 / 按钮自动 / 半自动 / 手推自动
   - **供应商名**：耀星 / 跃远 / 吉源 / 立腾 / 鼎业
2. **出库明细 `stock_quantity`** 是当时快照，混有异常值（运费行 19734）→ 禁止当库存
3. **采购入库 `supplier_name_raw` 是组合文本**：值形如 `"封口机车间    合作中"`，不是纯名称
4. **工单 `warehoused_quantity` 与 `warehousing_completed` 语义不一致**（见 §3.5）
5. **两个数据源时间窗不同**：出库台账 2026-01-01 起；工单 2025-04-05 起 → 跨年比对会缺一段
6. **`production_orders` 状态里没有"已完工"**：完工靠 `production_progress = 100%` 表达，状态只有 草稿 / 进行中 / 已生效 / 已取消

## 8. 对 ERP 首批切片的设计含义

1. **切片选得对**：全自动气调机正好是 **9 道工序的最长路线**，且跨"利强 ← 强子"内部结算 —— 能一次性压到最多问题。
2. **核心增量是补两条链，不是搬数据**：
   - 新建 `sales_order_line_id` 落到工单（解 B1）
   - 新建 `production_order_id` 落到出库明细行（解 B2）
   这两件事氚云**完全没有能力**，正是 ERP 的价值。
3. **完工入库要成为独立单据**（不能是工单上的字段），否则无法表达待检 / 合格 / 冻结状态（解 B5）。
4. **不要把「采购入库」当模板**：必须拆成「外部采购收货」与「内部完工入库」两种单据。
5. **必须先出一张「原始工序 → 规范工序」映射表**，标注未映射项（控制板面板 / 安排组装），否则 14 道工序主数据会与历史对不上。
6. **检验环节已拍板（U4 ✅ 09-21）**：实际无检验动作 → **模块保留、改为末道工序报工自动确认**（决策登记 #16）。⚠️ 注意这不是"建或拆"的选择题 —— `PENDING_INSPECTION` 是硬闸门，不处置则工单**永远无法完工入库**（`MO00000018` 已卡 17 天为证）。详见 `检验环节处置方案-20260921.md`。

## 附：本文数字的核查命令

```sql
-- 两条产品线金额
SELECT CASE WHEN category IN ('手动片膜','气动','按钮自动','半自动','手推自动')
            THEN '机器' ELSE '其他' END g,
       COUNT(*), ROUND(SUM(sales_total)/10000,1)
FROM product_archive.sales_outbound_items GROUP BY g;

-- 断点 B1
SELECT COUNT(*) total,
       SUM(linked_sales_order_no IS NOT NULL AND linked_sales_order_no<>'') has_order
FROM product_archive.production_orders;

-- 断点 B2
SELECT COUNT(*) FROM product_archive.sales_outbounds
WHERE external_title LIKE '%SCGD%' OR order_remark LIKE '%SCGD%';

-- 工艺路线 × 实际工序
SELECT po.process_name, r.component_name, COUNT(*)
FROM product_archive.h3_production_reports r
JOIN product_archive.production_orders po ON po.work_order_no = r.work_order_no
GROUP BY po.process_name, r.component_name
ORDER BY po.process_name, COUNT(*) DESC;
```

# 氚云库存「开账干跑」对账清单（2026-09-28）

> **定位**：这是决策 `#38`（氚云产品库存 = ERP 期初余额来源）的**干跑产出**。它回答一个具体问题：
> **切换日 T 真的开账时，会发生什么？** 进账多少行、涉及多少产品、金额多少、
> 哪些行会被拦下、**哪些行按口径该进账但当前代码会跳过**。
>
> **⚠️ 本清单是只读快照，未执行任何开账动作。** 开账真执行**仍未开工**（LQ：切换日未定）。
>
> 台账快照时点：**2026-09-28 14:03**（即当日重导后的台账状态）。台账一变，本清单作废重跑。

## 2. 口径（决策 `#38` 五条）

| # | 口径 | 实现判据 |
|---|---|---|
| ① | 只开数量 > 0 的行 | `quantity > 0`（零 / 负 / 缺失一律不进账） |
| ② | 切换后氚云停录转只读 | 与本干跑无关（部署动作） |
| ③ | 费用/非标行不进账 | **`ProductFeeFilter`**（唯一实现：类目 ∈ {费用,制版费,税点,运费} **或** 编号 ∈ 11 项兜底名单） |
| ④ | 名称/编号为 NULL 挂异常清单 | `product_name IS NULL OR product_code IS NULL`（三值逻辑会让它们绕过一切 `=`/`<>` 比较） |
| ⑤ | 缺价行金额置 null、**行仍进账** | 见 §5 —— ⚠️ **当前 `confirm` 与此相反** |
| ⑥ | 代发仓不进账 | `warehouse = '代发仓'`（`DROP_SHIP` 不持有实物库存） |

> **口径修正记录**：`#38` 原登记的费用判据写作 `product_name = product_code`（自拟），
> 与唯一实现 `ProductFeeFilter` **不等价**（有量命中 20 vs 21 行）。
> 实测两者在**进账集上结果一致**（进账集内费用行 = 0，因费用行的名称与编号同名），
> **未造成数据错误**，但已回指唯一实现（违反「同一口径禁两套表」铁律）。

## 4. 真异常 = 0

`blocked` 为空，含义是：**没有身份歧义、没有仓库主数据缺失**。

- 手工核对时发现的名字重复组（`切刀 / 把` 对应 2 个编号）**不构成歧义** ——
  因为库里 `sales_products` 为空，首次开账走「按编号建档」，不会触发多候选分支。
- **这正是"首次开账"与"二次合并"的差别**：首次全部建档，不存在歧义。

# 生产跟单产品制程与任务快照：实施边界

## 已核对的当前口径

- `production_tracking_stage_defs` 仍是现行跟单列表、详情、完成分母和旧表导入的车间类别节点来源。维护此表会立即改变既有任务的节点集合；它不能直接充当已发布的产品版本。
- 氚云 `production_orders` 保存车间与产品名称文本，没有与产品中心 `ProductModel` 稳定相连的外键。新模板暂关联 `manufacturing_task_config_items` 中的 `PRODUCT_NAME`，只在车间名、产品名唯一匹配时自动采用。
- `production_tracking_milestones` 是跟单员的执行记录；人工结案状态位于 `production_tracking_state`。两者不等同。
- P50/P75 当前从已填完成日期计算“节点完成间隔”，不是工序实际加工时长。无日期的 DONE 不应作为节点间隔样本。
- 旧版线性 P50/P75 候选现在仅取没有快照或 `LEGACY` 快照的工单；`PUBLISHED` / `MANUAL` 流程先排除，待版本相容性与并行依赖样本算法完成后再纳入。

## 本次已落地的基础能力

`V430` 保存产品模板版本、节点集合、依赖边、任务快照及快照变更审计的表结构。产品版本发布后不再编辑原行；新版本另建草稿。任务首次从氚云导入时捕获最新匹配的已发布版本及节点，重复导入不覆盖快照。匹配不唯一时保存 `LEGACY` 快照，不猜测产品归属。详情可只读查看任务制程来源。

模板支持多前置节点并进行有向无环校验。节点标签、关键词和依赖会复制到模板或快照，不依赖后续字典名称变化。

节点保存已允许人工明确确认 `DONE + NO_DATE`，同时要求说明依据；有真实日期的节点仍按真实日期记录。结案弹窗在有任务快照时逐项列出尚未核实的节点，后端拒绝遗漏确认。结案前后里程碑分别留在历史快照中。

列表的节点分子、分母与详情节点集合现已优先读取本单快照；没有快照的历史任务继续使用原车间节点。跟单保存按快照节点校验，明确不适用的节点不能直接报为进行中或已完成。旧制程兼容快照的按需节点在源单未指明、也没有原有里程碑时记为不适用；产品模板中的条件节点仍保留待确认状态。

产品快照的依赖图不是单链时，详情暂不生成原线性算法的自动节点参考日期或预测交期，仍显示人工填写的参考日期，并返回说明。现有 P50/P75 候选计算排除这类产品流程，待建立依赖边界清楚的样本算法后再启用。

产品参考工期的旧制程候选样本已排除停止生产任务。现有样本明细抽屉按节点展示有效、缺完成日期、无排产锚点、日期倒序、超过 60 天、未来日期及零天间隔数量，便于发布前核查。该统计仍只针对旧制程口径；产品快照的并行流程尚未进入 P50/P75 候选。

新增同一已发布产品制程版本的只读样本报告 `/api/manufacturing/tracking-processes/versions/{templateId}/duration-samples`，制程管理页可直接查看。报告只取绑定该版本且未作本单制程调整、未停止或取消的任务。单链流程分别计算节点完成间隔和整单周期的 P50/P75、有效样本数与排除原因；中间节点日期未知会排除受影响的节点间隔，整单起止可信时仍可计入整单周期。适用性待确认的节点不计入有效样本。并行或依赖未定义时只提示暂不计算线性间隔。该结果仅供审核，不会自动覆盖已发布参考值。

节点分析图与节点下钻现共用任务节点集合：有快照的任务使用快照中适用或待确认的节点，即使尚未建立里程碑行也计入“涉及单数”并在下钻显示“未开始”；无快照的历史任务继续按现有里程碑与车间字典统计。排产等待图与下钻均使用当前可见且未停产、未取消的任务范围。

交付日期派生查询在有任务快照时保留快照中的入库节点，即使车间字典后来停用该节点也可读取原完成日期；快照已明确标为不适用的入库节点不会被拿来推定入库交付。无快照任务继续遵循字典启用状态。此 SQL 变更已编译，仍需在 MySQL 实库核对已停用字典节点的历史单。

2026-10-30 实库验收：`backend/.env` 提供账号密码；当前执行沙箱禁止本机 TCP，沙箱外 127.0.0.1:3306 可连接 MySQL 9.7.1。V429–V431 均成功执行。6,148 张生产任务中，6,144 张可按车间＋产品名唯一匹配现有 50 条产品配置，4 张产品名为空。当前产品制程模板与任务快照均为 0，尚未配置真实产品流程。空快照、DONE 且不适用、DONE 无日期且缺依据均为 0；701 张任务有跟单状态，139 张已人工结案，其中 18 张存在非 DONE 的已登记节点。只读 `ProductionTrackingAnalyticsMysqlTest`、`ProductionTrackingDurationMysqlTest` 和新增 `ProductionTrackingProcessMysqlTest` 均通过。事务回滚探针验证旧快照可生成 7 节点／5 适用节点；另一事务回滚测试覆盖草稿创建、发布、匹配任务捕获及重复导入不覆盖。测试结束后模板、快照与探针审计记录仍为 0。

实库测试修复两处运行期缺陷：`manufacturing_task_config_items.active` 已在 V400 删除，产品模板创建／发布／匹配查询不再引用；MySQL JDBC 对 `TINYINT(1)` 返回 `Boolean` 时，节点条件标记统一按布尔或数值读取。旧任务快照捕获拒绝空节点集合，防止误生成 0/0 完成任务。后续仍需由业务人员确认首批产品的实际节点与依赖并发布模板，再对真实在制任务进行受控试点；18 张历史结案异常单需逐单核实，不自动补写完成日期。

旧任务治理已有只读预览 `/api/manufacturing/tracking-processes/legacy-preview` 和按明确任务 ID 批量建立兼容快照的 `/legacy-batch`。批量请求限 100 单，须填写核实原因；每单记录快照创建审计，一单失败则整批回滚。兼容快照冻结旧车间节点和已有执行节点，不追溯套用当前发布的产品模板。批量执行仍须先由管理员核对预览清单；目前没有自动批量修正历史节点事实。

单单预览 `/orders/{orderId}/legacy-preview` 会列出拟冻结节点、预计适用性、已有执行状态和“已结案但适用节点未完成”的核实标记。预览与捕获共用旧节点集合构造，并保留里程碑中已人工确认的适用性；不会因源单关键词重新判断而覆盖人工结论。

## 切换正式跟单口径前必须完成

1. 核对 Excel 导出与回写、周复盘及节点分析的快照兼容性；对照同一批工单的列表、详情、筛选与导出结果。现有导出字段仍按原车间节点列组织，不应视为已完成动态节点支持。
2. 核对所有统计入口的快照适用性；“待确认”不得默认为已完成或不适用。已有里程碑的节点不得无审计删除。
3. 对旧任务兼容快照逐批核实并执行；现有旧任务未建快照时仍使用旧结案口径。补充迁移前后差异报告和回退演练后再扩大范围。
4. 修订 P50/P75 的样本筛选、产品与版本兼容规则、并行节点间隔解释；增加样本数和排除原因回测。
5. 对氚云重复导入、模板发布后旧单不变、节点并行、结案、导出回写及三个分析入口做回归测试，再逐步启用快照驱动的生产判定。

历史任务不自动套用新发布模板。不得把目前的制程配置页面当成已经完成正式切换的依据。

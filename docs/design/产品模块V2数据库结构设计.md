# 产品模块 V2 数据库结构设计（product_archive V2）

> 范围：仅 `product_models` / `product_variants` / `product_machine_tiers` / `product_variant_packaging_links` 四张核心表，以及辅助表 `product_assets` / `product_documents` 的处置。
>
> 不在 V2 范围：包材（`packaging_*`）、模具（`packaging_mold_*`）、官网运营（`website_*`）、公司档案（`company_*`）等表保持不变。
>
> 起始版本：当前 Flyway 已执行到 V105，新脚本从 **V106** 起编号。

---

## 一、设计目标与边界

### 1.1 业务定位收缩

V2 把产品模块从"准 PLM/ERP"收缩为**企业产品知识库 + 官网展示 + 智能选型**：

| 维度 | V1（现状） | V2（目标） |
|---|---|---|
| 业务定位 | 产品档案 + 机器配置 + 价格 + 国际站营销 + 导入溯源 | 产品档案 + 官网展示 + 智能选型 |
| 字段规模 | ProductModel ~70 字段，ProductVariant ~80 字段，合计 150+ | ProductModel ~27 字段，ProductVariant ~16 字段，MachineTier ~20 字段，合计 ~63 |
| 数据来源 | Excel 导入为主 | 后台档案维护为主 |
| 删除原则 | — | 凡"机器参数 / 价格 / 导入溯源 / 历史业务字段"一律删除或下沉 |

### 1.2 边界四问

1. **设备 + 包材匹配**：保留（V2 核心价值）。
2. **官网产品展示**：保留（V2 核心价值）。`website_*`、`introduction_*`、`search_keywords_*` 全部保留。
3. **智能选型标签**：保留（V2 核心价值）。`application_tags` / `container_tags` / `packaging_process_tags` / `capacity_level` 全部保留。
4. **机器配置 / 价格 / 导入溯源**：全部删除。未来需要时另起 `machine_configurations` / `pricing_system` / `import_staging` 表，不污染产品档案。

### 1.3 核心层级模型

```
ProductModel（产品系列：自动封口机 / 气调包装机 / 贴体包装机 …）
    │
    └─ ProductMachineTier（机型档位：330 / 390 / 500）
            │
            └─ ProductVariant（封口规格：方模具 370×270 / 圆模具 φ180 …）
                    │
                    └─ ProductVariantPackagingLink（兼容包材关系）
                                │
                                └─ PackagingVariant（包材规格，本表不修改）
```

## 二、最终四表结构（V2 目标 Schema）

### 2.1 `product_models`（产品系列）

```sql
product_models  -- V2 目标，约 25 列
(
    id                  BIGINT PK,
    name                VARCHAR(200) NOT NULL,   -- 中文产品名（不改名：现状即 CN，改名 name_cn 成本高）
    name_en             VARCHAR(200),
    model_code          VARCHAR(80),
    category            VARCHAR(100),             -- 新合并字段（吸收 product_line_name / equipment_category / item_type）
    description_cn      LONGTEXT,                 -- 新合并字段（吸收 equipment_advantages + core_config_description；applicable_scope 不复制，单独保留为 application_scope）
    description_en      LONGTEXT,                 -- 新合并字段（吸收 *_en）
    application_scope   LONGTEXT,                 -- 保留：应用范围（与 description 互补，应用场景清单）
    default_image       VARCHAR(500),             -- 保留为字符串；未来 V3 迁到 cover_asset_id (FK product_assets)
    introduction_cn     LONGTEXT,                 -- 保留：AI 详情/直通车短描述
    introduction_en     LONGTEXT,
    search_keywords_cn  TEXT,                     -- 保留：SEO
    search_keywords_en  TEXT,
    website_enabled     BOOLEAN NOT NULL DEFAULT FALSE,
    website_featured    BOOLEAN NOT NULL DEFAULT FALSE,
    website_slug        VARCHAR(128) UNIQUE,
    website_summary     VARCHAR(500),
    application_tags    JSON,                     -- 保留：智能选型
    container_tags      JSON,
    packaging_process_tags JSON,
    capacity_level      VARCHAR(50),
    status              VARCHAR(50),              -- 新字段（吸收 sale_status + workshop + item_type 业务状态，统一为 ACTIVE/DISCONTINUED/PREVIEW）
    sort_order          INT NOT NULL DEFAULT 0,
    remark              VARCHAR(1000),
    deleted_at          DATETIME(6),
    created_at          DATETIME(6) NOT NULL,
    updated_at          DATETIME(6) NOT NULL
)
```

**说明**：
- `name` 不改名为 `name_cn`：现状即 CN，无歧义；改名需触动 Service/DTO/前端 30+ 处，收益低。
- `category` 由三个旧字段合并：旧值取 `product_line_name` 优先，无则 `equipment_category`，再无则 `item_type`。
- `description_cn/en` 由两个 LONGTEXT 字段合并：旧值拼接 `equipment_advantages + core_config_description`（EN 对应），分块以 `\n\n---\n\n` 分隔。`applicable_scope` 改名 `application_scope` 单独保留，数据不复制到 description，避免冗余。
- `default_image` V2 暂保留字符串；V3 引入 `cover_asset_id` FK 时再迁移。
- `application_scope` 与 `description_cn` 区别：前者是"应用场景清单"（用于智能选型），后者是"产品介绍正文"（用于官网/AI 详情）。

### 2.2 `product_machine_tiers`（机型档位）

V1 已基本到位，V2 仅做语义对齐和索引补齐，**字段不删不减**。

```sql
product_machine_tiers  -- V2 目标，约 17 列
(
    id                  BIGINT PK,
    model_id            BIGINT NOT NULL,
    tier_code           VARCHAR(40) NOT NULL,     -- 330 / 390 / 500
    tier_label          VARCHAR(80),              -- 330机型
    -- 口径范围（V2 核心：本层决定 Variant 的封口规格上限）
    round_diameter_min  DECIMAL(10,2),
    round_diameter_max  DECIMAL(10,2),
    rect_length_min     DECIMAL(10,2),
    rect_length_max     DECIMAL(10,2),
    rect_width_min      DECIMAL(10,2),
    rect_width_max      DECIMAL(10,2),
    -- 机型物理参数（V2 接收 ProductModel 下沉的尺寸/重量字段）
    machine_size        VARCHAR(100),
    net_weight_kg       VARCHAR(100),
    carton_size         VARCHAR(100),
    wood_box_size       VARCHAR(100),
    gross_weight_kg     VARCHAR(100),
    sort_order          INT NOT NULL DEFAULT 0,
    remark              VARCHAR(500),
    deleted_at          DATETIME(6),
    created_at          DATETIME(6) NOT NULL,
    updated_at          DATETIME(6) NOT NULL,
    UNIQUE KEY uk_pmt_model_tier (model_id, tier_code),
    INDEX idx_pmt_model_id (model_id),
    INDEX idx_pmt_deleted_at (deleted_at)
)
```

**说明**：
- 口径范围字段 `round_diameter_*` / `rect_*` 在 V1 已是 DECIMAL；V95 之前为 INT，V95 已硬化为 DECIMAL。
- `machine_size` / `net_weight_kg` / `carton_size` / `wood_box_size` / `gross_weight_kg` 在 V103 已新增，**接收 ProductModel 下沉的 `device_size` / `device_weight_kg` / `package_size` / `package_weight_kg`**。
- V2 不删除本表任何字段，因为本表本身就是"机器物理能力边界"的载体，符合用户业务定位。

### 2.3 `product_variants`（封口规格）

V1 最臃肿的表（70+ 字段），V2 收缩到 ~15 字段。

```sql
product_variants  -- V2 目标，约 15 列
(
    id                  BIGINT PK,
    model_id            BIGINT NOT NULL,
    machine_tier_id     BIGINT NULL,              -- 保留：关联机型档位（V94 新增）
    variant_name        VARCHAR(220),             -- 保留：规格名（如"方模具 370×270"）
    spec_key            VARCHAR(240),             -- 保留：规范化规格键（去重用）
    -- 模具几何（V2 核心：本表的真正业务数据）
    mold_size_type      VARCHAR(20),              -- ROUND / RECTANGLE
    mold_length_mm      VARCHAR(40),
    mold_width_mm       VARCHAR(40),
    mold_diameter_mm    VARCHAR(40),
    mold_size_label     VARCHAR(100),             -- 显示用："370×270" / "φ180"
    -- 状态
    baseline            BOOLEAN NOT NULL DEFAULT FALSE,  -- 保留：是否为主规格（一个 tier 下选一条作为展示基线）
    sort_order          INT NOT NULL DEFAULT 0,   -- 新增（V1 缺）
    remark              VARCHAR(1000),
    deleted_at          DATETIME(6),
    created_at          DATETIME(6) NOT NULL,
    updated_at          DATETIME(6) NOT NULL,
    INDEX idx_variant_model_id (model_id),
    INDEX idx_variant_machine_tier (machine_tier_id),
    INDEX idx_variant_deleted_at (deleted_at)
)
```

**说明**：
- `baseline` 保留：用于"一个机型档位下展示哪一条规格作为代表"。
- 删除所有 `origin` / `based_on_variant_id`（继承链表机制）：V1 用于多版本管理，V2 不再需要。
- 删除所有 `voltage` / `frequency` / `power` / `packaging_speed` / `output_count` / `device_size` / `device_weight_kg` / `package_size` / `package_weight_kg` 等机器参数（已下沉到 `product_machine_tiers`）。
- 删除所有 `plc_control_system` / `touch_screen_config` / `temperature_module` / `air_switch` / `ac_relay` / `intermediate_relay` / `solid_state_relay` / `switching_power_supply` / `button_switch` / `solenoid_valve_config` / `vacuum_pump` / `cylinder` / `servo_motor` / `vacuum_chamber` / `air_shaft` / `breaker` / `roll_film_motor` / `phase_sequence_protector` / `proximity_switch` / `air_pressure_gauge` / `oil_water_separator` / `sensor_photoelectric` / `film_photoelectric` / `motor_config` / `display_config` 等机器配置（30+ 字段）。
- 删除 `dealer_price` / `retail_price`（价格，未来 `pricing_system`）。
- 删除 `specification_table` / `gas_fresh_keeping_description` / `residual_oxygen` / `air_pressure_requirement` / `customs_code` / `gas_replacement_rate` / `ultimate_vacuum` / `vacuum_supported` / `temp_range` / `cutting_method` / `cover_material` / `custom_mold_supported` / `heating_method` 等技术参数（机器参数下沉或废弃）。
- 删除 `max_film_width` / `roll_film_diameter` / `max_sealing_size`（机器能力 → `machine_tier`）。
- 删除 `optional_device` / `equipment_size_spec` / `worktable_height_mm` / `film_or_box_size` / `box_or_mold_shape` / `box_height` / `supplement` / `applicable_product` / `power_formula` / `mouth_spec`（V1 散落的辅助描述字段，下沉或废弃）。
- 删除 `source_row_number` / `origin` / `based_on_variant_id` / `sku_image`（导入溯源与继承链表）。

### 2.4 `product_variant_packaging_links`（设备规格-包材关系）

V1 已基本到位，V2 仅做语义微调，**字段不大改**。

```sql
product_variant_packaging_links  -- V2 目标，约 7 列
(
    id                       BIGINT PK,
    product_variant_id       BIGINT NOT NULL,
    packaging_variant_id     BIGINT NOT NULL,
    relation_type            VARCHAR(20) NOT NULL DEFAULT 'COMPATIBLE',  -- 改名：原 compatibility_status
        -- 枚举：COMPATIBLE / RECOMMENDED / COMMON（覆盖原 MATCHED/PARTIAL/NOT_COMPATIBLE）
    match_source             VARCHAR(20) NOT NULL DEFAULT 'MANUAL',     -- 保留：MANUAL / AUTO
    remark                   VARCHAR(500),                              -- 改名合并：原 override_reason
    created_at               DATETIME(6) NOT NULL,
    updated_at               DATETIME(6) NOT NULL,
    UNIQUE KEY uk_pvpl_variant_packaging (product_variant_id, packaging_variant_id)
)
```

**说明**：
- `compatibility_status` → `relation_type`：枚举语义从"匹配度"改为"关系类型"（COMPATIBLE / RECOMMENDED / COMMON），更贴近"设备规格-包材"的语义。
- `override_reason` → `remark`：合并为单一备注字段。
- 不删除 `match_source` / `updated_at`：保留可追溯性。
- 不删除 `product_variant_id` 改为 `variant_id`：列名保持不变，避免 FK 重命名连锁修改。

## 四、Flyway 迁移方案

### 4.1 迁移原则

1. **不可逆操作（DROP COLUMN）必须先做数据备份**：每个被删除的列先写入 `*_backup` 临时表（V_xxx 步骤内创建 + 备份 + 验证 + 删除）。
2. **改名（CHANGE COLUMN）与合并（数据迁移后 DROP）分脚本**：避免单脚本过长难回滚。
3. **强约束变更（NULL → NOT NULL）单独脚本**：先数据回填，再加约束。
4. **每个脚本必须可独立执行**：不依赖前一脚本的内存状态。
5. **回滚策略**：每个 DROP 脚本顶部注释列出对应的回滚 ALTER 语句；备份表保留 30 天后由 DBA 手动清理。

### 4.2 脚本拆分

V2 共拆 7 个脚本，从 **V106** 起编号：

|---|---|---|---|

### 4.4 数据回填脚本（V110 关键步骤）

`product_variants.machine_tier_id` 由 nullable 改为 NOT NULL 前，必须回填所有 `machine_tier_id IS NULL` 的规格。

**回填策略选择**：设计稿原稿曾考虑按 `mold_size` 精确匹配机型档位（BETWEEN round_diameter_min/max 或 rect_length_min/max），但实际 `mold_diameter_mm` / `mold_length_mm` 是 `VARCHAR(40)` 字段，与 `machine_tiers.round_diameter_min/max`（DECIMAL）类型不兼容，隐式转换有 SQL 风险。**V110 实际脚本采用兜底启发式策略**：

```sql
-- V110 关键步骤示例（实际脚本内嵌，详见 V110__product_v2_variants_add_sort_order.sql）
-- 1. 统计未关联机型的规格
SELECT COUNT(*) FROM product_variants WHERE machine_tier_id IS NULL AND deleted_at IS NULL;

-- 2.0 备份待处理行 ID + original_deleted_at（精确回滚用）
CREATE TABLE product_variants_v2_soft_deleted AS
SELECT
    id AS variant_id,
    model_id,
    deleted_at AS original_deleted_at,  -- 原值: NULL=活跃, 非空=已软删除
    CURRENT_TIMESTAMP(6) AS snapshot_at
FROM product_variants
WHERE machine_tier_id IS NULL
  AND (
      model_id IS NULL
      OR model_id NOT IN (SELECT DISTINCT product_model_id FROM product_machine_tiers WHERE product_model_id IS NOT NULL)
  );

-- 2.1 启发式回填：每个 NULL 行的 machine_tier_id 设为该 product_model 下最小 tier_id
UPDATE product_variants pv
INNER JOIN (
    SELECT product_model_id, MIN(id) AS min_tier_id
    FROM product_machine_tiers
    GROUP BY product_model_id
) t ON t.product_model_id = pv.model_id
SET pv.machine_tier_id = t.min_tier_id
WHERE pv.machine_tier_id IS NULL;

-- 2.2 找不到 tier 的 NULL 行，同时设 machine_tier_id = 全局 MIN(id) + 软删除活跃行
--     必须设 machine_tier_id，否则步骤 3 NOT NULL 会失败
UPDATE product_variants pv
CROSS JOIN (SELECT MIN(id) AS global_min_tier_id FROM product_machine_tiers) g
SET pv.machine_tier_id = g.global_min_tier_id,
    pv.deleted_at = COALESCE(pv.deleted_at, CURRENT_TIMESTAMP(6))
WHERE pv.machine_tier_id IS NULL AND g.global_min_tier_id IS NOT NULL;

-- 2.3 极端边界 - product_machine_tiers 为空时硬删除（正常情况影响 0 行）
DELETE FROM product_variants WHERE machine_tier_id IS NULL;

-- 3. 加 NOT NULL 约束（步骤 2.1/2.2/2.3 已确保无 NULL 行）
ALTER TABLE product_variants MODIFY COLUMN machine_tier_id BIGINT NOT NULL;

-- 4. 新增 sort_order INT NOT NULL DEFAULT 0 AFTER spec_key
ALTER TABLE product_variants ADD COLUMN sort_order INT NOT NULL DEFAULT 0 AFTER spec_key;
```

**DBA 执行前必须核对**：
- `SELECT COUNT(*) FROM product_variants WHERE machine_tier_id IS NULL;` — NULL 行数
- 如 NULL 行数较多或业务有更精确的 tier 匹配规则，DBA 应在 V110 执行前手动回填
- V110 默认回填策略"最小 tier_id"是兜底启发式，可能不准确

**业务上需要的精确回填**（如：根据规格尺寸匹配最贴近的 tier）：可由业务代码或独立脚本在 V110 前完成，V110 不依赖精确匹配。

## 七、决策记录

| 决策项 | 选择 | 理由 |
|---|---|---|
| 是否改名 `name` → `name_cn` | **不改** | 现状即 CN，无歧义；改名需触动 30+ 处 Service/DTO/前端，收益低 |

| 是否保留 `based_on_variant_id` 继承链 | **删除** | 多版本管理机制过于复杂，V2 收缩后不需要 |
| 是否下沉 `device_size` 到 `machine_tier` | **下沉** | V103 已完成；机器尺寸跟随机型走，不跟规格走 |
| `product_documents` 是否删表 | **不删** | 历史数据保留；停止业务依赖即可；删表不可逆 |
| 是否在 V2 引入 `cover_asset_id` | **不引入** | 字符串 `default_image` 暂时够用；V3 再做 FK 迁移 |
| `application_scope` 是否分 CN/EN | **不分** | 单一 LONGTEXT 足够；若需多语言，未来再加 `application_scope_en` |

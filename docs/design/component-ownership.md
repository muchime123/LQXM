# 页面组件归属规范

## 目标

把项目从“文件很多但边界不清”整理成“页面结构集中、公共能力复用、后续迭代快”的状态。

## 判断标准

### 应该回归父组件

满足以下任意条件，优先内联回页面父组件：

- 只被一个 `views/*.vue` 页面使用。
- 组件名称强绑定某个页面或某个页面局部区域。
- props / emits 很多，本质是在替父页面搬运状态。
- 改页面布局时必须同时改父组件和子组件，来回跳文件。
- 抽出来后没有降低复杂度，只增加文件碎片。

典型例子：

- 公司信息页里的概览、财务账户、知识库、发展历程、团队组织。
- 产品管理页里的某些局部面板、局部 tab、页面专属弹窗。
- 包装管理页里的页面专属详情抽屉和编辑弹窗。

### 应该继续独立

满足以下任意条件，继续保留独立文件：

- 跨页面或跨模块复用。
- 具有稳定、通用的交互模型。
- 组件内部复杂度高，但对外 API 简洁。
- 可以被多个业务对象接入。

典型例子：

- 上传入口、拖拽上传、复制粘贴上传。
- 文件/图片预览。
- 通用弹窗、确认弹窗。
- 选择器、表格工具栏、分页、空状态、加载状态、错误状态。
- Markdown 编辑器。

## 逻辑放置规则

页面级组件回归父组件后，仍然保持逻辑分层：

- `api/`: 后端请求封装，页面不直接散写接口地址。
- `composables/`: 上传、拖拽排序、分页、筛选、弹窗状态、脏数据检测等可复用流程。
- `utils/`: 文件、日期、格式化、下载、校验等纯工具。
- `constants/`: tab、状态、字段、筛选项、字典选项。
- `styles/`: 全局设计令牌、布局、通用组件样式和模块样式。

## 当前执行顺序

1. 先清理已经失效的导出、不可达文件和遗留引用。
2. 公司信息模块保持父组件集中设计，继续补齐公共上传、预览、拖拽排序能力。
3. 产品管理模块按面板分批回归 `ProductCatalogView.vue`，每批都跑构建验证。
4. 包装管理模块单独处理大文件回归，避免一次性搬动 4000 行以上组件。
5. 新增页面默认先在父组件内完成，确认跨模块复用价值后再抽组件。

## 一、切换时间线（4 阶段）

业务代码切换按字段生命周期分 4 阶段，每阶段对应不同脚本：

| 阶段 | 触发脚本 | 业务代码状态 | 字段并存状态 |
|---|---|---|---|
| **A：新增 V2 字段** | V107 前（V106 备份阶段） | 实体/DTO/前端 type 新增 V2 字段（category/descriptionCn/descriptionEn/status/sortOrder）；旧字段保留 | V1 + V2 字段并存，业务双读过渡 |
| **B：业务切到 V2 字段** | V107 执行后 | Service / Controller / 前端组件切到读 V2 字段；旧字段停止写入但仍可读 | V1 字段只读，V2 字段为主 |
| **C：删 V1 字段** | V108/V109/V112 执行后 | 实体/DTO/前端 type 删除 V1 字段；Service 白名单收敛；导出/导入模板收敛 | V1 字段彻底移除 |
| **D：强约束 + 改名** | V110/V111 执行后 | 实体加 NOT NULL、pvpl 改名字段 | 字段名变更 + 约束变更 |

**关键原则**：阶段 A 必须在 V107 前完成（否则 V107 后业务读不到 status 等新字段）；阶段 B 必须在 V108/V109 前完成（否则删字段后业务报错）；阶段 C 在删字段脚本后立即完成；阶段 D 对应强约束脚本。

## 五、关键风险点

1. **阶段 A 必须先于 V107**：否则 V107 后业务读不到 status 等新字段，回退困难。
2. **阶段 B 必须先于 V108/V109**：grep 验证无引用后才可执行删字段脚本。
3. **ProductVariantPackagingService.applySpecification 删除字段调用最多**：影响 variant 创建/更新流程，需重点测试。
4. **CatalogImportService 是否整体下线**：若 V2 不再 Excel 导入，可整体下线该服务，TEMPLATE_HEADERS 仅保留导出使用。需业务确认。
5. **ProductMachineTierCapabilityValidator**：V2 强制 machineTier 必填后，validator 仍校验封口口径落在机型可行范围内，逻辑不变。
6. **官网公开接口字段映射**：必须同步切换，否则官网产品列表/详情页字段错乱。
7. **前端编辑表单分区调整**：从"基础信息/分类/机器参数/价格/机器配置/国际站履约/智能选型/官网发布"8 区 → "基础信息/应用范围/模具几何/智能选型标签/官网发布"5 区，UX 重构较大。
8. **`/api/website/product-categories` 端点完全依赖待删字段**（`equipmentCategory` + `productLineName`），阶段 C 必须同步重构该端点。
9. **`computeCompletenessScore` 评分依赖 `equipmentCategory`**，影响所有 4 个产品端点的过滤逻辑（WebsiteController L86/L138/L167/L177），阶段 D 必须重写评分。
10. **`searchWebsiteProducts` SQL 的 keyword 搜索匹配 `product_line_name` + `equipment_category`**（Repository L121-L122），删字段后搜索功能失效，阶段 D 必须改写 SQL。
11. **`PublicProductDetail.from` 与 `PublicVariantView.from` 构造器参数顺序耦合**，阶段 C 删字段时易引入参数错位 bug，建议改为 builder 模式或先加显式参数名校验。
12. **4 个端点共用 `PublicProductView`**，任何字段调整都需同时验证 `/products` / `/products/featured` / `/products/{slug}` / `/home`。
13. **`applicationScope` vs `applicableScope` 命名冲突**：JPA 默认下划线映射会撞到同一列，阶段 A 加新字段时必须显式指定列名。
14. **`useArchiveHealth.ts` ARCHIVE_HEALTH_RULE_VERSION 必须 bump**（当前 `'2026-07-11-main-product-v1'`），V2 字段变更后必须 bump 版本号让旧健康缓存失效；顺带修复 L271 `salesStatus` 拼写 BUG。
15. **`useCatalogEditorOps.ts:114` 必填校验依赖 `MODEL_FIELD_GROUPS`**（constants 层），schema 改动需在 constants 层同步。
16. **`ProductEditorModal.vue` 是大文件敏感组件（约 939 行）**：按 AGENTS.md 中"大文件优先用 Python 脚本批量替换"策略，建议批量字段删除/改名用 Python 脚本 + sed 行号定位完成。
17. **`ModelData` / `VariantData` 宽松类型隐藏字段引用**：`api/catalog/models.ts` 的 `batchUpdateModels` 与 `api/catalog/variants.ts` 的 `createCatalogVariant / updateCatalogVariant / batchUpdateVariants` 均使用 `[key: string]: unknown` 宽松类型，**编译期不会报错**，V2 切换时极易漏改调用方，建议阶段 A 替换为具名白名单类型。
18. **官网前端无 TypeScript**：`api/website.js` 中的 `@typedef` 仅为 JSDoc 类型提示，不参与编译校验，V2 字段删除不会引发编译错误，但需手动更新 typedef 以保持 IDE 提示准确。
19. **`Products.vue` query 参数名变更需与 SEO/外链协调**：若 `?equipmentCategory=xxx` 改为 `?category=xxx`，旧外链将丢失筛选状态。建议后端在 V2 阶段 B 同时接受两种参数名，前端读取时做 `q.category || q.equipmentCategory` 兼容。

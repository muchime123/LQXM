## 二、工作流顺序详解

### 第 0 层：基础设施

这部分文件和产品档案工作流无直接耦合，但被所有功能模块共享。

#### `api/http.js`
- **设计**：基于 `axios.create` 的单例封装，`baseURL: '/api'`，超时 120s
- **导出**：`http`（axios 实例）、`createAbortController()`
- **职责**：所有 API 调用的底层通道，通过 Vite proxy 转发到 Spring Boot 后端

#### `constants/fields.js`
- **设计**：集中管理所有字段定义，3 组核心常量
  - `MODEL_FIELDS` — 主产品 23 个字段（name → defaultManualFile）
  - `MODEL_FIELD_GROUPS` — 主产品编辑表单分组（3 组）
  - `VARIANT_FIELDS` — 配置 10 个字段
  - `VARIANT_FIELD_GROUPS` — 配置编辑表单分组（3 组：识别信息 / 核心参数 / 补充信息）
  - `ASSET_CATEGORIES` — 11 个素材分类（main_image、sku_image、manual...）
  - `IMAGE_ASSET_CATEGORIES` — 可预览的图片分类
  - 辅助函数：`getAssetLabel()`、`getAssetIcon()`、`getAssetAccept()`、`formatValue()`
- **职责**：单一事实来源（Single Source of Truth），所有字段标签/类型/必填标记由此定义

#### `constants/status.js`、`constants/documentTypes.js`
- 通用于售状态、文档类型等枚举常量

#### `utils/` 目录（与产品档案直接相关的）
| 文件 | 职责 |
|------|------|
| `errorHandler.js` | 统一错误消息提取（`errorMessage()`），解析 axios error / GraphQL error / 字符串 |
| `fileUtils.js` | 素材 URL 构建（`fileUrl(category, fileName, modelId)`），根据 modelId 是否为空自动区分产品/非产品路由 |
| `markdown.js` | Markdown → HTML 渲染（说明书预览用） |
| `downloadBlob.js` | 浏览器端 Blob 下载 |
| `exportTemplate.js` | 下载 Excel 导入模板 |
| `formatUtils.js`、`dateUtils.js`、`textUtils.js` | 通用格式化 |
| `chartManager.js` | Chart.js 懒加载管理（仪表盘用） |
| `productDisplay.js` | 产品名称 + 机型标签的显示拼接 |

### 第 1 层：主页面编排器

#### `views/ProductCatalogView.vue`
- **文件大小**：约 2800 行（含 730 行 CSS）
- **设计模式**：**编排器（Orchestrator）** — 自己不做业务逻辑，只负责：
  1. 初始化 14 个 composable 并连接它们
  2. 声明式渲染组件树（template 部分，约 500 行）
  3. 编写与视图耦合的适配函数（如 `saveModel()` 需要控制抽屉开关、Tab 切换）
- **核心状态**：
  - `activeTab` — 当前详情 Tab（overview / variants / assets / machine-config / manual / documents / marketing）
  - `catalogDisplayMode` — 视图模式：`browse`（卡片+抽屉）/ `workbench`（列表+右栏）
  - `detailDrawerVisible` — 抽屉开关（browse 模式下控制）
  - `batchMode` — 批量管理模式
- **7 个 Tab 定义**：
  ```
  overview → variants → assets → machine-config → manual → documents → marketing
  ```
- **弹窗优先级**（Esc 键关闭顺序，数字越大优先级越高）：
  | 优先级 | 弹窗 |
  |--------|------|
  | 100 | confirmDialog |
  | 90 | modelEditor |
  | 85 | variantEditor |
  | 70 | batchEdit |
  | 65 | moveVariant |
  | 60 | moveAsset |
  | 55 | batchMoveAsset |
  | 40 | healthPanel |
  | 35 | dashboard |
  | 30 | duplicateAssistant |
  | 25 | todoPanel |
  | 10 | detailDrawer |

- **键盘快捷键**：
  - `Esc`：按优先级关闭最上层弹窗
  - `Ctrl+S`：保存当前编辑器（配置优先于主产品）

### 第 2 层：Composable 状态管理层

这层是架构的核心——所有业务逻辑被抽入 composable，视图只做编排。

#### 2.1 列表与详情

##### `useCatalogModels.js`
- **状态**：`models`（产品列表）、`detail`（当前产品详情对象，含 model + variants + assets）、`selectedId`、`selectedVariant`、`loading`、`selectingModel`
- **方法**：
  - `loadModels(getQueryParams, getSortParams, page, pageNum, opts)` — 加载列表，支持去重（requestId 机制）
  - `selectModel(id, opts)` — 加载详情，自动预加载健康度缓存
  - `cacheModelHealth(models)` / `getCachedHealth(id)` — 健康度评分缓存
- **设计要点**：翻页不清空详情（`isPageChange` 选项），选中产品不在新页才清空

##### `useCatalogFilters.js`
- **状态**：`query`（keyword + 4 个筛选维度）、`filterOptions`（后端返回的可选值）、`listSort`（列表排序）、`listFilter`（列表内筛选）、`hasActiveFilters`
- **方法**：`updateFilters()` / `clearFilters()` / `getQueryParams()` / `getSortParams()` / `saveListSort()`
- **设计要点**：排序偏好存入 localStorage（`catalog-list-sort`），搜索支持 300ms 防抖

##### `useCatalogPagination.js`
- **状态**：`page`（number / size / totalPages / totalElements）
- **职责**：分页状态独立管理，与筛选/排序组合形成 API 查询参数

#### 2.2 批量操作

##### `useBatchSelection.js`
- **状态**：`batchMode`（是否批量模式）、`selectedIds`（Set）
- **方法**：`toggleBatchMode()` / `toggleSelection(id)` / `toggleSelectAll(items)` / `isAllSelected(items)`
- **设计要点**：**每个实体类型各自实例化**——ProductCatalogView 创建了 3 个独立实例（主产品/配置/素材），互不干扰

##### `useBatchActions.js`
- **状态**：`globalLoading` / `globalLoadingText`
- **职责**：全局 Loading 遮罩状态（导入/批量操作时显示）

#### 2.3 CRUD 操作

##### `useCatalogCrud.js`
- **职责**：纯 API 封装层，不含 notification
- **方法**：`saveModel()` / `deleteModel()` / `saveVariant()` / `deleteVariantById()` / `duplicateVariantById()` / `addAsset()` / `deleteAssetById(assetId, deleteFile)` / `setAssetDefault()` / `moveVariant()` / `moveAsset()`
- **设计要点**：`saveModel()` 根据 mode（create/edit）自动选择 POST 或 PUT；`deleteAssetById()` 支持 deleteFile 参数决定是否同时删除本地文件

##### `useCatalogAssets.js`
- **职责**：素材操作的协调器，接收 `onAssetChanged` 回调
- **方法**：`save(payload, mode)` — 创建/更新素材，成功后触发回调刷新详情

##### `useCatalogVariants.js`
- **职责**：配置操作的协调器，接收 `onVariantChanged` 回调
- **方法**：`save(modelId, payload, mode)` — 创建/更新配置，成功后触发回调
- **设计要点**：回调中自动切换到 variants tab 并选中刚编辑的配置

##### `useCatalogEditors.js`
- **职责**：编辑器表单状态管理
- **状态**：主产品编辑器（`modelEditorVisible` / `modelEditorMode` / `modelEditorForm` / `modelEditorDirty` / `modelEditorValidationErrors`）+ 配置编辑器（对应同上）
- **方法**：`openNewModelEditor()` / `openModelEditor()` / `closeModelEditor()` / `handleModelFieldChange()` / 配置编辑器对应方法
- **设计要点**：`blankModel` 和 `blankVariant` 提供创建模式的初始表单数据

#### 2.4 移动操作

##### `useCatalogMoveOperations.js`
- **职责**：统一管理三种移动操作（单配置、单素材、批量素材）
- **状态**：各自独立的 visible / 目标 modelId / variantId / modelOptions / targetVariants
- **方法**：`openMoveVariantModal()` / `doMoveVariant()` / `openMoveAssetModal()` / `doMoveAsset()` / `openBatchMoveAssetModal()` / `doBatchMoveAsset()`
- **设计要点**：移动后自动刷新详情、清除选择、退出批量模式

#### 2.5 说明书

##### `useCatalogManual.js`
- **状态**：`manualBuilderVisible` / `manualBuilderVariantId` / `manualExpired` / `manualVersions` / `manualStatusValue`（computed：已发布/草稿/待生成）
- **方法**：`openManualBuilder()` / `handleManualSaved()` / `publishManual()` / `loadManualVersions()` / `restoreManualVersion()`
- **设计要点**：`openManualBuilder()` 自动推断当前选中的配置 ID；保存后更新 detail.model 和列表中的模型数据

#### 2.6 健康度与仪表盘

##### `useCatalogHealthPanel.js`
- **职责**：健康度面板、仪表盘、待办面板的统一状态管理
- **状态**：`todoPanelVisible` / `healthPanelVisible` / `healthList` / `healthLoading` / `dashboardVisible` / `dashboardData` / `todoGroups` / `totalTodoProducts` / `healthSummaryText` / `archiveHealth`
- **设计要点**：接收视图层的所有操作方法（selectModel、setActiveTab 等），实现数据与 UI 的解耦

#### 2.7 弹窗管理

##### `useCatalogModals.js`
- **职责**：全局弹窗注册与 Esc 键栈式关闭
- **核心机制**：`modalRegistry`（Map<name, {getVisible, close, priority}>）+ `modalOrder`（按优先级排序的名称数组）
- **方法**：`registerModal()` / `closeTopmost()` / `anyModalOpen()` / `anyModalOpenExcept()`
- **设计要点**：`closeTopmost()` 按优先级从高到低遍历，关闭第一个可见弹窗；产品详情与主操作弹窗互斥（`detailSuspended` computed）

##### `useDuplicateAssistant.js`
- **职责**：重复数据检查
- **状态**：候选列表、类型筛选、忽略列表、范围选择

#### 2.8 全局交互

##### `useDropZone.js`
- **职责**：全局拖拽 + 粘贴上传
- **机制**：监听 document 级 dragenter/dragover/dragleave/drop + paste 事件
- **设计要点**：
  - 粘贴智能过滤：焦点在 input/textarea/select/contentEditable 时不拦截
  - 拖拽计数器（dragCounter）防止子元素触发误判
  - `disabled` 参数支持 ref/computed/function 三种形式

##### `useConfirmDialog.js`
- **职责**：全局确认弹窗，支持 3 按钮（取消/次要/确认）
- **导出**：`askConfirm()`（异步返回用户选择）、`confirmDialog`（reactive 状态）、`resolveConfirm()`

##### `useToast.js`
- **职责**：全局 toast 通知
- **导出**：`notify(message, type)` — type 支持 success/warning/error

##### `useDirty.js`
- **职责**：表单脏检测

##### `useArchiveHealth.js`
- **职责**：健康度缓存管理

### 第 4 层：视图组件层（`components/product/` 目录，按工作流顺序）

#### 4.1 顶部工具栏 — `CatalogToolbar.vue`
- **位置**：页面最顶部，固定显示
- **UI 组成**：
  - 搜索输入框（300ms 防抖 + Enter 搜索）
  - 4 个下拉筛选：产品线 / 车间 / 设备大类 / 在售状态
  - 查询 / 清除筛选按钮
  - 视图切换：列表（workbench）/ 卡片（browse）
  - 状态指示按钮：档案待办（橙色点）、健康度
- **Props**：`query`、`filterOptions`、`totalTodoProducts`、`healthSummaryText`、`displayMode`、`compactViewport`
- **Events**：`search`、`filter-change`、`clear-filters`、`open-todo`、`open-health`、`open-dashboard`、`change-display-mode`

#### 4.2 产品列表 — `ProductListPanel.vue`
- **设计**：卡片/列表双视图，由 `layout` prop 控制
- **卡片视图**（browse 模式）：
  - 缩略图 + 产品名称/型号 + 完整度进度条 + 分类标签 + 待办标记
  - 支持 HTML5 拖拽排序（`draggable="true"`）
- **列表视图**（workbench 模式）：
  - 紧凑行布局，左侧缩略图 + 中间信息 + 右侧完整度
  - mouse hover 高亮，选中激活绿色左边框
- **排序**：下拉选择（手动/名称A-Z/名称Z-A/配置最多/素材最多）
- **列表内筛选 chips**：全部 / 有配置 / 有说明书 / 素材齐全
- **Props**：`models`、`selectedId`、`batchMode`、`selectedModelIds`、`loading`、`layout`、`page`、`listSort`、`listFilter` 等
- **Events**：`select`（打开产品详情）、`toggle-select`（批量选择）、`reorder-models`（拖拽排序）、`prev-page` / `next-page` / `go-to-page` / `page-size-change`、`sort-change`、`filter-change` 等

#### 4.3 产品详情容器 — `ProductDetailDrawer.vue`
- **设计**：双模式容器
  - `pinned=false`（browse 模式）：Teleport to body，带遮罩的侧滑抽屉，宽度 `min(1180px, 92vw)`
  - `pinned=true`（workbench 模式）：不 Teleport，作为右栏固定面板
- **结构**：header（返回按钮 + 标题 + 机型标签 + 副标题） + body（slot 内容） + footer（可选 slot）
- **Props**：`visible`、`title`、`modelTag`、`subtitle`、`pinned`、`closable`、`bodyClass`、`drawerWidth`
- **Slots**：`#header-actions`（标题右侧操作按钮）、默认（内容）、`#footer`
- **设计要点**：browse 模式支持 Esc 关闭 + 点击遮罩关闭 + 关闭动画（drawer-slide transition）

#### 4.4 概览 Tab — `CatalogOverviewTab.vue`
- **UI 分区**：
  - **主图区**：大尺寸封面图 + 可展开多图 gallery（含拖拽排序 + 拖拽上传）
  - **完整度面板**：各维度打分 + 缺失项警告 + 一键跳转操作
  - **待办清单**：按优先级排列的操作项
- **Props**：`model`、`assets`、`health`、`completeness`、`defaultImage`、`showGuide`
- **Events**：`preview-asset`、`run-action`、`guide-action`、`reorder-images`、`drop-images`、`open-import`
- **设计要点**：主图 gallery 支持 HTML5 原生拖拽排序 + 拖入图片直接上传（通过 `useDropZone`）

#### 4.5 配置 Tab — `CatalogVariantsTable.vue`
- **UI 结构**：
  - 操作栏：配置数量 + 缺图统计 + 批量管理按钮组 + 新建按钮
  - 表格：配置名称 / 模具盒型 / 包装速度 / 价格 / 操作（缩略图列 + 复选框列）
- **筛选 chips**：全部 / 缺配置图 / 有配置图
- **交互**：
  - 单击选中 → 右侧详情面板高亮
  - 双击 → 打开编辑器
  - 批量模式 → 复选框 + 移动/删除按钮
- **Props**：`variants`、`selectedVariant`、`selectedVariantIds`、`batchMode`、`modelId`
- **Events**：`new-variant`、`select-variant`、`edit-variant`、`copy-variant`、`delete-variant`、`move-variant`、`batch-move-variants`、`batch-delete-variants`、`toggle-batch-mode` 等

#### 4.6 素材 Tab — `CatalogAssetGallery.vue`
- **UI 结构**：
  - 吸顶工具栏：
    - 第一行：11 个分类导航标签 + 批量管理/导出按钮 + 上传控件（分类选择 + 文件输入）
    - 第二行：快速筛选 chips + 排序切换
  - 素材卡片网格（按分类分组）
- **每个素材卡片**：
  - 缩略图 + 文件名 + 标签（可编辑 tag input）
  - 操作菜单：预览 / 设默认 / 改分类 / 移动 / 删除
  - 批量模式：复选框覆盖层
- **拖拽上传**：覆盖整个素材区域，释放文件自动上传到当前分类
- **素材标签系统**：18 个预设标签（一出一/模具类型/膜类型/包装方式/操作方式/特殊功能）
- **Props**：`assets`、`variants`、`categories`、`activeFilter`、`uploadCategory`、`uploadVariantId`、`uploading`、`batchMode` 等
- **Events**：`upload`、`preview`、`set-default`、`move-asset`、`save-tags`、`batch-save-tags`、`delete-asset`、`reorder-assets`、`export-zip` 等

#### 4.7 机器配置 Tab — `MachineConfigEditor.vue`
- **设计**：富文本表格编辑器（contenteditable 不可用时的 input 替代方案）
- **显示模式**：中文 / 英文 / 双栏（3 种切换）
- **表格列**：序号 / 零部件名称 / 品牌产地 / 规格材质 / 操作
- **工具栏**：
  - 添加行 / 批量导入（CSV） / 套用模板 / 管理模板
- **模板系统**：预设模板可一键套用，支持保存/加载已有配置为模板
- **列数**：实际列数根据显示模式动态变化
- **Props**：`modelId`
- **设计要点**：每个组件行有本地 `_new` / `_dirty` 标记，按需批量保存

## 三、数据流图

```
用户操作
  ↓
ProductCatalogView（事件处理 → 调用 composable 方法）
  ↓
Composable（业务逻辑 → 调用 API 函数）
  ↓
api/catalog.js（HTTP 请求 → axios）
  ↓
Vite Proxy → Spring Boot 后端 (8081)
  ↓
数据库 MySQL (product_archive)
```

**关键数据流**：
1. **选择产品**：`ProductListPanel@select` → `selectModel(id)` → `useCatalogModels.selectModel()` → `fetchCatalogModel(id)` → 更新 `detail` ref → 所有 Tab 响应式更新
2. **保存配置**：`VariantEditorModal@save` → `saveVariant()` → `useCatalogVariants.save()` → `createCatalogVariant/updateCatalogVariant` → 回调刷新详情 → 自动切到 variants tab
3. **上传素材**：`CatalogAssetGallery@upload` → `processUploadFiles()` → `uploadFile()` → `addCatalogAsset()` → `refreshCurrentModel('assets')`
4. **生成说明书**：`CatalogManualBuilder` → `generateCatalogManualPreview()` → 后端渲染 Markdown → 用户确认 → `generateCatalogManual()` → 保存 + 更新模型

## 四、设计原则总结

1. **关注点分离**：View（编排）→ Composable（状态+逻辑）→ API（网络）→ Backend，每层职责清晰
2. **Composable 优先**：22 个 composable 覆盖所有业务逻辑，视图文件保持瘦身
3. **批量选择独立性**：主产品/配置/素材各自独立的选择状态，互不干扰
4. **弹窗栈管理**：`useCatalogModals` 统一注册 + 优先级排序 + Esc 键栈式关闭
5. **乐观更新**：素材拖拽排序先更新本地数组 → 后台保存 → 失败才回滚
6. **去重请求**：列表加载使用 `requestId` 递增机制，避免快速切换导致数据错乱
7. **防抖搜索**：300ms 防抖，减少不必要的 API 调用
8. **状态持久化**：视图模式（browse/workbench）和排序偏好存入 localStorage
9. **全局交互**：useDropZone 监听 document 级事件，所有 Tab 均可拖拽/粘贴上传
10. **双视图模式**：browse（卡片浏览 + 抽屉详情）和 workbench（列表 + 右栏面板），通过 `catalogDisplayMode` 一键切换

# 公司财务账户与资金日记账账户整合审查（2026-10-26）

## 已核实的现状

- 公司信息页的“财务账户”由 `CompanyInfoView` → `CompanyAccountsTab` → `/api/company/accounts` → `company_accounts` 维护。字段包括账号、户名、开户行、币种、SWIFT/IBAN、收款码、主账户和排序；`company.manage` 可增改并直接删除。这套数据主要用于收款资料展示，收款码还由 `CompanyFileAssetAdapter` 引用。
- 资金日记账的账户由 `h3_cash_accounts` 提供，`cashflow_entities` 管理归属，`cashflow_account_opening` 管理年度期初。`CashflowEntityController` 已提供认领和启停，使用 `cashflow.read/manage`。日记账查询和部分导入仍按 `h3_cashflow_entries.account_name = h3_cash_accounts.account_name` 关联。
- 两表没有已核实的稳定关联键；同名、同币种或相似银行名称均不足以证明是同一账户。`company_accounts` 也没有年度期初或流水身份。当前不能将前者整表视为后者的主档，更不能自动按名称合并。

## 目标边界

资金账户、归属、启停、年度期初和流水集中在资金日记账模块；公司信息保留公司主体资料。银行账号、SWIFT、收款码等收款资料需要逐户核对后才关联至稳定的资金账户 ID。历史来源账户名继续原样保留，账户停用不改变历史计算。

“资金账户”和“收款资料”允许暂时只有一侧：有日记账账户但未补账号，或有对外收款资料但尚未匹配到日记账账户。界面须标明未关联，不能把未核实关系显示为已统一。

## 安全实施顺序

1. **只读对拍**：导出两表字段、记录数和候选匹配清单；对账号仅展示掩码，人工确认同一账户、不同账户、待确认。核对币种、户名、账户类型和历史流水，记录决定人及依据。
2. **稳定关联**：在完成各环境迁移版本审查后，为收款资料增加可空的资金账户 ID 关联及唯一性/审计约束。只迁入人工确认的关系；未匹配资料原样保留。不得以名称自动更新 `h3_cash_accounts`，也不更改历史 `account_name`。
3. **统一操作入口**：在资金日记账的账户工作区展示资金账户和已关联的收款资料，继续区分 `cashflow.manage` 与敏感账号维护权限。未授权用户只看到掩码；收款码文件访问也须同步核对权限。公司信息页改为关联账户摘要/跳转，避免双处编辑。
4. **最后收敛旧写入口**：验证导入、报表、文件附件及权限后，再决定是否退役 `/api/company/accounts` 写入口。数据表和未匹配记录不能因页面迁移直接删除。

## 本轮决定

本轮只完成代码级审查与设计，不执行账户合并、数据库迁移或正式数据写入。B-3.1 正式库清理仍等待负责人授权和环境审批；B-3.2 正式部署也保持原边界。公司账户的直接删除能力不应直接迁入资金账户管理。

# 原销售明细关联发货

本阶段补齐自产主产品和外采本地到货，从原销售订单明细办理发货的入口。供应商直发继续从采购单生成代发出库，不经过本地仓库。

## 操作

1. 完成销售订单的评审、审批确认。
2. 自产完成生产任务的检验入库；外采在关联采购单办理实际到货入库。
3. 打开原销售订单详情，在对应明细点击“办理发货”。
4. 选择“仓库＋来源”：自产为原任务主产品的成品批次；外采为原采购明细在该仓库的实际到货产品。产品身份依据入库事实，无须手工修改销售明细的产品档案或供货方式。
5. 填本次数量，生成出库草稿。页面自动跳转到该出库单，核对后过账。
6. 返回原订单，查看已发数量、草稿待发数量和未生成数量，以及“关联出库记录”。可点击出库单下钻，查看原明细和来源批次／采购单。

没有入库、原来源已失效、单位不一致、库存不足或来源已全部占用时，没有可发选项。供应商直发在此也不会出现本地可发库存。

## 数量与状态

- 已发：原明细关联的 POSTED 出库数量。
- 草稿待发：关联的 DRAFT 出库数量。
- 未生成：需求数量减去 DRAFT＋POSTED 数量。
- CANCELLED／REVERSED 不占用该明细待发需求，可重新办理。
- 自产可发量取需求剩余量、批次可用量减草稿占用、当前总库存量的最小值。
- 外采可发量取需求剩余量、该仓库已到货量减草稿／已发占用、当前总库存量的最小值。

每张自产出库草稿选择一个成品批次，多批次分别生成草稿；支持分批数量。来源占用只针对关联发货草稿，不是全面的跨订单库存预留。

## 过账、取消与冲销

自产过账同一事务扣总库存和来源批次可用量，并写批次流水；任一步失败整体回滚。出库冲销同一事务回补二者。取消未过账草稿不增加库存，只释放其来源占用。

已关联待发／已发出库的完工入库不能直接冲正，先取消或冲销关联出库。采购到货冲正后若剩余到货量不足以覆盖关联待发／已发量，也会被拦截。执行异常未解决时仍禁止生成关联出库及过账。

原订单生成的出库草稿不能在普通出库编辑中脱离订单改产品、仓库或数量；调整时取消原草稿，再从订单重新生成。

## 本轮边界

- 自产发货来源按原任务的主产品产出筛选。随附模具、配件的装箱清单及多产出成套交付尚未统一。
- 本轮只给新建的关联出库保存来源。历史出库不回填来源、不重新扣库存；独立库存出库尚未全面统一到批次选择。
- 客户收款归单、应收核销仍未建设。

## 验证

独立 MySQL 测试验证了：自产原明细与批次关联、草稿数量占用、过账扣减与冲销回补、不能借用另一任务批次、外采无销售产品 ID 时引用真实到货身份，以及到货冲正的数量保护。既有销售审批、采购到货／代发及异常规则回归通过。

浏览器测试用模拟接口验证了自产、外采两个“办理发货”流程，不向真实客户订单写测试数据。前端类型检查、定向 lint 和构建通过。V352 已在本地执行，后端已重启。

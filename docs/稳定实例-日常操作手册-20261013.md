## 1. 两个实例是什么

| | **开发实例**（你的） | **稳定实例**（同事的） |
|---|---|---|
| 用途 | 你写代码、自测 | 同事日常使用 |
| 前端 | Vite 热更新，端口 **5173** | 冻结产物，由后端同源托管 |
| 后端 | 端口 **8081** | 端口 **8082** |
| 代码 | 你的工作区，保存即生效 | `release/stable/` 里的**副本**，你改源码它不动 |
| 迁移 / 定时任务 | **由它负责** | 关闭（防止两个进程打架） |
| 数据库 | 同一个 MySQL | 同一个 MySQL（**共用**） |
| 访问地址 | `http://192.168.3.65:5173` | `http://192.168.3.65:8082` |

**一句话原理**：同事访问的是**复制出去的冻结副本**，不是你的工作区。
所以你在 5173 上保存、重启、甚至把后端重编一百遍，同事那边**毫无感觉** —— 直到你主动「发布」。

## 2. 开发：我的改动怎么生效

### 2.1 起开发环境

```powershell
.\scripts\start-local.ps1      # 起 5173（前端）+ 8081（后端）；已在跑就自动跳过
```

自测地址：`http://localhost:5173`

### 2.2 三种改动，三种后果

| 你改了什么 | 要做什么 | 影响谁 |
|---|---|---|
| 前端 Vue / 样式 | **什么都不用做**（Vite 热更新） | 只有你 |
| 后端 Java / `application.yml` | 打包 → 重启后端（见 §2.3） | 只有你 |
| 想让同事也看到 | 发布（见 §3） | 同事 |

### 2.3 只重启开发后端（最常用）

**① 双击 `restart-dev-backend.bat`（仓库根目录）** —— 一步到位，等价于下面的三步。

**② 或者在普通 PowerShell 里：**

```powershell
cd backend
mvn -o -DskipTests -Djacoco.skip=true package    # ① 出新 jar（约 78MB）
cd ..
.\scripts\start-local.ps1 -RestartBackend        # ② 只重启 8081
```

**③ 等价的一行式脚本**（`.bat` 内部调的就是它，参数更灵活）：

```powershell
.\scripts\rebuild-backend.ps1                    # 打包 + 重启 8081
.\scripts\rebuild-backend.ps1 -SkipPackage       # 只重启、不打包（已打过包时用，快）
.\scripts\rebuild-backend.ps1 -Clean             # 先 clean 再打（遇到诡异编译问题用）
.\scripts\rebuild-backend.ps1 -Online            # 去掉 -o，允许联网解析依赖
```

> ⚠️ **顺序不能反**：只重启不打包 = 还是旧代码。
> **怎么确认生效**：看这两行 ——
> - 成功：`后端启动副本：…\_lqxm_run\dev-local\app.jar（78.x MB，源 jar 时间 …）` → `后端已就绪：http://127.0.0.1:8081`
> - 失败：`源 jar 只有 x.xMB，像是没内嵌依赖的瘦包…` ⇒ **打包没成功**，回第 ① 步重打（见 §5.3）

`-RestartBackend` 做三件事：① 只终止「命令行指向本项目 jar」的 8081 进程（若是别的服务占着 8081，只告警、不误杀）；② 等端口释放；③ 拉起后**轮询最多 30 秒确认真在监听**，起不来就打印日志尾部并明确报错。

**前端 5173 与稳定实例 8082 完全不受影响。**

## 3. 发布：让同事看到新版

### 3.1 一条命令

```powershell
.\scripts\publish-stable.ps1 -Restart
```

它做三件事：构建前端 → 打包后端 → 把产物冻结进 `release/stable/` 并重启稳定实例。

> 只改了前端：加 `-SkipBackend` 可跳过 Maven，快很多。
> ⚠️ 这个动作比较重（要跑 `vite build` + `mvn package`）—— 在**你自己的终端**跑，别放在受限环境里。

### 3.2 「改了 X，要不要发布？」

| 你改了什么 | 要发布吗 | 命令 |
|---|---|---|
| 前端页面 / Vue / 样式 | 要 | `.\scripts\publish-stable.ps1 -Restart -SkipBackend` |
| 后端 Java 代码 | 要 | `.\scripts\publish-stable.ps1 -Restart` |
| `application.yml` 等配置 | 要（配置打在 jar 里） | `.\scripts\publish-stable.ps1 -Restart` |
| 只是数据库里的数据（导氚云、改业务记录） | **不用** | 数据库共用，改了立刻对所有人生效 |
| 新增了迁移脚本 `Vxxx__*.sql` | 要，**且先起一次开发实例** | 见 §4.2 |

### 3.3 同事那边会怎样

- 不会自动更新；你发布后他们**刷新浏览器**才是新版。
- 已登录的 token **继续有效**，不会被踢。

## 4. 三条边界（最容易踩）

### 4.1 数据库是共用的 —— 破坏性操作立刻影响同事

前后端隔离了，但 **MySQL 只有一个**。**不要在同事使用时段**做：

- 删表 / 清空数据 / 大批量重导
- 删除迁移脚本、改字段类型等 schema 破坏性变更

要做就挑**没人用的时段**（比如晚上），**先备份**。

### 4.2 迁移和定时任务只由开发实例负责

稳定实例启动时带了 `--spring.flyway.enabled=false` 和全部 `cron=-`，这是刻意的：两个进程共库时都跑迁移/归档会互相打架。

**副作用你要知道**：新写的迁移脚本（`Vxxx__*.sql`）**只有在开发实例启动过之后才会应用到库**。
⇒ 新增了迁移 → 先 `.\scripts\start-local.ps1` 起一下开发实例让它跑迁移 → 再发布稳定版。否则稳定版面对的还是旧表结构。

### 4.3 你的 5173 随便折腾

改样式、改组件、HMR 报错、前端白屏 —— 都只影响 `localhost:5173` 这一份，同事的 8082 是独立进程，碰不到。

## 5. 出问题：按症状查

### 5.1 同事说「打不开」

按顺序查：

1. 稳定实例活着吗？→ `.\scripts\check-health.ps1 -Stable -StablePort 8082`
2. 端口在听吗？→ `Get-NetTCPConnection -LocalPort 8082 -State Listen`
3. 你本机能开吗？→ 浏览器 `http://127.0.0.1:8082/`
   - 你能开、同事开不了 ⇒ **防火墙 / 网络** → §5.6
   - 你也开不了 ⇒ 进程挂了 → 看 `release/stable/logs/stable.out.log`
4. 同事和你在**同一个网段**吗？（都要是 `192.168.3.x`）

### 5.2 开发页顶部红条「加载员工身份中失败」

**含义**：前端打不通后端 —— **不是前端坏了**，开发环境里几乎都是 **8081 没在跑**。

```powershell
# 1) 先看后端活不活
.\scripts\check-health.ps1 -FrontendPort 5173 -BackendPort 8081

# 2) 没在听 → 起来
.\scripts\start-local.ps1

# 3) 若脚本又说 "already listening" 但页面仍然红条
#    ⇒ 端口被一个半死的进程占着，杀掉再起：
Get-NetTCPConnection -LocalPort 8081 -State Listen | Select-Object -First 1 -ExpandProperty OwningProcess
taskkill /PID <上面查出来的数字> /F
.\scripts\start-local.ps1
```

**记住这条**：**「端口在监听」≠「服务可用」**。启动脚本只判端口、不探健康 —— 看到 `already listening` 也要用探活或页面本身确认。

### 5.3 发布时后端打包失败：`Unable to rename '…jar' to '…jar.original'`

**含义**：有进程锁着 `backend\target` 里的 jar —— 通常是 **8081 开发后端**（Windows 上运行中的 JVM 持有文件句柄，Maven 改名被拒）。

**正常情况下不会再发生**：开发后端已改为从副本 `_lqxm_run\dev-local\app.jar` 启动，不锁 target；发布脚本也会在打包前自动停掉占用者。

万一还遇到（例如你曾手动 `java -jar target\…jar` 起过后端）：

```powershell
# 1) 看谁占着 8081
Get-NetTCPConnection -LocalPort 8081 -State Listen | Select-Object -First 1 -ExpandProperty OwningProcess
# 2) 结束它
taskkill /PID <上面查到的数字> /F
# 3) 重新打包（成功后再发布）
cd backend ; mvn -o -DskipTests -Djacoco.skip=true package
```

> ⚠️ 打包失败会在 `target` 里留下一个 2~3MB 的**「瘦包」**（不含依赖、`java -jar` 起不来）。**别拿它启动** —— 必须重新打包成功（约 78MB）。
> ⚠️ 发布是先冻结前端、再打包后端 ⇒ 后端失败时**同事可能已看到新前端、后端还是旧的**（半发布状态）。遇到就尽快把后端补齐并重启稳定实例。

### 5.4 命令「跑了却什么都没发生」

大概率是**在 IDE 集成终端（Trae / VS Code）里跑的**。这类终端会注入小写 `http_proxy`/`Path`，与 Windows 原生大写变量撞车，触发 PowerShell 5.1 的 `Start-Process` 缺陷：

```
已添加项。字典中的关键字:"HTTP_PROXY"所添加的关键字:"http_proxy"
```

**两个办法**：① 换**普通 PowerShell 窗口**跑（推荐）；② 或加 `-Foreground` 前台跑，日志直接打在窗口里。
脚本已内置自诊断提示，撞上会告诉你怎么办。

### 5.5 换端口

```powershell
.\scripts\start-stable.ps1 -Port 8083
.\scripts\stop-stable.ps1 -Port 8083
```

（脚本发现端口已在监听会**自动跳过**，防止起出重复实例。）

### 5.6 防火墙

现状：`java.exe` 有一条 `入站 / Allow / Profile=Private` 的放行规则，而你的以太网正是 **Private** ⇒ 同事可达（已实测 200）。

**只有一种情况会失效**：以太网被系统改判成 Public（换到陌生网络、插了新路由器）。届时用**管理员** PowerShell 补一条：

```powershell
New-NetFirewallRule -DisplayName 'LQXM-Stable-8082' -Direction Inbound -Protocol TCP -LocalPort 8082 -Action Allow -Profile Any
```

## 6. 长期运维

1. **局域网 IP 可能变**：`192.168.3.65` 是 DHCP 分的，重启路由器 / 换网络可能变 ⇒ 同事的收藏夹会失效。
   要长期稳定，建议给这台机配**静态 IP**（或让 IT 配 DHCP 保留）。查当前 IP：
   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' }
   ```
   > ⚠️ 本机还有个 `vgate0 → 172.30.211.184`（虚拟网卡，Public profile），**别让同事用这个地址**。
2. ⭐ **稳定实例开机自启（一次性安装，装完永久生效）**
   它是普通进程，关机 / 重启就没了；而本机 Windows 更新**常在傍晚自动重启**（Active Hours = 9~19，一过 19:00 更新即可动手，实测总在 19:29）⇒ 不装自启的话，每次重启都要你手动拉一次。

   **在【管理员】PowerShell 里跑一次即可**（注册计划任务必须提权）：

   ```powershell
   # 方式一：管理员 PowerShell 里（推荐）
   cd C:\Users\20676\source\LQXM
   .\scripts\install-stable-autostart.ps1

   # 方式二：普通终端一行（会弹 UAC，点是）
   Start-Process powershell -Verb RunAs -ArgumentList '-NoExit','-ExecutionPolicy','Bypass','-File','C:\Users\20676\source\LQXM\scripts\install-stable-autostart.ps1'
   ```

   装出来的任务 `LQXM-Stable-8082`：
   - **触发**：① 开机后 1 分钟 ② 用户登录后 30 秒 ③ **每 15 分钟自愈**一次（崩了/没起来会自动补）
   - **身份**：优先 `S4U`（「不管用户是否登录都运行」，**不留明文口令**）；若系统不给 S4U 权利，自动回落成「仅在用户登录时运行」
   - **幂等**：`start-stable.ps1` 自带「端口已在监听就跳过」⇒ 开机与登录同时命中也不会起两份

   验证 / 卸载：
   ```powershell
   Get-ScheduledTask -TaskName 'LQXM-Stable-8082' | Get-ScheduledTaskInfo   # LastTaskResult 应为 0
   .\scripts\install-stable-autostart.ps1 -Remove                           # 卸载
   ```

   > ⚠️ 装完之后**机器重启就再也不用人管 8082 了**。若某天发现「重启后没起来」，先看 `Get-ScheduledTaskInfo` 的 `LastTaskResult`，再看 `release\stable\logs\stable.out.log`。

### 7.2 脚本参数

| 脚本 | 参数 | 作用 |
|---|---|---|
| `rebuild-backend.ps1` | `-SkipPackage` `-Clean` `-Online` `-WithFrontend` `-BackendPort` | 打包后端 + 重启开发后端二合一（`restart-dev-backend.bat` 调它）。校验 fat jar 与 BUILD SUCCESS，失败不重启 |
| `start-local.ps1` | `-FrontendPort` `-BackendPort` `-RestartBackend` `-BackendOnly` | 起开发实例。**后端从副本 `_lqxm_run\dev-local\app.jar` 启动**（不锁 `backend\target`）。带 `allow-employee-header=true` 供开发免登录 |
| `start-stable.ps1` | `-Port` `-Foreground` `-EnableSchedulers` | 起稳定实例（默认 8082）。默认关迁移、关定时任务、关身份冒充 |
| `stop-stable.ps1` | `-Port` | 只杀该端口的进程，**不碰** 5173/8081 |
| `publish-stable.ps1` | `-Restart` `-SkipBackend` `-Port` | 冻结并发布；**构建前预检并释放被锁的 jar**，打包后自动拉回开发后端 |
| `check-health.ps1` | `-Stable` `-StablePort` `-FrontendPort` `-BackendPort` | 探活。401 记为 PASS（服务活着、需登录） |
| `install-stable-autostart.ps1` | `-Port` `-LogonOnly` `-NoWatchdog` `-WatchdogMinutes` `-Remove` | **需管理员**。把 8082 注册成计划任务（开机 1 分 / 登录 30 秒 / 每 15 分钟自愈）。默认优先 S4U，失败自动回落登录模式 |

# 氚云生产任务单（产线+产品配置）与库存产品名关联分析

> 2026-09-23 · 数据源：`product_archive` 真库（氚云台账只读镜像）
> 表：`production_orders`(5691) / `production_order_components`(14227) / `h3_production_reports`(11956) / `h3_other_stock_movements(+items)`(6076/18814) / `h3_warehouse_stock`(16019) / `sales_outbound_items`(35159)

## 结论（先给）

1. **库存里的"产品名"不是从任务单生成或引用的。** 它是入库人员在氚云「其他入库单」上手打的一串复合描述；任务单与入库单之间**零引用**——1934 张入库单（direction=IN）的 `source_no`/`remark`/明细 `remark` 中出现工单号（SCGD…）的次数为 **0**。这就是你说的"完工到入库在数据层面断联"，实测成立。
2. **但两边词汇同源。** 库存名 ≈ `[订做/定做] + 机型号 + 盒子尺寸 + 一出N + 品类词 + 附加配置`，每个成分都能在任务单的产品配置字段里找到出处——只是**词序不定、写法不一、全靠人脑拼**。
3. **量化可重建率：约 8~9 成靠字面，但组合键冲突严重。** 5148 张有尺寸的成品任务单中，88.9% 的尺寸字面出现在某条库存名里、83.2% 尺寸+品类词同时出现；然而 **(尺寸, 一出N) 组合 1308 组里有 285 组被多张单共用，最多 62 张单共用一组** → 这个复合键**不能当 SKU 身份**，只能当检索线索。
4. **出库侧 99.7% 与库存精确同名**（35159 行出库明细中 35051 行产品名与库存快照完全一致）→ 这个人手拼的名字就是事实上的**商业/库存身份**，而生产任务单侧只存了结构化配置。**断的不是"有没有数据"，是"没有人把配置翻译成名字并锚定"。**

## 一、断联的直接证据

| 检查 | 结果 |
|---|---|
| 入库单引用工单号（source_no/remark 含 SCGD） | **0 / 1934 张** |
| 入库明细 remark 引用工单号 | **0 / 18814 行** |
| 其他入库单内容构成 | 4840 行明细中仅 336 行是成品（卷膜/片膜），仅 1 行 LQ 整机 → 「其他入库单」主要入的是**包材/配件**，成品完工入库走的是快照表 `h3_warehouse_stock` 的另一条人手维护路径 |
| 任务单自报入库字段 | `warehoused_quantity` 是手填数字：完工>0 的 4702 张里，4507 张填了"入库=完工"，159 张填 0，36 张部分入库——**是登记，不是单据联动** |
| 零部件表 | `production_order_components` 全是「设计/画图、模具加工、安排组装」这类工序占位名，**不含任何产品身份** |

补充：报工环节反而是**连通**的——`h3_production_reports.work_order_no` 精确关联任务单，且其 `work_order_text` 是氚云自动拼的显示串：`SCGD20250000075    按钮自动卷膜    188*81    一出二    8`（工单号+品类+尺寸+一出N+数量，4997/4997 全部如此）。**氚云自己在报工环节用的"工单身份"就是（品类+尺寸+一出N）这个三元组**——这是入库人员拼库存名时脑内参照的同一套东西。

## 二、库存产品名的语法解剖（真实样本）

| 库存产品名 | 拆解 |
|---|---|
| `订做200x138气动一出四卷膜` | 订做 + 尺寸 + 品类词拆开（气动…卷膜）夹住「一出四」 |
| `订做180x180气动一出四卷膜+气流式+特氟龙` | 同上；品类「气流式卷膜」被拆成 尾缀+附加项 两截 |
| `LQ310T-230x165一出一台式全自动+易撕口` | 机型号(来自品类名) + `-` + 尺寸 + 一出N + 型别 + 附加项 |
| `LQ750D-80x58一出十二多模具连续式+自动进盒（7字型）` | 同上 |
| `1812半自动卷膜 老款` | 尺寸(压掉x) + 品类 + 人肉备注 |
| `订做80x80一出四按钮全自动卷膜 塑料盒+特氟龙` | 尺寸 + 一出N + 品类 + 材质 + 附加项 |

产线不进名字，只决定大类：封口机车间（5057 单）→ 片膜/卷膜/模具/配件；气调机车间（634 单）→ LQ 系整机（型号就藏在品类名里，如 `LQ310T台式黑白机` → 库存名 `LQ310T-…`）。

## 三、任务单字段 → 库存名成分 映射表

| 任务单字段 | 在库存名中的落点 | 实测 |
|---|---|---|
| `product_name` 产品名称 | 三处：①机型号前缀（LQ260/LQ310T/LQ750D…）②品类词（手动/气动/按钮全自动 × 片膜/卷膜），**常被拆开**把「一出N」插中间 ③型别词（台式全自动/连续式/多模具） | LQ 系 15 个品类名中 12 个的型号能在库存名找到（大品类 100%） |
| `box_size` 盒子尺寸 | 尺寸段，紧跟型号/订做前缀 | **88.9%** 字面命中（4575/5148，规范化 mm/空格/*/× 后）；含小数点的尺寸命中率掉到 **47.5%**（38/80）——写法差异（取整/单位/Φ换算）集中在这里 |
| `mold_layout` 模具排列 | 紧跟尺寸的「一出N」 | 与尺寸同时命中 58.7%（1368/2332 强键单）；库存常省略或写法不同 |
| `box_shape` 形状 | 基本不写「圆形/方形」（66/16019）；圆形改用 Φ/φ 前缀表达 | 间接 |
| `box_height` 高度 | 截图设计的字段，台账无此列，库存名中不出现 | ≈0 |
| `box_material` 材质 | 偶尔以「塑料盒/铝盒/纸杯」落在尾部 | 低频 |
| `voltage` 电压 | 几乎不出现（20/16019） | ≈0 |
| `plug_type` 插头 | 几乎不出现（6/16019） | ≈0 |
| `brand` 品牌 | 几乎不出现（1/16019） | ≈0 |
| `optional_configuration` 可选配置 | 尾部「+特氟龙/+易撕口/+色带打码/+出口木箱/塑料盒」 | 中频，写法自由 |
| `production_line` 产线 | 不进名字，决定品类大类（封口机 vs LQ 系） | 间接 |

## 四、为什么"像有关联，其实断联"

- **同源不同源**：词同源（上面的映射），但**没有生成关系、没有引用关系、没有唯一键**。
- **组合键冲突**：`330x225+一出一` 被 61 张任务单共用、`370x270+一出一` 56 张、`53x53+一出六` 43 张。所以即使把配置拼成名字，同配置的不同订单仍会挤同一个库存名。
- **实配反例**（同尺寸同排列，库存名品类对不上）：
  - 任务单 `SCGD20260005684 手动片膜 80x80 一出四` ↔ 库存名 `订做80x80一出四按钮全自动卷膜 塑料盒+特氟龙`（品类不一致）
  - 任务单 `SCGD20260005770 气动卷膜 200x138 一出四 PET 易撕口` ↔ 库存名 `订做200x138气动一出四卷膜`（材质/可选配置没进名字）
- 这些不是脏数据，是**人肉命名体系的正常波动**——正因如此，靠"名字对名字"永远收敛不了。

## 五、对 ERP 的含义（SKU 重设计的落点）

建单侧已经存了完整配置（`manufacturing_orders.product_config_json`：productName/boxSize/boxHeight/moldArrangement/boxShape/boxMaterial/voltage/plug/brand/optionalConfigs），缺的是"配置 → 入库身份"的翻译层：

1. **建单提交时自动生成 SKU 名**（显示用）：`[型号|品类]-尺寸×一出N[+配置缩写]`，尺寸按**入库口径规范化**（去单位、`*`→`x`、保留小数不取整——历史数据里命中率损失主要来自这里）。
2. **SKU 身份键与显示名分离**：身份用 `MFG-{工单号}`（现有约定）或配置哈希；显示名允许重复。氚云的根病就是把"人手拼的显示名"当成了唯一身份。
3. **电压/插头/品牌/盒子高度不进名字**——历史数据证明库存与销售从不靠它们区分，放进 SKU 属性字段即可。
4. **完工入库行必须引用工单 SKU**（V331 已允许入库明细带 SKU）→ 完工→入库的断联在这一个约束上闭环，不需要去氚云补数。

---
*匹配口径备注：尺寸规范化 = lower + 去 `mm`/空格 + `*`/`×`→`x`；"命中"= 库存名含该串。所有数字可直接用本文 SQL 复算。*

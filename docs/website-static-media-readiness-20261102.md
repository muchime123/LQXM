# 官网静态媒体验收记录

范围：当前 `corporate-website/public/content` 静态快照与 `public/content/media`。仅核对文件映射和可读取性，未对图片内容、版权或视觉质量做人工验收。

## 产品

45 个公开产品的 slug 无重复，均有对应详情和卡片/主图媒体引用；产品详情图库中的媒体引用也在自动化测试中逐一检查。当前静态媒体目录有 139 个文件。

## 页面区块缺口

`page-sections.json` 引用的下列官网媒体 ID 未出现在静态媒体清单中：

| 页面区块 | 缺失媒体 ID |
| --- | --- |
| HOME / showcase | 141、142、143 |
| PRODUCTS / hero | 144 |
| SOLUTIONS / hero | 146 |
| ABOUT / hero | 145 |
| ABOUT / intro | 143、145 |
| ABOUT / manufacturing | 140、141、142、143 |

总计 7 个不同媒体 ID（140–146）。静态内容适配器会将无法映射的官网媒体 URL 转为空值，因此不会回退请求内部档案文件。首页制造图廊只展示存在有效图片的记录，避免把品牌占位图当成真实工厂照片。

补齐时应从官网独立媒体资产找到这些 ID 对应的实际文件，确认画面内容和使用权限，复制到官网静态媒体目录并更新媒体清单；随后重新执行 `npm test`、生产构建和页面视觉检查。不得按 ID 猜测图片或直接引用内部档案文件。

## 联系与视觉验收

邮件/电话在代码中有可点击路径，但实际接收人、邮件送达和电话接通尚未验证。浏览器自动化通道当前不可用，因此桌面与手机宽度的视觉验收仍待执行。上述两项不能由构建成功替代。

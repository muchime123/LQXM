# 生产任务单到销售出库的追溯设计

## 目标与口径

回答“这张生产任务单对应的已入库产品，有多少数量可以确认经销售出库售出”，并展示支持结论的采购入库明细与销售出库明细。生产完成、采购入库、销售出库是三个独立事实；不以其中一个替代另一个。当前其他出入库尚未全部导入，查不到销售出库只能说“当前数据未找到”，不能说“尚未销售”。

## 当前数据事实（2026-10-10，只读审计，全量导入数据，非九月跟单子集）

- `purchase_receipt_items` 共 64,853 行；其中 6,935 行同时有生产任务单编号和产品号，涉及 5,564 张工单。这 6,935 行的工单编号均能命中 `production_orders.work_order_no`。
- 按产品号相同、销售出库日期不早于采购入库日期，6,078 条入库明细至少找到一条候选销售出库明细。这是候选覆盖，不是已销售数量或已售工单数。
- 3,752 个带工单号的入库产品号中，867 个产品号涉及多张工单；最多一个产品号涉及 51 张工单。找到销售出库的产品号里，有 1,058 个产品号涉及多条销售出库明细。
- 3,747 条入库明细的同产品号还存在早于该入库日期的销售出库，证明同号库存跨批次流动常见，不能按“同号”反推出来源工单。
- 当前采购入库有 8 张草稿；销售出库有 107 张草稿、21 张处理中。候选和确认都必须区分单据状态。

只读统计脚本：`scripts/audit-production-outbound-link.cjs`。

## 事实链与证明边界

1. 生产任务单 `production_orders.work_order_no` → 采购入库明细 `purchase_receipt_items.production_order_no`：按源工单号可建立明确关联。入库明细还带 `product_code`、`unit`、`quantity`；主单带 `purchase_date`、`warehouse_id/name`、`data_status`。
2. 采购入库明细 → 销售出库明细 `sales_outbound_items`：现阶段只有产品号等产品属性，没有批次号、序列号或来源入库明细 ID。产品号可检索候选，不能证明是哪一批产品。
3. 销售出库主单 `sales_outbounds` 有出库日期、客户、仓库、归一化状态及销售/退货/换货业务性质。只有有效的销售出库才可计为“已售”；内部流转、草稿、退换货必须单独处理。
4. 采购入库日期与出库日期是单据日期，可能补录；日期倒置列为冲突，允许人员核实，不自动归属。工单要求数量与实际入库数量不同，已售分母以确认关联的有效入库数量为准，同时展示工单要求数量供对照。

## 判定层级

| 层级 | 页面用语 | 判定条件 | 能否计入已售数量 |
| --- | --- | --- | --- |
| 无入库证据 | 当前未见关联采购入库 | 没有有效且能关联工单的入库明细 | 否；不能推断未生产或未售 |
| 已入库，未找到候选 | 当前数据未找到销售出库 | 有有效入库明细，当前导入的有效销售出库中无可用候选 | 否；不能写“未售出” |
| 有候选，待核实 | 找到同产品号销售出库，来源待确认 | 产品号相同，单位一致且数量为正；日期/仓库/业务性质用于排序与排除 | 否 |
| 已确认部分销售 | 已确认销售 X／入库 Y | 有审核通过的明细数量分配，0 < X < Y | 是，仅 X |
| 已确认全部销售 | 已确认销售 X／入库 Y | 审核通过的分配 X = Y，且 Y 为该工单所有有效、已关联的入库数量 | 是，X；只说明已入库部分 |
| 数据冲突 | 来源或数量待核 | 工单号/产品号/单位缺失、跨仓未解释、日期倒置、分配超量、源单变更等 | 不新增确认数量 |

“已确认全部销售”也不等于整张生产任务单全部生产或全部入库；页面应同时展示工单要求数量、有效入库数量、确认销售数量与未分配数量。若未导入的库存流水可能影响该产品，始终附“仅覆盖当前导入的采购入库与销售出库”的范围说明。

## 候选匹配规则

候选查询先限 `sales_outbound_items.line_type='PRODUCT'`、正出库数量、有效的销售出库主单及经确认属于 `SALE` 的业务性质。精确匹配规范化产品号与单位；产品名、规格、客户、业务员只作提示与排序，不代替产品号。优先同仓库、出库日期不早于入库日期；跨仓和日期倒置归为“需核对”，不能悄悄排除，因为其他调拨/补录数据尚未齐全。空产品号、单位不一致、草稿或非销售性质不得自动分配。任何“唯一候选”也只代表候选唯一，不代表库存来源唯一。

候选可以按证据强度展示“同号同单位同仓且日期合理”“同号同单位但仓库/日期待核”等分组，但不要显示百分比置信度或自动写入已售结论。

## 数量归属与数据结构

建立独立的人工确认关系 `production_outbound_allocations`，每行保存：工单 ID、采购入库与销售出库明细 ID、两端源单号、产品号、单位、确认数量、两端数量和日期快照、确认人/时间、说明、当前状态。采购入库重导会整单删除重插，因此旧明细 ID 失效后，这条确认自动标为“源单已变更，需复核”，不计入确认已售数量；历史记录保留，可撤销后基于新源行重新确认。后续可补源明细 UUID 与变更哈希，以便自动定位重导后的同一源行，但仍需人员复核数量与日期变化。

事务内约束：单条入库明细的有效分配总量 ≤ 其有效入库数量；单条销售出库明细的有效分配总量 ≤ 其有效出库数量；产品号和单位必须一致；工单号必须命中入库明细；不可重复分配同一数量。退货、换货、其他入出库未建模前不自动抵减或补足。重导后若数量、状态、产品号、日期或业务性质改变，标记关联“需复核”，历史确认记录保留审计，不静默沿用。

将来补齐其他入出库、调拨与期初库存后，可以提供先进先出等“模拟来源”供核对，但模拟结果仍与人工/批次证据区分。

## 页面设计

生产跟单详情在采购入库卡片之后增加“销售去向”卡片：顶部为 `有效入库 X / 已确认销售 Y / 待归属 X-Y`，并单独显示工单要求数量；下方按每条采购入库明细列产品号、单位、数量、日期、仓库及“查看采购入库详情”。展开后列候选销售出库单号、日期、客户、仓库、数量、业务性质和冲突提示，可打开现有销售出库台账详情抽屉。按钮“确认关联”让有权限的人员填写分配数量和说明；确认前预览该入库行及销售出库行的剩余可分配量。

列表仅显示简短状态与 `已确认销售/有效入库`，不要把“候选”显示成“已售”。提供“有候选待核”“确认部分销售”“确认全部销售”“来源冲突”筛选。跟单状态与销售去向状态保持独立，销售去向不参与跟单完成节点。

## 落地顺序与验收

1. 已实现只读候选查询与详情展示，同产品号的候选按单位、仓库、日期排序；可按出库单号或客户进一步搜索。候选不计入“已售”。
2. 已实现明细数量确认、撤销留痕、重导失效复核、权限和事务内并发限量校验。仅当前有效的确认计入“已确认销售”。多单位入库按单位分别汇总，不跨单位相加。
3. 最后接入其他入出库、调拨、期初库存和退换货，逐步缩小“当前数据未覆盖”的范围。

验收重点：同产品号多工单不会同时被自动认定售出；分批入库和分批销售的数量守恒；同一销售明细不会超量分给多个工单；草稿、处理中和非销售性质不计入已售；源单重导改变后自动提示复核；没有候选时不显示“未售出”。

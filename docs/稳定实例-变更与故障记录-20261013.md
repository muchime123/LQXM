## 三、故障档案（含完整取证）

### F-1 开发页面顶部红条「加载员工身份中失败」（2026-10-13）

**症状**：`http://localhost:5173` 顶部红条，所有接口失败。

**根因**：**8081 后端没在跑**。触发路径很有迷惑性 ——
跑 `start-local.ps1` 时显示：
```
Backend port 8081 already listening - skip backend start.
```
但那只是**执行那一瞬间**有个后台残留进程占着端口，脚本按「幂等防重复」设计跳过了启动；占用者随后退出，8081 就空了，而 5173 还活着 ⇒ 前端全接口失败 ⇒ 红条。

**处置**：见手册 §5.2（先查后端再动手，别重启前端）。

**教训**：启动脚本只判「端口是否在监听」，**不探测服务是否真的健康**。⇒「端口被占」≠「服务可用」，占用者可能是个残留/半死的进程。判断服务是否可用，永远用探活或页面本身。

### F-2 发布时 `Unable to rename '…jar' to '…jar.original'`（2026-10-13）

完整经过与两条根治见上文「二、变更记录 · 下午」。

**关键认知**：
- Windows 上运行中的 JVM 持有 jar 文件句柄 ⇒ **改名被拒**（但**写覆盖是允许的**）⇒ 失败后 `target` 里会留下一个**已被重写成 ~2.5MB 的瘦包**（不含依赖，`java -jar` 起不来）⇒ **必须重新打包成功才能用**。
- 发布是「先前端后后端」⇒ 后端失败会产生**「新前端 + 旧后端」的半发布状态**。这是把占用预检**提到最前面**的直接原因。

**判据（可证伪）**：后端在跑时对 target jar 做独占打开 —— 修前「正由另一进程使用」，修后「未锁定」。

### F-3 裸 `java` 起不来后端（2026-10-13）

**症状**：脚本报「启动完成」，但后端秒崩、无任何输出。

**根因**：本机 **Machine PATH 最前面**是 Oracle 的 `C:\Program Files\Common Files\Oracle\Java\javapath`，该目录只有 4 个 launcher（java/javac/javaw/jshell）、**缺 `jvm.dll`** ⇒ 执行即崩（`exit=0xC0000409(-1073740791)`、stdout/stderr 全空）。而 PATH 拼接 **Machine 优先于 User**（真 JDK 21 装在 User 级 `D:\Program Files\Java\jdk-21.0.12`）⇒ `Get-Command java -All` 第一条就是那个坏的。

**修法**：显式解析 `$javaExe` = `$env:JAVA_HOME\bin\java.exe` → `D:\Program Files\Java\jdk-21.0.12\bin\java.exe` → 裸 `java` 兜底；`$nodeExe` 同理。另加**启动后确认**：轮询 ≤30 秒，起不来就打印日志尾部并抛错。

**适用范围**：`mvn` 不受影响（它读 `JAVA_HOME`，User 级是对的）；受害的只有「用裸 `java` 命令直接起 jar」这条路径。

### F-4 命令「跑了却什么都没发生」—— IDE 集成终端环境字典冲突

**症状**：脚本执行了、无报错、但什么都没做（`stop-stable.ps1` 曾因此"跑了但没杀进程"）。

**根因**：IDE 集成终端（Trae / VS Code）会注入小写 `http_proxy` / `Path`，与 Windows 原生大写 `HTTP_PROXY` / `Path` 撞车，触发 PowerShell 5.1 重建子进程环境时的字典键冲突：
```
已添加项。字典中的关键字:"HTTP_PROXY"所添加的关键字:"http_proxy"
```
**判定方法**：查 `[System.Environment]::GetEnvironmentVariable('<name>','Machine')` 与 `'User'` —— 注册表干净就说明只是终端注入，**用户普通终端不受影响**。

**办法**：换普通 PowerShell 窗口；或加 `-Foreground` 前台跑。脚本已内置自诊断提示。

### F-5 受限沙箱跑不动 `vite build`

整条 `publish-stable.ps1` 会在前端构建的 `transforming...` 阶段被杀（日志仅 ~200 字节、**无任何报错**、`exit 1`）⇒ 别在此类环境里反复重跑整条脚本，**把发布命令交回你自己的终端**。

### F-7 「昨天下班到今天早上中间程序被关了」——Windows 更新计划内强制重启（2026-10-14 晚，2026-10-15 归因）

**LQ 的原始问题**（10-15 09:23）：「今早 09:07 那次重启是我自己点的；我想问的是**昨天下班到今天早上中间**，我的程序（稳定实例 / QQ / 微信）为什么被关了。」

**取证窗口**：2026-10-14 12:00 → 2026-10-15 09:10（System 日志，逐条可复核）

| 时刻 | 事件 | 含义 |
|---|---|---|
| 10-14 19:29:28 | **1074 User32** · 发起者 `C:\WINDOWS\uus\AMD64\MoUsoCoreWorker.exe`，代表 `NT AUTHORITY\SYSTEM`，原因「操作系统: Service Pack (**计划内**)」，原因码 `0x80020010`，类型「重启」 | **Windows 更新发起强制重启**（非用户操作） |
| 10-14 19:30:22 | **Winlogon 7002**（用户注销通知） | **用户会话在此结束** ⇒ 该会话内所有程序（QQ/微信/稳定实例 java 进程）随之被杀 |
| 10-14 19:34:57 | 6006 事件日志服务停止 → 19:34:58 Kernel-Power 109「Power Action Reboot，原因: Kernel API」 | 实际关机（19:30→19:34 这 4.5 分钟是更新在装包） |
| 10-14 19:35:13 | Kernel-General 12 操作系统启动（**第 1 次重启完成**） | — |
| 10-14 19:36:27 | **1074** · 发起者 `C:\WINDOWS\servicing\TrustedInstaller.exe`，原因「操作系统: 升级(**计划内**)」，原因码 `0x80020003` | **第二轮更新再次发起重启** |
| 10-14 19:36:33 → 19:36:53 | 关机 → **第 2 次重启完成** | — |
| 10-14 19:36:53 → 10-15 09:06:31 | **无任何 7001 登录事件** | **整夜无人登录**，机器停在登录界面 ⇒ 什么事都没在跑 |
| 10-15 09:06:31 | Winlogon 7001 登录 | LQ 到岗登录 |

**结论**：程序**不是今早被关的**，是**昨晚 19:30（会话结束）被带走的**——罪魁是 **Windows 更新的计划内自动重启**（19:29 与 19:36 两次），把机器重启了两轮；此后整夜停在登录界面，无人登录 ⇒ 未设自启的程序**不会自己回来**，所以今早看到的是「一片都没了」。

**为什么偏偏是 19:29？—— 找出可解释的规律**
- 注册表 `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings`：**`ActiveHoursStart = 9`，`ActiveHoursEnd = 19`**。
- 「活动时间」= Windows **禁止**自动重启的时段；活动时间一结束（19:00），Windows 即可自由重启 ⇒ 于是它**每次都在 19:00 刚过就动手**。
- 近 14 天实证：**10-13 19:29:10**、**10-14 19:29:28** 均由 `MoUsoCoreWorker.exe` 发起，时间几乎分秒不差地落在 19:29。⇒ 这不是偶发，是**每天都可能发生**的既定行为。
- 对照：10-07 11:40 / 16:48 / 17:30、10-02 16:13 那几次重启的发起者是 `StartMenuExperienceHost.exe`（原因「其他(计划外)」）⇒ 那些是**人手动点的**，与本次不同。

**除重启外无第三方插手**
- 卡巴斯基：`Kaspersky_Upgrade_Launcher` 任务近 3 天未运行；其事件日志 0 条；`Backup`/隔离目录 10-14 晚无新增对象 ⇒ **再次排除**。
- Application 日志中 **QQ / 微信 / java 均无崩溃记录**（1000/1001/1002 全空）⇒ 不是被杀软/异常终止，而是**随会话结束被正常结束**。
- 无 6008（意外关机）、无 41（Kernel-Power）⇒ 不是断电/死机。

**根因（与 F-6 同一条）**：两个条件叠加 —— ① **Windows 更新每天 19:00 后随时会强制重启**（活动时间 9–19 所致）；② **稳定实例 / QQ / 微信全部零开机自启**（任务计划里查无 LQXM/stable/8082；`Run` 键与启动目录也没有；系统会话内程序在注销时必然被杀）。⇒ **只要傍晚机器被更新重启一次，这些程序整夜都不会回来，直到次日有人手动拉起来。**

## 1. 结论

跟单表**不是可导入的新数据源**（手工维护、无幂等键、日期为 Excel 序列号、有重复副本），但它给出了切片**目前最缺的三件事**：

1. **完工 ≠ 入库**。气调机的「入库」被推到发货前集中办理（半自动中位间隔 6 天、最长 41 天，9 行里 8 行挤在同一天入库），封口机则是完工当天入库——**两条产线行为不同**。切片若把「末道工序报工完成」直接等同于「车间交付收货」，会与气调机实际不符。
2. **跟单员真正要的字段清单**：订单号 / 产品 / 规格(一出N) / 尺寸 / 数量 / 计划开工 / **订单要求完成日期** / 生产周期 / **倒计时** / **交付结果** / **预计完成日期** / **延期原因** / 分段实际完成日期 / 发货状态 / 业务员 / 备注。
3. **工序阶段按车间可配置**：气调机 7 段（画图·备料·钣金·模具·组装·调试·入库），封口机 4 段（备料·模具生产·组装·入库），**不是全局一套**。

另外确认一条硬事实：**工单与销售订单零绑定**——`production_orders` 5,691 行里 `linked_sales_order_no` 填充 **0**，`plan_type` **只有「非合同生产」一个值**。

## 4. 对「报工 → 车间交付收货」切片的实证启示

1. **完工与收货必须是两个独立状态，且允许长期分离**（最重要）
   - 封口机：`入库 − 组装` = **0 天（29/31 行）** → 完工当天入库
   - 半自动气调机：中位 **6 天**、最长 **41 天**，9 行中 8 行挤在 `2026-09-16` 同一天入库
   - 「延期原因」列 15 处非空里 **7 处是同一句「已按工期完工但是发货前才入库」** —— 跟单员明确把「已完工」与「已入库」分开表述
   - → 切片需要「**已完工待入库**」这个可用状态（对应现有 `PENDING_RECEIPT`），并明确可否跨月滞留、是否需要提醒；**不要**让收货成为完工的自动副作用
2. **收货单据应支持一单多台批量**：半自动 8 台同日入库；封口机 84 行数量=1，但 13 行=2、其余 3/5/7/8/10/12 → 批量场景真实存在
3. **报工（细）与跟单进度（粗）是两层，不是二选一**：车间按工序报工（含数量/报工人/时间），跟单员按 4~7 段记日期。ERP 若要提供「跟单视图」，应从报工聚合出阶段日期，而不是让跟单员重复录入
4. **工序模板按车间可配置**：气调机 7 段 vs 封口机 4 段 → 工序模板不能全局一套
5. **「车间」取产线口径**：最新版已放弃楼层口径，与 `production_line` 对齐 → ERP 工作中心用三车间
6. **「一出N + 尺寸」是行标识**：跟单表把 `规格型号(一出N)` 与 `产品尺寸` 与产品名并列作为一行机器的身份 → 印证决策 #2，工单/订单配置必须保留这两项可读属性（`mold_layout` 90.5% 填充）
7. **无订单生产是现实**：备注出现「转成库存机」「常规展会机」，`plan_type` 全为「非合同生产」，`linked_sales_order_no` 0 填充 → ERP 工单**不能强制绑定销售订单**，需允许无单投产

### ⚠️ 发现一处会阻塞本切片的权限缺陷

`ManufacturingService.requireVisible()` 的 DEPARTMENT 语义是：

```sql
FROM manufacturing_orders m LEFT JOIN employees e ON e.id = m.salesperson_id
WHERE ... AND e.department = <当前用户部门>
```

即过滤的是「**与工单业务员同部门**」（`e` = **工单业务员**），**不是**「我车间 / 我该看的车间」。

| 后果 | 实测 |
|---|---|
| ① **陈苏平（`department`=NULL）永久看不到任何生产任务** | SQL `e.department = NULL` 恒不成立 → 真库模拟 **0 行**。这是硬缺陷，与数据量无关 |

| ③ 角色全局 `data_scope=ALL` 被功能级 `DEPARTMENT` **覆盖** | `CurrentUserFactory` 先取 MAX 得全局 ALL，但 `DataScopeSupport` 里 `featureScope` **优先于**全局 → 表面 ALL、实际按部门过滤 |

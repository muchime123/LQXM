## 1. 源文件实测结构（40 张 sheet）

| 组 | 数量 | 内容 | 处置 |
| --- | --- | --- | --- |
| 账户明细 | 36 | 12 列基线表头 + 3 张外币 sheet 多 5 列 | **导入主体**，共 7831 行（含每 sheet 1 行「上期结存」伪行） |
| 汇总 | 1 | 2026年资金年报表 + 日报表，纯公式（#REF!） | 不导入；仅作**对拍校验**（上期结存/本年累计收支） |

| Sheet1/WpsReserved | 2 | 空 | 跳过 |

### 账户 sheet 表头形态（4 种）
- **31 张**（标准 12 列）：`月份|日期|供应商|摘要|客户 供应商|报销人|是否开票|收入|支出|结存|账户|返回首页`
- **2 张**（温州数创温州银行、宋文温州银行）：缺「月份」列
- **3 张**（温州睿包中信银行美元/欧元 等）：多 `汇率|人民币|结汇汇率|人民币|汇兑损益` —— 两个「人民币」语义不同，第二个须 `putHeader` 改名 `人民币(结汇)`
- 睿包**欧元** sheet 表头缺「月份」；**宋文温州银行** sheet 的「账户」列填的是「温州数创温州银行」（人工错填）

### 关键数据形态
| 项 | 实测 | 影响 |
| --- | --- | --- |
| 日期 | datetime 为主；于士强农业银行5277 有 **398 行文本「2026年1月1日」**；于士强农业银行6816 有 **7 行 Excel 序列号** | 解析须三分支：datetime / `YYYY年M月D日` / 数值序列号 |
| 首行 | 每 sheet 第 1 数据行 = 「上期结存」伪行（无日期，结存=期初余额） | 不进分录表 → **进账户维度表 opening_balance** |
| 幂等键素材 | 无任何单号/数据ID；`(日期,收入,支出,结存)` 全文件重复 **16 种**（最多同键 3 行） | external_id 须加同键序号：`账户#日期#收入#支出#结存#n` |
| 账户列 | 与 sheet 名一致（个别错填/空） | **账户 = sheet 名**（确定性来源），账户列不采信 |
| 币种 | 人民币 + 美元/欧元（3 张外币 sheet，含汇率/汇兑损益） | 账户维度表带 `currency` |
| 数据范围 | 至 2026-08（收银通到 09-16）；月份列取值混乱（1/2/3/4 + 空） | 月份列**原样存**（人工标注，不解读） |

### 收银通 sheet（利强收银通）
- 表头（第 1 行）：`交易完成时间|交易状态|交易金额(元)|订单总扣费(元)|付款人识别号|摘要|业务员`
- 6088 行，状态全「成功」，金额全非 0；**401 行缺摘要/业务员**（openid 未在 Sheet2 字典中）
- 幂等键 `(交易完成时间, 交易金额, 付款人识别号)` **6088 行零重复** → 干净
- 摘要形如「1.2精武鸭脖」「1.2蒋雨舟11150+3000」= 折扣率+客户名+备注，人工文本，**原样存不解读**

## 2. 方案对比：一个 kind 还是两个 kind？

| 维度 | A. 合并为 1 个 kind | B. 拆 2 个 kind（推荐） |
| --- | --- | --- |
| 数据形态 | 账户流水（日粒度、借贷+结存、36 sheet 异构表头）与收单流水（秒级时间戳、手续费、openid）完全不同 | 各自独立表头识别、独立幂等键 |
| 表头识别 matchesTemplate | 一套 matchesTemplate 要同时容纳 4 种表头 + 收银通，误判风险高 | 各自用独有列识别（账户表用「结存+报销人」，收银通用「订单总扣费+付款人识别号」） |
| 幂等键 | 两套逻辑塞进一个 externalIdOf | 各自干净 |
| 前端卡片 | 1 张卡混两件事 | 2 张卡，各自台账 Tab |
| 工作量 | 略省 | 多一套六件套（约 +1/3 工作量） |
| 与第 17 类 multiSheet 机制 | —— | 账户表直接复用 multiSheet=true（sheet 名=账户，天然注入） |

**推荐 B**：流水日记账 = 第 18 类 `cashflowJournal`（multiSheet 复用 17 类机制），收银通 = 第 19 类 `cashierLog`（单 sheet）。

## 3. 表结构草案（迁移号以动手时 `ls V3xx` 实测为准，下称 V-J/V-C）

### `h3_cash_accounts`（账户维度，由导入自动 upsert）
```
account_name  VARCHAR(64) UNIQUE   -- = sheet 名
currency      VARCHAR(8)           -- CNY/USD/EUR（按 sheet 是否带汇率列 + 名称判定）
opening_balance DECIMAL(18,2)      -- 「上期结存」伪行
system 列照抄 A 域十件套（external_id = account_name）
```

### `h3_cashflow_entries`（账户分录，multiSheet）
```
external_id  = 账户#日期#收入#支出#结存#n   （n = 同键序号，1 起）
source_no    = external_id（无业务单号，沿开票域惯例用 external_id 作历史键）
account_name, entry_date DATE, month_label（月份原文）,
summary（摘要）, supplier_raw（供应商）, counterparty_raw（客户 供应商）,
reimbursed_by（报销人）, invoiced（是否开票 原文）,
income DECIMAL, expense DECIMAL, balance DECIMAL,
fx_rate, fx_cny, settle_rate, settle_cny, fx_gain_loss   -- 外币 sheet 专有，人民币行 NULL
+ 系统列十件套
```

### `h3_cashier_log`（收银通收单流水）
```
external_id  = 时间#金额#openid（实测零重复，无需 seq）
source_no    = external_id
tx_time DATETIME, status, amount DECIMAL, fee DECIMAL（订单总扣费，源值带负号原样存）,
payer_openid, summary, salesperson
+ 系统列十件套
```

## 4. 口径与纪律（沿用既定拍板）

1. **校验源定位**：不参与收款权威（销售出库）、不做 resolveCustomer 身份解析（供应商/客户/摘要均为人工自由文本，只存 `_raw` 原文）。
2. **人工标注字段原样入库**：月份/是否开票/报销人 不解读、不清洗；脏值（宋文 sheet 账户列错填等）记文档不修数。
3. **对拍校验点**（导入后自动告警/人工核对）：
   - 每账户 Σ期初+Σ收入−Σ支出 = 末行结存（跑平校验）
   - 汇总 sheet「上期结存/本年累计收支」vs 分录聚合
   - 账户分录日合计 vs 收银通当日合计（同为流入侧的交叉核验，差异预期存在：收银通只覆盖微信收单）
4. **告警**：日期解析失败计数、外币行缺汇率、同键多行（n>1）计数、账户列与 sheet 名不一致行数。

### 7.2 两处表头陷阱（`putHeader`）

1. **`客   户    供应商`**：源表头夹带不规则空白 → 归一为无空格键 **`客户供应商`**。⚠️ save 里取值必须用归一后的键（曾写成带空格的 `客户 供应商`，见 §7.5 坑 6）。
2. **外币 sheet 两个「人民币」**：第 14 列 = 收入折算、第 16 列 = 结汇折算，语义不同 → 第二列改名 **`人民币(结汇)`**（与「仓管员/报工人/备注(平台)/付款方式(尾)」同款陷阱）。

### 7.3 幂等键与组键

- **分录（行级，无业务单号）**：组键 = `账户#日期#收入#支出#结存#同键序号 n`（n 由所在 sheet 行序确定，实测同键最多 3 行）。`external_id = source_no = 组键`。
- **期初行**：组键 = **`账户#期初`**（不掺金额，避免金额修订被判新行）→ 写 `h3_cash_accounts.opening_balance`，不入分录。
- **排除行**：账户 sheet 顶部「逐月空白填充行」（只有结存/月份，无日期无收支，实测 209 行）在**分组阶段直接跳过**。
- **收银通**：组键 = `交易完成时间#交易金额#付款人识别号`（实测 6088 行零重复；仅时间有 1 对同秒不同额，故必须带金额）。

### 7.5 本轮新踩的坑（已写入 skill 17–20）

1. ⚠️⚠️ **列宽只在 confirm 炸，现象是「卡在 PREVIEW_READY」**：`Data too long for column 'summary'`（源有 1 行多行备注摘要 262 字 > 255）→ MySQL 严格模式抛错、**整个 confirm 事务回滚**（两表 0 行），批次停在预览态。→ V317 ALTER。**建表前必须逐列量源字段最大长度**。
2. ⚠️⚠️ **POI `DataFormatter` 给的是「显示格式」串**：日期列为 `yyyy"年"m"月"d"日"` 时原文是 **`2026"年"1"月"1"日"`（带引号）** → `date()`/`dateTime()` 全部落空、**7 183/7 588 行 entry_date 为 NULL**。→ 解析前先剥引号。**诊断信号 = 告警原文带引号**；且 **openpyxl 看是 `datetime`，只看它会误判「日期没问题」**。
3. ⚠️⚠️ **无业务键的排除行若成组 → 台账永不收敛**：排除必须在**分组阶段显式 `return`/`continue`**（只置 `key=null` 会把该行并进上一组、污染其 hash）；**若排除行还要落另一张表（期初余额），必须给它确定性组键（`账户#期初`）并在 `loadExistingFacts` 里把该表 `CONCAT(...,'#期初')` UNION 成同型事实键**，否则同样恒判 CREATE（本轮实测每轮多计 34 条 → 收敛判据失效）。
4. ⚠️ **标记列位置逐 sheet 不同**：「上期结存」在多数 sheet 落「摘要」列，在 `浙江利强中国银行欧元` 落「供应商」列 → 判定必须**全字段扫描**。
5. ⚠️ **同一个「期初行是否入组」的判据写在两处**（`cashflowRowKey` 与 `isOpeningBalanceRow`）→ 改一处漏一处：`cashflowRowKey` 曾硬取「摘要」，导致欧元账户整体缺档（34 而非 35 个账户）。**教训：判据只留一个实现，另一处调用它**（已改为 `cashflowRowKey` 直接调 `isOpeningBalanceRow`）。
6. ⚠️⚠️ **表头归一后的键名与取值键名不一致 → 静默全空**：`putHeader` 归一成 `客户供应商`，save 却取 `客户 供应商` → **`counterparty_raw` 全表 0 行（源侧 7 129 行）**，前端「客户 供应商」列恒显示「—」。**教训：新 kind 落库后必须对每个字段做「填充率 vs 源侧填充率」逐项对拍**（本轮靠这一步抓出），只看行数/金额合计抓不到。

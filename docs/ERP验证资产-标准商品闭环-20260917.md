## 0. 交付物与运行方式

| 文件 | 作用 |
|---|---|
| `scripts/erp-s0-schema.sql` | 隔离 schema `erp_s0_verify` 的 15 张骨架表（**不是生产表结构**，是 S0 假设下的最小可运行模型） |
| `scripts/erp-verify-s0.cjs` | harness 主体：领域原语（过账/核销/调拨/冲销/幂等）+ 断言框架 + 主流程 |
| `scripts/erp-s0-cases.cjs` | 43 条用例的可执行实现 |

```bash
# 建库（幂等：含 DROP DATABASE）
mysql -uroot -p*** < scripts/erp-s0-schema.sql

# 全量跑
node scripts/erp-verify-s0.cjs

# 只跑指定用例
node scripts/erp-verify-s0.cjs T01 B09

# 机器可读
node scripts/erp-verify-s0.cjs --json
```

**隔离保证**：harness 只连 `erp_s0_verify`，不触碰 `product_archive`。B20 用例会断言「本 schema 内不存在任何 `h3_%` 表」——从结构上证明 ERP 骨架与氚云源无耦合。

### 1.1 全绿不是证据 —— 变异测试已验证判定能力

「43 例全过」本身可能只是断言太松。为此做了**变异测试**：故意破坏 harness 中的 3 条规则实现，观察是否如实报红。

| 变异 | 破坏内容 | 被抓到的用例 |
|---|---|---|
| M-1 | 去掉禁负库存检查 | B08（冲销造负库存） |

## 2. S0 假设（本次验证成立的前提）

以下都是**沙箱测试假设，不是已批准的生产政策**（契约 §1）。用例的通过只在 S0 前提下有效。

| 假设 | 取值 | 对应待拍板项 |
|---|---|---|
| 公司 | 单一公司（用例中另有公司 2 仅用于跨主体拒绝验证） | D01 |
| 币种 | 同币种 CNY | D06 |

> ⚠️ 任一假设被业务推翻，对应用例须重跑并更新预期——`ruleVersion` 字段已为每个对象保留版本号（X03 用例验证了这一点）。

## 3. 用例设计与判定方式

### 3.1 编号来源与合并

| 来源 | 条数 | 说明 |
|---|---|---|
| 蓝图 T01–T18 | 18 | 原表 §8 |
| 契约 B01–B20 | 20 | 原表 §9 |
| 字典 M03–M16 | 5 | 原表 §8 中可直接执行的部分 |
| 本文新增 X01–X04 | 4 | 针对设计输入 C4/C5/C6/C9 的结构性不变量 |
| 实际实现 | **43** | T13/T18 并入他例；B09≈T09、B18≈T13 合并 |

**未实现并在下方标注的**：T13（生产领退料，需要 BOM/工单模型，属 G2 缺口）、B18（停用客户退款，需要主数据生命周期实现）。这两条**不是遗漏，是超出 S0 骨架范围**——S0 只覆盖标准商品进销存，不含生产与主数据停用流程。

### 3.2 判定纪律

- 数值比较一律走 `nEq()`（容差 1e-9），禁止 `===` 比 DECIMAL（设计输入 C5）。
- 字符串/状态用 `is()` / `str()`，与数值断言严格区分。
- 期望被拒绝的场景用 `rejects(fn, 错误码)`，**必须匹配到具体错误码**，不接受「抛异常就算过」。
- **失败照实报告**：不静默跳过、不放宽断言、不为「全绿」修改预期。

## 4. 不变量清单（本次验证的核心）

### 4.1 数量守恒

| 不变量 | 验证用例 | 断言 |
|---|---|---|
| 事件净额 = 余额 | T01 | 对 `stock_event` 求和 == `stock_balance` |
| 总货权守恒（现场 + 在途） | T09 | 调拨全过程 `totalQty` 不变（发出/首收/末收三点） |
| 质量转移不重复入库 | B05 | 放行前总现存 = 放行后总现存 = 5 |
| 数量换算按 SKU 定义 | T07 / M04 | A 一箱 12、B 一箱 24，22 箱 ≠ 全局比率 |
| DECIMAL 无残差漂移 | X02 | 3 板 × (1/3) 精确为 `1.000000000` |

### 4.2 额度与并发

| 不变量 | 验证用例 | 断言 |
|---|---|---|
| 零超量容差 | T02 / B03 | 超额出库触发 `SOURCE_QUANTITY_EXCEEDED` |
| 关闭后不可再执行 | B03 | 关闭剩余 6 后发 1 被拒 |
| 已执行不可回缩 | B04 | 承诺量改为 3（< 已执行 4）被拒 |
| 禁负库存 | T06 / B08 | 并发出库只成功一笔；冲销不造负库存 |
| 可退量上限 | B06 | 已售 4 退 1 后再退 4 被拒 |
| 退货不自动重开额度 | B07 | 退货后补发被拒 |
| 在途收货上限 | B10 | 在途 2 收 3 整次拒绝 |
| 资金/项目双侧额度 | T03 / B11 / B13 | 超 `F−R−A−H` 或超未结均拒绝 |

### 4.3 状态与生命周期

| 不变量 | 验证用例 | 断言 |
|---|---|---|
| 审批与过账独立 | X04 | `APPROVED` 但 `UNPOSTED` 时库存不变 |
| 草稿零影响 | T11 | 草稿取消后库存/往来/资金均 0 |
| 未审核不得过账 | T14 / T11 | `INVALID_STATE` |
| 过账幂等 | B02 / T05 | 重发返回原结果，事件不重复写 |
| 冲销不改原单 | T10 | 退货不自动生成退款资金事实 |
| 快照隔离 | T12 | 主档改名不改历史单据身份 |

### 4.4 结构性缺口（对应设计输入 C 系列）

| 缺口 | 验证用例 | 断言的约束 |
|---|---|---|
| C4 一行多角色 | X01 | 同一明细行产生 2 腿事件 |
| C5 浮点残差 | X02 | DECIMAL 精确，无 `0.9999...` |
| C6 规则版本可复算 | X03 | 单据与往来均带 `rule_version` |
| C9 状态分离 | X04 | 两维度独立演化 |
| B20 与源解耦 | B20 | schema 内无 `h3_%` 表，重导不影响 ERP |

## 5. 保留意见（必须与结果一起读）

### 5.1 S0 是简化模型，不是生产方案

- 骨架表**刻意省略**了权限、审计、期间、批次/序列号、库位、多币种、跨公司结算、成本计价。
- 这些不是「已验证可行」，而是「本阶段没验证」。契约 §10 的 D01/D04/D05/D06/D07/D08 仍全部未决。

### 5.2 并发是顺序模拟

T06（并发出库）与 B11（并发核销）用**顺序调用 + 额度校验**模拟，未使用真实并发连接。真实并发下的行锁行为需在技术方案阶段用压测验证（契约 §8「行锁或等效并发控制」）。

### 5.3 未覆盖的规则

| 未覆盖 | 原因 |
|---|---|
| 生产领退料守恒（T13） | 需 BOM/工单模型；对应源数据缺口 G3 |
| 主数据停用后的历史业务（B18） | 需主数据生命周期实现 |
| 实际开票与红冲（T15 只验证了申请侧） | 对应源数据缺口 G2 |
| 采购付款与应付核销（B 系列只验证了收款侧） | 对应源数据缺口 G1 |
| 跨公司/跨币种结算（T16 只验证了拒绝） | 需业务先定规则 |

### 5.3 执行中修掉的 harness 缺陷

首轮 43 例为 39 PASS / 2 FAIL / 2 ERROR，全部是 harness 自身缺陷，非规则问题：

| 现象 | 根因 | 修正 |
|---|---|---|
| B01 订单执行量 = 0 | 入库侧漏了回写来源订单行（出库侧有，入库侧没有） | 抽 `checkOrderLineQuota` 双向共用 |
| T05 结果引用比较失败 | 用数值容差断言比字符串（`Number('DOC-1001')` → NaN） | 新增 `str()` 断言 |
| B12 调整被拒 | 用例步骤顺序违背契约 §7.3（应先解核销→再调整→后核销） | 按 §7.3 工序重写 |
| T14 库存 12 而非 8 | 盘点差异符号二次取反 | `signed = sign(qty) × abs(baseQty)` |
| T14/B16 误报未覆盖事件 | 截点用固定时间，同秒比较歧义 | 截点取 `MAX(occurred_at)`，需要时显式推后 |

# 履约评审、生产下达与交期变更

本阶段收敛正常流程的重复需求审核，并将执行风险与客户承诺变更分开。以下是本轮已实现行为，不代表配置、价格或取消等完整变更能力已经建设。

## 正常流程

销售填写需求及产品配置 → 车间评审自产、采购评审外采 → 销售订单审批确认。

- 自产：在“待下达生产需求”查看原需求，点击“生成生产任务”。任务引用原配置、数量、客户交期及绑定制程，不再进行第二轮需求评估。新生成任务沿用销售订单审批依据，有工序进入已下达，无工序进入待检验；任务详情显示依据为原销售订单，不伪造独立生产审批流水。
- 外采：生成采购订单，采购确定供应商、采购价格和到货计划；采购订单继续审批。这是采购支出授权，不是重复判断客户需求能否履行。
- 展会、备库、展厅等独立生产任务仍需提交自身审批。历史已经生成的任务不自动改状态或补审批依据。

## 登记执行问题

入口共用同一弹窗：待下达需求的“登记条件变化”、关联销售订单的生产任务详情、采购订单详情，以及销售订单明细的“登记风险／问题”。

填写具体问题、处理方案，并选择影响：

1. 风险提醒，继续办理：保留问题待办，但不阻止后续执行。
2. 暂停本明细后续下达及发货：阻止新建生产／采购单、采购提交／审批及出库过账。已有报工、检验和到货不会自动停止，由执行人员协调。本轮尚未实现分工序或仅发货等更细粒度暂停。

车间／采购可以填写“执行方确认的可行客户交期”，核对所展示的关联单据并说明执行安排。销售普通登记入口不提供执行方交期承诺。后端按明细的自产／外采方式核验执行方权限，记录提出人、日期、原需求和执行快照。

每条明细同时保留一条未解决问题，先处理原记录。历史异常继续保留原来的暂停语义，不自动改成风险提醒。

内部调整仍能满足原产品、数量和客户交期时，订单不用变更。销售记录原约定仍可执行的依据，使用“原约定不变，解决问题”结束记录。此步骤不改订单版本。

## 客户交期确实需要改变

### 客户接受执行方原方案

1. 执行方登记具体可行交期与安排。
2. 销售同客户协商；协商期间原订单交期保持不变。
3. 客户明确接受时，在销售订单问题记录点击“客户接受原交期方案”。
4. 填客户确认日期、记录位置或补充协议等依据。
5. 系统校验原数量、原交期及执行快照；仍有效则生成已生效变更、递增订单版本、同步未完成生产任务需求交期并解决问题。无需重复执行复评，也无需 sales_order.approve 权限。

如果报工、入库、到货、单据状态或关联单据已经变化，旧执行快照不能继续使用。通过“协商其他数量／交期”提交当前方案、重新确认执行可行性，然后登记客户接受结果。不会直接覆盖生产事实。

### 客户提出其他方案

1. 销售点“协商其他数量／交期”，填写客户提出的日期和沟通记录。
2. 自产由车间、外采由采购确认新方案是否可行；需要调整时退回销售协商。
3. 仅交期变化且执行方确认可行后，状态为“待客户确认”。
4. 销售记录客户最终接受依据，点“登记客户接受并生效”。不再要求第二次销售商业审批。
5. 客户不接受时可“客户未接受／撤回”，原订单不改变，问题继续保留，另行协商或按原约定解决。

数量变化仍需商业审批。已有下游单据的数量变更不自动改写，本轮继续拦截。执行方复评确认数量方案并不能替代增购金额的授权。建设前已复评通过、待销售审批的纯交期变更，可走客户确认入口，不会自动生效。

## 本轮边界

- 不自动修改排产起止日期、供应商到货计划、已完成任务或历史报工／入库／出库。
- 有待审批采购单或有效出库记录时，交期变更继续要求先协调处理。已取消／已冲销的出库记录保留可查，但不再作为有效发货阻碍。
- 配置、型号、价格、取消和复杂数量变更尚未实现，页面已明确提示。
- 没有自动向客户或其他人员发送消息；客户确认依据由授权销售人员登记。
- 权限：风险登记由销售管理或对应执行岗位；交期确认由 sales_order.manage 且校验订单数据范围；数量等商业审批仍由 sales_order.approve。

## 验证

隔离 MySQL 验证了：风险提醒不阻断执行、暂停记录会阻断、无客户依据拒绝生效、原交期方案直接接受及幂等、执行快照变化时无变更写入、其他交期方案转客户确认、数量方案仍走审批及可撤回、销售关联任务沿用订单依据而独立任务不能借用该依据。既有销售审批、采购审批／到货、独立制造审批及异常规则回归通过。

浏览器使用模拟接口验证销售只有管理权限时可登记两种交期方案的客户接受结果、生产下达入口名称及风险方案提交；原订单发货和执行复评页面回归通过。测试未对真实客户订单写业务数据。

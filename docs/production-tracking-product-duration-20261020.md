# 生产跟单产品工期（产品级参考间隔）

本阶段让**每个任务单产品各自决定参考工期**，继续沿用 `ProductionTrackingPolicy` 的节点顺序、完成状态、列表分母与 Excel 回写口径。氚云报工工序和本地跟单节点仍是两套不同记录，不共用工序 ID。

> 结构、边界与页面约定（产品身份＝车间+产品名、可选配置不进产品名、三栏布局、权限、不做什么）已由
> [任务单产品与配置设计](任务单产品与配置设计-20261021.md) 定稿；本文只讲间隔算法与发布口径。

> 2026-10-20 曾先做「产品工期分组」中间层（V391），当天即删除：每个产品的历史样本都足够独立统计，先归组再算工期会把同组产品的差异抹平，而分组本身要额外维护。分组结构与相关端点由 V394 一并移除，库里只剩产品级一种口径。

## 数据与匹配

- `production_tracking_product_benchmarks.task_config_id`：指向 `manufacturing_task_config_items` 的**产品名称行**（车间 + 产品名），唯一键 `(task_config_id, stage_code)`，随产品删除级联。
- 每行保存该节点的历史候选（样本量、P50、P75、排除数、零天数、首节点起点来源）与人工审核发布值 `typical_days`。候选与发布值分开；重算候选不会自动改在制任务参考日期。
- 生产任务按**车间名称 + 产品名称**精确匹配启用的产品配置；唯一命中时，用该产品已发布的节点间隔覆盖车间基准，未发布的节点沿用车间基准。没有匹配、同名产品在同一车间有多行配置（不猜）时全部沿用车间基准。原始产品名称不被改写。

## 历史候选计算

样本是**该产品自己的跟单记录**（`production_tracking_state` 存在 + `production_orders.production_line/product_name` 精确匹配），**不是该产品的全部历史任务单**：6038 张任务单里目前只有 593 条跟单记录，从没进过跟单的单没有任何节点完成日期，算进来只会把「样本量」显示得虚高（2026-10-21 修正，`loadOrderSamples` 已改为 JOIN `production_tracking_state`）。计算上一跟单节点完成到当前节点完成的自然日。**首节点锚点从排产时间起算**（2026-10-21 LQ 定）：优先级＝本地计划开工 `planned_start_date` → 氚云排产时间 `production_orders.schedule_time`（99% 有值）→ 申请日兜底；前两者算排产锚点、首段进正式候选，只有申请日兜底的片段单独计数和计算分位数，**不计入正式候选**。缺起点、缺相邻节点完成日期、日期倒序（含完成早于排产）、未来完成日期或间隔超过 60 天的片段不参与分位数；已取消任务不参与。按需节点没有完成记录时跳过。零天间隔保留在候选中但单独展示，发布前应抽查是否为批量补录。界面显示的是**节点间隔片段**数，同一任务可能贡献多个节点片段。P50/P75 使用线性插值并保留一位小数。超参考日期只提醒填写原因，不阻断跟单保存。

2026-10-20 的实库只读核查见 [样本质量报告](production-tracking-duration-quality-20261020.md)：6025 张任务中 6021 张精确匹配产品配置。⚠️ 该报告里「计划开工日期均为空、首节点无法发布」的结论已被 10-21 口径修正——空的只是本地 `planned_start_date`，氚云 `schedule_time` 一直有值，现作为首段锚点。

2026-10-21 按 593 条跟单记录重算（排产时间锚点）的产品级间隔、样本量与零天占比见 [跟单节点间隔实测](跟单节点间隔实测-20261021.md)。三条结论：① 每个产品能用的样本远小于历史单量（手动片膜 1115 张单 / 103 条跟单）；② 封口机「备料」「入库」两段 P50＝0 天（零天占比 90% / 90%），参考间隔填 0 对跟单没有约束力；③ 有区分度的是封口机的「模具」「组装」和机器车间的「钣金」「组装」。

## 发布方式

- 逐节点保存：单行「保存」即发布该节点，空值表示回退车间基准。
- 按 P50 批量填充：`POST /api/manufacturing/followups/product-node-benchmarks/{taskConfigId}/apply-p50`，只补「尚未发布 + 候选样本 ≥ 3 段」的节点，已发布节点不动。3 段是下限，避免一两条补录记录定下参考值；界面确认框会写明将填充的节点数。

## 维护入口与页面结构

入口：`/manufacturing-task-configs`（任务单产品与配置），单页三列布局，无 Tab。2026-10-20 起参考间隔不再出现在「制程与工序管理」页——该页是氚云实际工序主数据，氚云工序不按时报工，与跟单节点参考间隔口径无关。

- **左：生产车间**：车间卡片列表（默认制程、产品数、配置数）。点击切换产线。
- **中：产线详情**：默认制程卡片 + 「产品名称」表（每行可编辑产品名 / 启用 / 历史工单 / 已发布节点 `x/y` / 保存，点击行选中用于右栏）+ 「可选配置」表（产线级，不随产品切换）。
- **右：选中产品节点参考间隔**：选中产品后显示头部（产品名 + 车间 tag + 已发布 `x/y`）与「节点参考间隔」表（车间基准对照、本产品间隔、历史候选、计算历史样本、按 P50 填充）。无选中产品时显示提示。
- 1500 屏以下三列回到「产线 + 详情」两列（参考间隔降到底部整行）；900 以下回到单列流式。
- 页头常驻全局状态条：历史任务数 / 匹配到产品配置数 / 命中产品已发布间隔的张数，以及参考日期口径说明。

## 权限与后续

产品与配置维护沿用 `manufacturing.template.manage`；历史候选计算、发布与 P50 批量发布使用 `manufacturing.baseline.manage`（无该权限时本页只剩产品清单只读）。本阶段没有增加“不适用／待确认”状态，也没有改动节点完成判断。

任务级动态节点模板属于下一阶段：实施前需统一后端节点白名单、列表进度 SQL、详情、Excel 导入导出和历史兼容。现阶段按产品逐个推进：先「计算历史样本」看样本量与 P50，样本可信的节点再发布，历史工单过少的产品继续沿用车间基准。

# 生产跟单节点体系收敛设计（2026-11-02）

> 产品制程版本与本单制程调整部分已于 2026-11-02 撤回；现行范围见 [制程管理入口撤除记录](production-tracking-process-management-withdrawal-20261102.md)。跟单只覆盖已开始跟单任务的范围规则继续有效。

## 1. 范围先行

生产任务单全集不等于生产跟单任务集。氚云导入只更新源任务及源事实；跟单员明确纳入，或已有真实跟单操作的任务才进入跟单范围。工作台可以单设“待纳入任务”查询，不能将其混入已跟单统计。列表中的“需要处理”是已纳入任务的待办视图。停止跟单的任务保留记录，生产恢复后恢复原任务。

建议用 `production_tracking_enrollments` 的纳入事件作为新数据权威入口；旧数据按已有里程碑、跟进记录、非空版本变更识别，并生成只读核查清单。空 `production_tracking_state` 行、单纯的源单提交日期、氚云首次导入都不是纳入证据。旧进度表历史入口仅用于识别既有跟单事实，本轮不改导入和回写。

## 2. 四层节点模型

| 层 | 权威数据 | 用途 | 写入时机 |
| --- | --- | --- | --- |
| 全局节点字典 | `production_tracking_stage_dictionary` | 统一节点编码、名称、条件识别规则；不归属车间 | 管理员维护 |
| 车间默认流程 | `production_tracking_stage_defs.default_included` | 产品未配置专属流程时的兜底节点组合 | 管理员显式选用 |
| 产品制程版本 | `production_tracking_process_templates` 及节点、依赖边 | 产品开始跟单时可采用的已发布默认方案 | 草稿审核发布 |
| 任务制程快照 | `production_tracking_process_snapshots` 及节点、依赖边 | 这张已纳入跟单任务实际执行和计算的依据 | 开始跟单时一次性冻结；本单调整留审计 |

字典新增节点不会自动进入默认流程或任何产品。产品流程从字典选择节点，决定顺序、条件和依赖。模板改版不修改已有任务。已登记的节点不能静默移除；调整本单制程须展示影响、原因与前后快照。

## 3. 跟单启动与快照

新任务导入时只存源单；跟单员点击“开始跟单/纳入跟单”后，在同一事务中创建纳入记录、跟单状态和任务制程快照。优先精确匹配唯一已发布产品模板，否则冻结该车间默认流程，并明确标记为兜底来源。重复纳入必须幂等。已有真实跟单操作但无纳入记录的旧任务，先按旧流程建立兼容快照，不追溯套用今天的产品模板。

产品模板页面应显示“只影响今后开始跟单的任务”。对于已开始跟单的订单，页面应显示当前快照来源、版本及“调整本单制程”入口。已发布模板有 8 节点、旧任务仍是 7 节点是正常的版本隔离，界面必须直说，不能让用户误认为配置未生效。

## 4. 页面职责

- **节点与流程管理**：全局字典、车间兜底流程。两者分区维护；新增字典项不自动进入流程。车间兜底流程应标明“仅用于尚无产品模板且开始跟单的任务”。
- **产品节点与参考工期**：主表只显示本产品已采用的节点；“管理节点”从全局字典加入或移除。每行展示顺序、前置依赖和发布参考天数。未发布草稿与已发布版本明确区分，保存草稿不等于发布。
- **任务跟单详情**：只显示本任务快照节点及实际执行记录，展示来源和版本。必要时通过有权限的“调整本单制程”变更，不随产品模板自动变化。
- **待纳入任务**：独立查找氚云源任务，执行纳入操作；不进入常用工作台、节点完成率和工期样本。

## 5. 参考工期与样本

参考工期是里程碑**完成间隔**，不是工序实际加工工时。候选 P50/P75 仅从已开始跟单且有可信日期的任务计算。统计每个节点的有效样本、零天、排除数和排除原因；产品源任务数量只作为产品覆盖信息，不能标作跟单样本。

已发布参考值优先于车间通用值；借用通用值须明确标记来源。产品模板版本样本与旧按产品名计算的候选应分开展示并标注口径，不能混成一个 P50。并行依赖只在计算路径已统一且所有消费方使用同一算法后参与预计日期；此前不把并行节点的完成日期差冒充加工耗时。DONE 但日期未知的节点参与完成状态判断，不进入日期间隔样本。

## 6. 实施顺序与验收

1. 修复范围：从氚云导入移除自动建跟单快照；纳入跟单时原子建快照；拆分待纳入与已跟单查询。核对权限和重复导入幂等。
2. 收敛页面：字典、兜底、产品版本、任务快照分别标名；产品表只显示采用节点，管理弹窗列全局可选项；旧任务显示快照版本差异。
3. 收敛统计：所有跟单完成率、节点分析、交期分析和 P50/P75 共用已开始跟单范围，再按各自状态和样本质量筛选。
4. 数据治理：只读盘点空状态行、源任务但未纳入、已有记录无纳入、快照与纳入不一致；逐批补建兼容快照，不改写历史节点日期。

验收至少覆盖：氚云导入但未纳入的任务不生成快照或样本；纳入时选取当时已发布模板；模板改版后旧任务不变；本单调整留历史；停止及恢复沿用同一快照；P50/P75 样本只来自已跟单且日期可信的任务。实库数量必须按核查日期标注，不能沿用旧快照充当当前事实。

# 生产跟单制程管理与生产参考工期 · 双页面收敛设计

> 已于 2026-11-02 撤回。现行决策见 [制程管理入口撤除记录](production-tracking-process-management-withdrawal-20261102.md)：不提供制程管理页面、产品制程版本配置或本单制程调整。

更新时间：2026-11-02。此文是产品设计与实施依据；实库数量须重新查询，不引用旧报告的“模板 0 / 快照 0”作为当前事实。

## 一、先确定业务边界

氚云 `production_orders` 是全部源任务；生产跟单只覆盖明确开始跟单的部分任务。产品制程配置可以预先维护，但它不意味着同产品的全部源任务都开始跟单。源任务导入不创建跟单事实、进度或任务制程快照。跟单员开始跟单时，系统才确定这张单的节点组合并冻结。

用户日常只需要理解三个问题：

1. **字典**：有哪些可选的跟单节点？
2. **产品方案**：这个产品跟哪些节点，各节点的参考完成间隔是多少？
3. **本单执行**：这张已经开始跟单的任务，实际使用哪个节点组合，完成到哪一步？

车间默认流程只是产品尚无方案时的兜底，不是全车间统一工艺。

## 二、两个页面的明确职责

### 页面 A：制程管理

分成两个区域，不出现产品参考天数：

| 区域 | 管理内容 | 操作 | 生效范围 |
| --- | --- | --- | --- |
| 全局跟单节点字典 | 稳定编码、名称、说明、按需识别规则 | 新增、编辑、查看引用；有引用不能删除 | 只增加“可选项”，不自动加入任何流程 |
| 车间默认流程 | 从全局字典选择兜底节点、顺序及条件 | 加入、移出、排序 | 今后开始跟单且没有已发布产品方案的任务 |

字典不跟车间走。同一个节点编码只定义一次。车间默认流程引用字典节点，可有不同的组合和顺序。页面应明确展示“字典共 N 个节点；当前默认流程使用 M 个”，避免把未选用误读为停用。新增字典节点不能直接出现在产品表或跟单任务中。

### 页面 B：生产参考工期

以产品为入口，一张主表同时管理该产品的**跟单节点方案和参考完成间隔**。主表只显示该产品已采用的节点；“管理节点”弹窗列出全局字典供加入。产品无专属方案时，表格预览车间默认节点，并标注“尚未保存为本产品方案”。

| 主表内容 | 说明 |
| --- | --- |
| 节点、顺序、前置节点 | 定义该产品需要跟哪些节点及先后关系；上移/下移代替手输序号 |
| 节点性质 | 必经或条件；条件判定来自源单配置，人工修正仅针对本单并留原因 |
| 参考天数 | 该节点完成间隔的已发布产品值；未发布时显示车间通用值及借用标记 |
| 历史样本 | 有效样本量、P50/P75、零天和排除数；点击查看样本与原因 |

表格下方只显示“保存草稿”“发布方案”和参考工期合计。保存草稿仅存管理者的修改；发布后供今后开始跟单的任务采用。产品参考天数的发布与节点方案的发布应在界面上明确标识，不要让一行的“保存”与整套方案的“发布”看起来是同一个动作。

## 三、版本与任务快照怎么呈现

版本是产品方案的历史记录：V1、V2 表示发布了不同节点组合、依赖或参考设置。日常页面默认只展示“当前已发布方案”，历史版本收在“查看变更记录”中。修改已发布方案时自动另建草稿；旧版本只读。

任务快照是**已开始跟单任务的本单方案**，用于保证后来修改产品方案不会改写正在跟单的单。它只在任务详情显示为一行：“本单节点方案：产品方案 V1 / 车间默认流程 / 本单调整”，附“查看依据”“调整本单节点”入口。任务快照不单独设管理页。调整本单节点必须预览完成率变化，保留已有执行记录、填写原因并审计。

例如产品 V1 发布 8 个节点，而较早开始跟单的任务仍有 7 个，这是历史隔离。详情应直说“本单开始跟单时采用旧方案；产品新方案仅用于后续跟单”。需要本单跟 8 个节点时，走本单调整，不能因模板发布自动批量改写。

## 四、参考工期只保留清楚的三种角色

1. **车间通用参考**：产品没有可信专属值时借用；显示“沿用通用”，不是产品实测。
2. **产品已发布参考**：人工审核后用于本产品参考日期；页面显示发布来源和时间。
3. **历史候选 P50/P75**：帮助审核的证据，不自动成为参考日期。候选必须注明按什么任务与流程计算，且展示每个节点的有效样本数。

现有“按产品名的旧候选”与“按制程版本的样本”是两种统计口径，应并列标名。优先逐步使用**相同产品且制程边界可比较**的已跟单任务计算候选；旧口径保留为过渡历史参考，不与新版候选混写。节点 DONE 但无真实完成日期，不参与日期间隔 P50/P75；推断日期也不能冒充真实日期。只有完成日期而没有开工/停工数据时，指标名应是“节点完成间隔”，不能写“加工耗时”。

若产品节点存在并行依赖，简单相加会高估工期。当前可继续显示逐段参考值，但合计必须标注“线性试算，不适用于并行路径”，且不要据此生成承诺交期。未来如做并行预测，详情、列表、节点分析须同用一套计算规则。

## 五、数据生效规则

| 事件 | 字典 | 车间默认流程 | 产品方案 | 已跟单任务 |
| --- | --- | --- | --- | --- |
| 新增字典节点 | 新增可选项 | 不变 | 不变 | 不变 |
| 改车间默认流程 | 不变 | 今后兜底使用新流程 | 不变 | 原快照不变 |
| 发布产品新版本 | 不变 | 不变 | 今后开始跟单采用新版本 | 原快照不变 |
| 修改产品参考天数 | 不变 | 不变 | 新发布值生效并留历史 | 详情参考日期须显示采用的基准来源和更新时间；不能改写实际节点日期 |
| 氚云重复导入 | 不变 | 不变 | 不变 | 只更新源事实，不重建快照或覆盖人工记录 |
| 停止/恢复跟单 | 不变 | 不变 | 不变 | 保留并复用本单节点及历史 |

## 六、当前代码需要收口的关键处

1. `ProductionTrackingService.visible()` 仍以提交日期自动纳入源任务；应拆成“待纳入候选”和“已开始跟单”两个范围。空状态行不算开始跟单。
2. `H3FactImportService` 在源单首次导入时调用 `captureNewOrder()`；应移到开始跟单的原子事务中。旧任务已有真实跟单事实时按兼容规则建立快照。
3. 生产参考工期页面应把节点选择、顺序、参考天数放在同一产品表中，但明确草稿与发布；未采用字典节点只在“管理节点”中出现。
4. 两套 P50/P75 的来源、可比较流程和样本排除条件须标识并收敛；统计分母只能是已开始跟单任务中的可信样本。
5. 老报告的任务、模板和快照数量只可作为注明核查日期的历史截面。上线前重新只读验收纳入任务、空状态行、已有记录无纳入、源任务快照和模板使用数量。

## 七、验收要看什么

- 导入一张氚云任务但不开始跟单：不出现在已跟单工作台，不生成快照，不计入节点分析和参考工期样本。
- 开始跟单：有唯一已发布产品方案则采用该方案，否则采用车间默认流程；重复点击不重复建快照。
- 改字典、默认流程或产品方案：已有任务的节点数、进度与历史日期不变。
- 产品表只显示已采用节点；管理弹窗可增删字典节点；草稿保存后未发布，新任务不采用草稿。
- 产品版本 8 节点、旧任务 7 节点时，详情解释来源，并可通过有审计的本单调整补节点。
- P50/P75 只使用已跟单且日期可信、流程可比较的样本；候选与发布值分清，零样本不显示伪精确结果。

Excel 旧表导入与导出回写本轮维持现状，不作为节点体系收敛的前置条件。

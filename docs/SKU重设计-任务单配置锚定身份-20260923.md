## 0. 结论先行

氚云的病根不是「没人把配置翻译成名字」，而是**把「人手拼的显示名」当成了唯一身份**。翻译层其实很简单，难的是**分清三件事**：

| 层 | 是什么 | 谁用 | 允许重复 |
|---|---|---|---|
| **显示名** `displayName` | `品类-尺寸一出N+配置` 的人话串 | 人看（库存页、出库页、打印） | ✅ 允许 |
| **身份键** `skuKey` | 规范化配置串（内容寻址） | 系统认、库存聚合 | ❌ 唯一 |
| **订单产出标识** `MFG-{工单号}` | 本单产出了什么 | 溯源、跟单、可售通知 | ❌ 唯一 |

> **一句话**：显示名给人看、身份键给系统认、工单号给溯源用。三者混用就是氚云的病。

三条本轮新证据支撑的硬约束：

1. **同款重复生产是常态，必须聚合** —— 5150 张规格化任务单压缩成 **2710 个配置键**，其中 **688 组有多张单**（最大一组 99 张：封口机车间 / 手动片膜 / 250 / 一出一）。若按工单造身份，同一件货在库存里会裂成 99 份，业务员永远答不出「有没有货」。
2. **模具/配件天然退化，必须走工单身份** —— 542 张单没有尺寸（模具 430 + 配件 108），其中 **374 张模具单共用一个全空配置键**。它们不是「配置没填」，是**非标工装**：身份在图纸/工单上，不在配置上。
3. **规范化只能统一字形，不能还原语义** —— 尺寸字段三种写法并存（`*` 1244 / 纯数字 1747 / `x` 1004 / 含 `mm` 1616），且 `2014`、`1812`、`2216` 是业务**人脑压掉乘号的写法**（库存名里就写着 `2014气动一出四卷膜`、`1812按钮全自动卷膜`）。任何「智能还原成 20x14」的规则都会**把新数据与历史名脱钩**。

## 1. 证据：配置键能不能当身份？

### 1.1 聚合粒度（`production_orders` 5691 张任务单）

| 键定义 | 组数 | 组内 >1 单的组数 | 最大组单数 |
|---|---|---|---|
| 产线 + 品类 + 尺寸 + 一出N | **2717** | 692 | 374（← 模具，全空配置） |
| 同上 + 形状 + 材质 + 可选配置 | 3709 | 548 | 374（← 同上，说明增列**没有**改善这个退化） |
| 同上，**排除模具/配件** | **2710** | **688** | **99**（手动片膜/250/一出一） |
| 品类 + 尺寸 + 一出N（不含产线） | 2715 | — | 其中仅 **2 组跨产线** |

**读法**：
- 加「形状/材质/可选配置」只把组数从 2717 提到 3709，**最大组一动不动（仍是 374 的张模具）** → 这几列是**属性**，能细分但不能救退化的键，**不该进身份键**（进了会让同一件货因「材质填了/没填」而裂开）。
- 产线近乎冗余（2715 组里只有 2 组跨产线）→ 品类名已隐含产线。但产线**仍要保留**，因为数据范围过滤（车间只看本车间）要用它。

### 1.2 退化边界（哪些单不能用配置键）

| 类别 | 单数 | 配置状态 | 身份从哪来 |
|---|---|---|---|
| 规格化产品（片膜/卷膜/LQ 整机…） | **5150** | 尺寸+一出N 齐 | ✅ 配置键 |
| 模具 | **430** | 尺寸/一出N 全空 | ❌ 走 `MFG-{工单号}` |
| 配件 | **108** | 尺寸/一出N 全空 | ❌ 走 `MFG-{工单号}` |
| 品类为空 | 3 | — | 数据修正项 |

> 模具占氚云完工入库行的 **27.9%**（1,864/6,681）且出库率 57.6% ≈ 成品 56.6% —— **模具也是商品**（`U15-Q2` 已定「进可售库存」）。所以它必须有身份，只是身份不是配置。

### 1.3 写法现状（规范化的靶子）

| 现象 | 实测 | 处理 |
|---|---|---|
| 尺寸乘号 | `*` 1244 / `x` 1004 / `×` 34 | 统一为小写 `x` |
| 尺寸纯数字 | 1747（含 `2014`/`1812`/`2216`/`2617` 这类压掉乘号的双值） | **原样保留**，不还原 |
| 尺寸带单位 | 含 `mm` 1616 | 去 `mm` |
| 含 Φ/φ | 55 | 保留符号，规范为 `Φ` |
| 小数尺寸 | 80 张（如 `203.9x146`），字面命中库存名仅 47.5% | **保留小数**，不取整 |
| 一出N 写法 | 台账用**中文数字**（一出一 2074 / 一出四 1385 / 一出二 614 / 一出六 569 / 一出九 282 …）；ERP JSON 用**阿拉伯数字**（`1出4`） | 建**唯一转换 util**；异常值 1 条 `一出104` |
| 订做前缀 | 库存名含「订做」5390 / 「定做」1717 → 合计 **7107 = 43.6%**，两写法并存 | 统一为 `订做`，作为**标记位**而非名字的一部分 |
| 机型号前缀 | 库存名以 `LQ\d` 开头仅 **675（4.1%）** | 型号只对 LQ 整机有意义（气调机车间 634 单） |

## 2. 身份模型

### 2.1 三个键

```
displayName  = [订做] 品类 [机型号] - 尺寸 一出N [ + 配置缩写… ]
                ↑标记位  ↑来自49项制程品类配置         ↑配方    ↑可选配置
skuKey       = 规范化(品类) | 规范化(尺寸) | 规范化(一出N)        # 内容寻址，唯一
MFG-{工单号}  = 订单产出标识（非标件 / 溯源）
```

**身份键的字段取舍**（由证据决定，不是审美）：

| 字段 | 进不进 skuKey | 理由 |
|---|---|---|
| 产线 | ❌ | 只 2/2715 组跨产线，品类已隐含；进键反而会把同款拆成两条产线 |
| 品类（49 项配置） | ✅ | 制程解析的唯一依据（`§5.2.1`：品类 ≠ SKU，不可互推） |
| 尺寸（规范化） | ✅ | 判别力最强（88.9% 字面命中库存名） |
| 一出N（规范化） | ✅ | 判别力次强（58.7% 与尺寸同时命中） |
| 形状 / 材质 / 可选配置 | ❌（作属性列） | 只把组数从 2717 提到 3709，**救不了退化组**；进键会因「填/不填」裂开同一件货 |
| 电压 / 插头 / 品牌 / 盒子高度 | ❌（作属性列） | 16,319 条库存名里出现 20 / 6 / 1 / 0 次 —— 业务从不靠它们区分 |

### 2.2 显示名拼装顺序（贴着库存名的实际语法）

```
[订做] + 品类 + [机型号] + "-" + 尺寸 + 一出N + ["+" 配置1] + ["+" 配置2] …
     示例：订做 气动卷膜 - 200x138 一出四 + 特氟龙
          LQ310T 台式全自动 - 230x165 一出一 + 易撕口
```

- **订做**：`is_customized` 标记位（43.6% 的存量名带它），不是名字内容的一部分 —— 展示时可加，`skuKey` 里不含。
- **机型号**：仅当品类名里带出型号（`LQ310T台式黑白机` → `LQ310T`）才拼，否则省略。
- **配置缩写**：`optional_configuration` 逐项以 `+` 连接，原样保留措辞（不翻译、不排序去重以外的加工）。

### 2.3 「三出口」落位（对应 `U15-Q1` 的「保留 `MFG-` 但降为仅非标件」）

| 场景 | 身份来源 | 落库 |
|---|---|---|
| 主数据已有对应标准 SKU | `sales_products`（`H3-` 前缀） | `outputs.sales_product_id` |
| 配置键命中（规格化新品） | 自动建档 `skuKey` | 新增 `outputs.sku_key` |
| 非标件（模具/配件）或无配置 | `MFG-{工单号}` | `outputs.sales_product_id`（经 `ensureManufacturingProduct`） |

> 与 `U15-Q1` 的差异：原案是「`H3-` 查不到才用 `MFG-`」，那会把**所有规格化新品**都推进 `MFG-`（因为新品在主数据里当然查不到）→ 仍然是「同款裂 N 份」。**修正为**：规格化新品走**配置键自动建档**（同款即同键，天然聚合），`MFG-` 收缩到**非标工装**（模具/配件）。这才是 `U15-Q1` 想要的「保留机制，去掉缺陷」。

## 3. 与既有决策的关系

| 决策 | 原表述 | 本方案的关系 |
|---|---|---|
| **`#28`**（身份锚定 SKU） | 身份只在两处产生：① 主数据建档 ② 完工入库单绑产出清单 | ✅ **不变量保留**。新增的是①的**自动分支**：配置键命中即自动建档，不再依赖人工选 SKU |
| **`#30`**（建单退出 SKU） | 无 SKU 时身份由 `product_name_snapshot` + `product_config_json` 表达 | ⬆️ **升级**：从「自由文本表达」升为「规范化配置键表达」，`#30` 的「身份退化」不再是退化 |
| **`U15-Q1`**（保留 `MFG-`） | 保留为订单专属产出标识 + `canonical_product_id` 归一到标准 SKU | ⬆️ **收敛口径**：`MFG-` 收缩到非标工装；归一由 `skuKey` 承担（`canonical_product_id` 全表已填充，机制已在） |
| **`U15-Q2`**（模具进可售） | 进 | ✅ 自洽：模具走 `MFG-` 身份，照样进库存 |
| **`#27`**（主轴 = SKU） | 工单接不上 SKU 是唯一硬断，完工入库单是桥 | ✅ **补上桥的另一半**：完工入库行写 `skuKey` → 工单与库存主轴贯通 |
| **`#31`**（制程跟随产线） | 品类 = 工序展开依据 | ⚠️ **不可互推**约束不变：`skuKey` 不参与制程解析 |

## 4. 分阶段落地路线

| 阶段 | 做什么 | 风险 | 依赖 |
|---|---|---|---|
| **P1** | **纯函数 util**：`ProductIdentityKeys.derive(config)` → `(displayName, skuKey)`。含尺寸字形规范化、一出N 中文⇄阿拉伯、非标分支判定。**零依赖、可单测** | 无（不碰库） | — |
| **P2** | **工单落库**：`manufacturing_order_outputs` 加 `sku_key`；建单时生成并写入；抽屉显示名改为生成值（不再让用户打） | 低（只加工单侧列） | P1 |
| **P3** | **完工入库引用 `skuKey`** → 写 `product_inventory_transactions` 首笔业务流水（= 闭环设计 **C** 步） | 中（首次写库存账） | P2 |
| **P4** | **出库从可售库存选** + 落 `sales_outbound_finished_goods_allocations`（= 闭环设计 **D** 步） | 中 | P3 |
| **P5** | **存量对接**：16,319 条历史库存名 → `skuKey` 映射（只读分析 + 映射表），供期初与对账 | 低（只读产出） | P1 |

> P1 是**唯一实现**（铁律：同一业务口径禁两套实现）—— 后端 Java 与任何 SQL 侧都必须调它，不许各写一份 `REPLACE` 链。当前 `sku_agg.sql` 里的 `REPLACE` 链只是**测量用**，不得进入生产路径。

### ✅ P1 已落地（2026-09-23 晚，四项拍板均按推荐）

- **拍板结果**：S1 订做保留并统一写法为「订做」（存量「定做」1717 条并入，不删数据）；S2 身份键 = 可读串 `品类|尺寸|一出N` + 唯一索引；S3 模具/配件一件一身份走 `MFG-{工单号}`；S4 存量 16,319 条只做只读映射表。
- **新增**：`backend/src/main/java/com/liqiang/archive/util/ProductIdentityKeys.java`（唯一实现）+ `ProductIdentityKeysTest`（**19/19 绿**，纯单测零依赖）。
- **真库对拍**（只读 JDBC，5,150 张规格化单逐行过 util）：

| 指标 | Java 实现 | SQL 测量口径 | 差异解释 |
|---|---|---|---|
| 有效 skuKey 行 | 5,148 | 5,150 | 2 张漏尺寸单被非标分支兜走 → MFG-（正确） |
| 不同键组数 | **2,707** | 2,715 | Java 多归并 8 组（`70mm`/`70 mm`/`70` 这类字形变体），收敛方向正确 |
| 组内 >1 单 | 689 组 | 688 组 | 同上 |
| 最大组 | **104 单** | 104 | 完全一致（封口机/手动片膜/250/一出一，含跨产线归并） |

- **对拍暴露并已修的真实边界**（都进了单测钉死）：
  1. 大写 `Φ` 落 else 分支被小写化 → φ/Φ 统一归 `Φ`；
  2. 一出N 头部原先只认「一/1」，但 ERP JSON 真实存在 **`2出1`**（MO00008768）→ 改为**两侧都按数字解析**（`2出1`→`二出一`，`12出12`→`十二出十二`，`一出104`→`一出一百零四`）；
  3. 尺寸里数字后的逗号是分隔符噪声（`46,mm`/`φ90，φ80`/`2014x2,光板透明`）→ 剥离；多段尺寸每段带 mm（`86mm75mm`）→ 逐段剥（结果 `8675`，与业务「压掉乘号」的人脑约定一致）。
  4. 可选配置的真分隔符是 **`;`/`；`**（1,003 条），不是 `+` —— ERP JSON 本就逐项无需拆；探针拆分时两种都要认。
- **遗留未修（个位数垃圾行，不为其做特殊逻辑）**：尺寸是自由文本灾难的单（如「按照450机型做，2014；2216；90；95；70；120下磨具拼盘」「第一种尺寸：内径5.6厘米…」）共约 6 行 —— 规范化后键为长文本但确定性不变，唯一索引照常生效。

## 附：本轮探针方式与可复算口径

- 全部数字用 `mysql` CLI 只读复算（SQL 见 `.workbuddy/tmp/20260923/sku_agg.sql`），**零写库**。
- 尺寸规范化口径（测量用，**生产实现见 P1 util**）：
  `LOWER(TRIM(x))` → 去 `mm` → 去空格 → `*`/`×` → `x`。
- 「命中」定义：库存名包含规范化后的尺寸串。
- ⚠️ 库存名条数本轮实测 **16,319**（上午报告为 16,019，差 300 条 —— 期间台账被重新导入过），引用时以最新为准。

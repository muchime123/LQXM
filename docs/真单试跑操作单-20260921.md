## 参与人

| 角色 | 人 | 干什么 |
|---|---|---|
| 建单 + 收货 | 于洋洋（ADMIN） | 建工单、办交付收货 |
| 车间报工 | 胡健 或 陈苏平（生产跟单） | 按工序报实际完成量 |
| 兜底 | 阿简 | 页面报错、权限补配、数据核查 |

**权限码对照**（页面提示无权限时补给对应角色）：
- `manufacturing.report` 报工 —— 生产跟单
- `manufacturing.receive` 交付收货 —— 仓库/于洋洋
- `manufacturing.report.override` 超额报工 —— 先不给，遇到再说
- `manufacturing.receive.reverse` 冲销入库 —— 只给仓库负责人

## 第一幕：建单（于洋洋，约 5 分钟）

1. **氚云数据管理 → 车间执行 → 右上角「新建工单」**（需 `manufacturing.manage` 权限；09-21 下午已补上该入口——此前建单只能调接口，页面没有按钮）。
2. 填真实客户、真实产品、数量、单位；任务类型按实际选（打样 / 销售排产 / 返工替换 / 返工 / 内部领用 / 特殊定制）。
3. **选生产车间即可**——系统按车间默认制程自动展开工序；车间没有默认制程时会要求手动指定制程模板。
4. 建完检查：执行看板出现该单的待开工工序，状态为「待报工」。
5. ⚠️ 提交失败就**原地重试**——失败时请求键自动复用，不会重复建单；不要另开页面再填一次。

## 第二幕：车间报工（胡健 / 陈苏平，随实际进度，1~3 天）

1. 车间执行 → 执行看板 → 找到本单 → 点「报工」。
2. 填**实际完成的数量**。第一单建议故意只报一半，制造「部分完成」状态，验证看板数量、仓库看到的待收量是否一致。
3. 报工人要带回来的答案（口头问就行）：
   - **Q1 口径**：你们平时跟车间要数，是按「这道工序做了多少」报，还是按「今天/这一班总共做了多少」报？**如果答案是后者，页面要改，这条最重要。**
   - **Q2 返工**：做坏了怎么处理？页面上的「冲销报工」够不够用？
4. 报错了就原地重试；数量报多了找于洋洋冲销。

## 第三幕：仓库收货（于洋洋或仓库负责人）

1. 车间执行 → 交付收货 → 本单出现在待收列表 → 选仓库、填实收数量。
2. 建议故意**分两次收**（2 台以上的单先收 1 台）→ 看状态变「部分收货」→ 再收剩余。
3. 带回来的答案：**Q3** 仓库实际是一次收完还是分批？习惯按什么节点收（每台一收 / 攒一批 / 按天）？
4. 注意：现在**超量收货会被直接拒绝**——如果这和仓库习惯冲突，记下来，别硬试。

## 第四幕：冲销演练（10 分钟，强烈建议）

1. 故意「收错了」：冲销入库，填真实原因（如「重复收货」）。
2. 确认：冲销后订单状态、已收数量、库存全部正确回退。
3. 冲销同样支持原地重试。

## 试跑成功的标准

- 全程**没有人需要来找阿简改数据库**；所有报错都能通过页面重试或冲销解决。
- 每个动作在 `erp.idem_request` 恰好一行、每次变更在 `erp.row_change_log` 恰好一行（跑完我来查，不需要参与者关心）。
- Q1（报工口径）、Q2（返工处理）、Q3（收货习惯）三个问题带回明确答案。

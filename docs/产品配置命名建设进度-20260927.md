# 产品配置与命名：首阶段建设

## 已实现

- 现有任务单产品与配置增加稳定代码；产品与选配继续引用原有记录 ID。
- 产品命名规则支持草稿、修订号校验、发布、历史版本；发布时冻结名称与选配标签。
- 在 `/manufacturing-task-configs` 产品行点击“配置规则”，维护产品类型、必填字段、选配分组、进入名称的技术选配和互斥组。
- 规则保存后可用样例试算，再发布。机器、模具和配件使用各自适用字段。
- 销售订单的自产配置与独立生产任务单共用现有抽屉；有发布规则时，展示统一后端名称预览、缺项与待确认说明。
- 保存订单或工单时，后端重算配置、规格及名称快照，记录基础产品 ID 和规则版本，不信任客户端预览文本。
- 未发布规则的产品保持原有流程。未批量修改历史订单、工单与库存名称。

## 启用顺序

1. 从全自动气调机选一个实际产品，在“配置规则”核对必填字段。
2. 将配置项分组，明确哪些影响名称，哪些仅进入规格；同类替代项填写相同互斥组。
3. 保存草稿，填写真实配置试算名称、规格和待确认说明。
4. 发布后分别在销售订单和独立生产任务单验证同一配置。

未分类选配、异形、额外模具及其他配置说明会提示人工确认。该提示不是质检结论。

## 本阶段边界

名称预览不建立库存产品身份，不以名称或“品类＋尺寸＋一出N”作为唯一键。正式入库产品身份确认、旧库存别名归并、历史产品逐条治理属于后续阶段。

## 验证

命名和业务服务测试覆盖尺寸规范、技术选配与包装区分、互斥冲突、缺项与待确认区分、配件残留字段清理、冻结标签、草稿并发修订保护和跨产线拒绝。

浏览器回归覆盖独立建单、自动制程、旧路由跳转、销售配置不提前建工单、发布规则版本写入销售明细。V347 已通过本地 Flyway 实际迁移与启动验证。

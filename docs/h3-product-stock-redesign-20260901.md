# 氚云产品信息与仓库明细重构建议

分析日期：2026-09-01。来源为2026-08-31导出的“产品信息”和“仓库明细”Excel、当前数据库只读统计。原Excel和业务数据均未修改。

## 结论

不应继续要求15131条氚云产品逐条映射到 `product_models/product_variants`、包材规格或模具档案。

氚云产品明细是企业实际交易SKU，包含大量定制机器、客户定制膜、盒、模具和一次性费用；现有产品中心则更接近标准产品、结构化规格和官网资料。两者颗粒度不同。正确结构是：

```text
标准产品档案（产品中心，可选关联）
          ↑
      SKU档案关联
          ↑
销售产品/交易SKU（sales_products，销售和库存共同引用）
          ↑
氚云产品来源记录（保留外部子ID、原编号、原名称、规格、单位）
          ↑
仓库快照候选 → 期初库存批次 → 库存余额/流水
```

导入氚云SKU不以关联标准产品档案为前置条件。标准档案关联只服务产品分析、配置复用和官网，不决定库存身份。

## 实测数据

### 产品信息

- 63个父级产品类目，15131条唯一子记录ID。
- 15105个非空产品编号；4条编号为空；22个编号出现重复，说明产品编号不能单独充当绝对唯一身份。
- 14316条“上架”，815条“下架”。
- 4088条规格为空，28条单位为空，10条名称为空。
- 常见单位：台7149、kg3577、个1583、箱1171、套716、只430。另有 `Kg`、`公斤`、`台·`、`箱··` 等需规范化或核查的单位。
- 类目并不是标准产品型号。大类包括耀星1798、定做膜1590、模具1416、气动1332、定做气动1032等，明显混合标准品、定制品、客户专用品、材料和费用。

### 仓库明细

- 16204条快照记录，14825个不同产品编号。
- 三个仓库：温州仓13491行、代发仓1734行、安徽仓979行。
- 1751条正数、14415条零、38条负数；38条负数中32条是绝对值小于0.000001的浮点残差，实际异常为6条（5条-1、1条-3）。残差可在确认规则后归零，6条实质负库存必须人工核查。
- 1643个产品编号存在非零库存。
- `产品名称（隐）`只是产品名称副本，不是氚云产品子记录ID；不能靠隐藏字段建立稳定外键。

### 两份Excel的关联

- 15452/16204条仓库记录可按“产品编号＋名称＋规格＋单位”唯一精确对应产品来源记录，占95.36%。
- 其余包括：名称差异51条、规格差异268条、单位差异120条、多条完全相同候选4条、产品导出中找不到编号309条。
- 只看非零库存1789行，1753行可唯一精确对应；剩余36行才是首轮真正需要处理的异常，不需要人工核对15131行。
- 非零库存中有16行产品编号为空或未出现在产品导出中。
- 按“仓库＋产品编号＋单位”发现82个重复余额键，共168行；61个键其实对应不同名称或规格，进一步证明编号不能单独决定SKU。12个重复键至少一行非零，只有2个键有多行同时非零。不能按编号盲目合计。

### 当前数据库

- 已有3988条 `sales_products`，全部来自销售出库聚合；3956条待审核，32条启用。
- 产品Excel的15105个编号中，3979个编号已存在于 `sales_products`；3949条能进一步按编号、名称、规格、单位完全一致。
- 178494条销售出库产品明细包含12731个不同编号，但178491条仍未写入 `sales_product_id`，即现有销售产品主数据基本没有真正关联回历史出库。

## 推荐数据库设计

### 1. 继续使用 sales_products 作为交易SKU主表

它已经被销售出库、成本快照和利润模块引用，也在V128中明确预留 `H3YUN_PRODUCT_IMPORT`，没有必要再造一张竞争主表。

建议明确字段语义：

- `id`：系统SKU身份，销售和库存只存这个ID。
- `product_code`：系统显示编号，保持唯一；不要假设它永远等于氚云编号。
- `product_name/specification/unit/category`：当前确认后的交易信息。
- `status`：PENDING_REVIEW/ACTIVE/DISCONTINUED。

### 2. 新增 sales_product_source_aliases

保存外部来源身份和原始快照：

```text
id
sales_product_id             可空，待解析时为空
source_system                H3YUN
external_id                  氚云产品明细子ID，来源内唯一
source_product_code          原产品编号，允许重复
source_name
source_specification
source_unit
source_category
source_status
source_hash
resolution_status            AUTO_LINKED / REVIEW / IGNORED
created_at / last_seen_at
```

唯一约束用 `(source_system, external_id)`，普通索引用 `(source_system, source_product_code)`。这样22个重复编号不会被错误合并，也不需要破坏 `sales_products.product_code` 当前唯一约束。

如果一个氚云编号唯一且没有占用，可继续把它作为系统 `product_code`；如果编号重复或为空，系统生成稳定编号，例如 `H3-{external_id短码}`，原编号仍完整保存在来源表。

### 3. 标准产品档案采用可选关联

新增 `sales_product_catalog_links`，将交易SKU可选关联机器规格、包材规格或模具。一个标准机型可以对应很多客户定制SKU。这个关系不是导入产品或记库存的前置条件。

不要再把 `product_variants`、`packaging_variants`、`packaging_molds` 直接作为统一库存SKU，因为三个表的身份体系不同，而且大量定制交易记录没有合理的一一对应目标。

### 4. 仓库快照先进入期初批次

建议增加：

```text
inventory_opening_batches
  id, snapshot_at, source_file_hash, status, confirmed_by, posted_at

inventory_opening_items
  batch_id, source_stock_id, warehouse_id, sales_product_id,
  source_code/name/spec/unit, raw_quantity, normalized_quantity,
  resolution_status, issue_code, version
```

只有已解析 `warehouse_id + sales_product_id + unit`、数量有效且重复余额问题已解决的项目才能过账。过账后统一生成 `OPENING_BALANCE` 库存流水和余额，原Excel数量永久保留为来源证据。

## 自动处理规则

1. 先按氚云产品子ID幂等写入来源别名表，不创建库存。
2. 与已有 `sales_products` 按“编号＋名称＋规格＋单位”完全一致时自动关联；只有编号相同但其余字段不同的，进入审核。
3. 未关联但来源编号唯一、字段完整的产品，自动创建 `PENDING_REVIEW` 交易SKU并关联来源记录。
4. 编号重复、编号为空、名称/单位缺失的记录进入产品异常队列；不要因异常阻塞其他正常产品。
5. 仓库快照按同样的完整签名关联来源SKU。非零库存1753行可直接形成自动关联候选，剩余36行优先人工处理。
6. 零库存14415行不进入首轮期初过账；保留来源记录即可。这样首轮人工范围从15131条降为几十条。
7. `kg/Kg/公斤`等单位先建立规范单位与原始别名；只有语义确定的大小写/同义词才能自动规范。箱、只、个之间没有换算配置时禁止转换。
8. 浮点残差32条单独标记 `FLOAT_RESIDUE`，经统一阈值规则确认后归零；6条实质负库存进入异常审核。
9. 82个重复余额键不能按编号直接合计。先解析到SKU：不同名称/规格分别保留；同SKU同仓同单位的多条记录才进入“是否重复还是应合计”的人工确认。

## 建设顺序

### 第一阶段：SKU来源注册与自动解析

- 新增来源别名表和导入预览。
- 自动对齐现有3988条 `sales_products`。
- 对字段完整且无冲突的氚云产品批量创建待审核SKU。
- 修复出库关联逻辑，使用来源解析结果回填 `sales_outbound_items.sales_product_id`，不再只按编号假定唯一。

### 第二阶段：非零期初库存

- 三个仓库映射到正式仓库ID。
- 只处理1789条非零库存行；自动候选1753行，人工异常约36行，再叠加重复余额和6条实质负数复核。
- 生成期初预览和按仓库/类目/单位的对账结果，由用户一次确认后过账。

### 第三阶段：标准档案关联和数据治理

- 根据实际复用价值，把交易SKU批量关联标准机器、包材和模具档案。
- 处理下架产品、重复编号、单位别名和历史无来源产品。
- 这一阶段不阻塞销售和库存上线。

# ERP 单据字段、状态与业务影响契约

版本：v0.1 · 2026-09-17；工作包 2 设计草案。

上游：[建设前蓝图](ERP建设前业务蓝图-20260917.md)、[主数据字典](ERP主数据字段与约束字典-20260917.md)。本文定义标准商品采购、销售、库存与收付款的业务契约，不是已实现接口或获批核算政策。氚云数据只作场景与验证依据，不驱动未来 ERP 正式单据。

## 1. 范围与假设

本工作包覆盖采购订单、收货入库、采购退货、销售订单、销售出库、销售退货、调拨、盘点调整、收付款、退款、往来项目与核销。生产与实际开票保留接入约定，详细字段属于后续复杂业务工作包。

为了让案例可计算，**沙箱建议配置 S0** 为：单一公司、同币种、标准商品、固定单位换算、零超量容差、禁止负库存、人工明确确认往来项目、订单不自动占用库存。以上只是测试前提，D01/D04/D05/D06/D08 未确认前不得作为生产默认政策发布。本文金额公式描述业务子账，不作财务会计确认或税务规则结论。

## 2. 单据共同字段

类型为逻辑类型，长度与物理精度沿用主数据字典候选值，后续技术设计确定。C=草稿创建必填，S=提交必填，P=过账必填。

| 字段 | 类型/时点 | 规则 |
|---|---|---|
| id / lineId | 稳定 ID，系统 | 单据与行独立身份；行号不是跨单关联键 |
| documentType / documentNo | 枚举/字符串，系统 | 单号唯一范围建议公司+类型+单号；作废不复用 |
| companyId | ID，C | 业务主体；有下游后不可变更 |
| businessDate / occurredAt / postedAt | 日期/时间 | 业务日期 S；实际发生时间 P；过账时间系统记录，不混作一个日期 |
| approvalStatus / postingStatus | 枚举，系统 | 审批与记账分别表达，见第 3 节 |
| revision / version | 整数，系统 | revision 表示业务修订，version 防并发覆盖 |
| partyId / companyRoleId | ID，往来类 S | 校验本公司客户或供应商角色；不凭名称确定身份 |
| currency / pricingBasis | 币种/含税或未税标识，金额类 S | 同单统一币种和明确价格基数 |
| ruleVersion | 版本引用，P | 固定计量、金额和记账政策版本 |
| sourceReferences | 来源单据行关系，条件 S | 保存来源行 ID、数量/金额，不能只保存来源单号文本 |
| ownerEmployeeId / departmentId | ID，按职责 S | 权限与业务归属分别校验；保存发生时快照 |
| remark / reasonCode / evidenceRefs | 文本/原因/附件引用 | 退货、调整、冲销、关闭须原因；附件不代替结构字段 |
| createdBy / approvedBy / postedBy 等 | 审计字段，系统 | 操作记录含前后状态、时间、操作者和请求键 |

### 2.1 商品明细公共字段

| 字段 | 必填时点 | 约束 |
|---|---|---|
| skuId、skuCodeSnapshot、nameSnapshot、specSnapshot | SKU 在 S，快照在确认修订时固定 | 主档改名不能改变已确认单据 |
| configurationRevision | 定制类 S | 引用锁定配置，不能只写自由备注 |
| quantity、unitId | S | 业务输入数量为正；退货方向由单据类型表示 |
| baseUnitId、conversionRevision、conversionNumerator/Denominator、baseQuantity | P | 比率与数量同时存；无换算时阻断；不默认单位为“个” |
| unitPrice、discountAmount、netAmount、taxAmount、grossAmount | 金额类 S/P | 明确计价单位；净额+税额=含税额，折扣不能重复扣除 |
| warehouseId、locationId、qualityStatus、lotId/serialRefs | 库存类 P | 后三项按启用范围；仓库管理主体与货权主体独立 |

单价、折扣、税额、尾差的计算顺序由金额规则版本决定。请求传入金额与服务端计算不一致时返回差异，不能静默改价。非库存服务行允许没有库存维度，但仍需正确金额和来源关系。

## 3. 状态、修订与动作

### 3.1 状态维度

| 维度 | 状态 | 含义 |
|---|---|---|
| approvalStatus | DRAFT / SUBMITTED / APPROVED / CANCELLED | 驳回回 DRAFT 并记录原因；取消只针对未产生业务影响的修订 |
| postingStatus | UNPOSTED / POSTED | 订单不使用此维度产生库存事件；影响型单据使用 |
| executionProgress | NONE / PARTIAL / COMPLETE | 从有效执行分配量派生，不手工维护 |
| closureStatus | OPEN / CLOSED | 关闭剩余履约与执行进度分开，不伪装全部交货 |
| reversalProgress | NONE / PARTIAL / FULL | 原单始终保留 POSTED，通过有效反向事件计算净影响 |

### 3.2 动作契约

| 动作 | 允许来源 | 业务效果 | 拒绝条件 |
|---|---|---|---|
| 保存/提交 | DRAFT | 保存修订或进入 SUBMITTED | 旧 version、缺提交字段、无权限 |
| 驳回/撤回 | SUBMITTED | 回 DRAFT，审计留痕 | 已审核；并发状态已变 |
| 审核 | SUBMITTED | 固定该修订快照 | 主档/公司关系不可用、来源不足、权限不符 |
| 过账 | APPROVED+UNPOSTED | 原子写业务事件、执行量、余额及单据状态 | 任何金额/数量/期间/权限校验失败 |
| 撤销审核 | APPROVED+UNPOSTED | 回 DRAFT | 有下游引用、占用等影响未解除 |
| 修订订单 | 已审核订单 | 新修订，旧版留存；已执行部分不可改写 | 新承诺量小于已执行量、变更已履约身份/主体 |
| 关闭剩余 | 已审核未关闭订单 | 关闭未执行数量；保留部分履约事实 | 有在途/待过账分配冲突未处理 |
| 冲销 | POSTED | 新建关联原事件的反向单据并独立过账 | 超可冲数量/金额、下游依赖未解除 |

审核和过账可按 D08 合并为用户操作，但事务内仍分别校验。冲销用于纠错，真实退货用于反向业务，两者不能互相冒充。已交付或已消耗的库存不能通过直接冲销原入库凭空变负。

## 4. 采购与销售订单

| 单据 | 专有字段 | 审核约束 | 执行关系 |
|---|---|---|---|
| 采购订单 | supplierRoleId、预计到货日、收货地点、条款快照 | 供应商角色可用；价格/币种/单位明确 | 订单行→多次收货/入库行 |
| 销售订单 | customerRoleId、交期、收货信息快照、业务员、条款快照 | 客户角色可用；交付信息按业务完整 | 订单行→多次出库行 |

每条来源执行分配包含 allocationId、sourceLineId、targetLineId、baseQuantity、状态和反向引用。分配的主体、SKU、配置和基本单位必须一致。不同订单可合并到一张交付单，但不能把不同订单单价混成一个无来源金额。

S0 履约口径：

- 累计执行 E = 有效正向执行量减纠错冲销量；真实退货另记 R，不自动恢复可交量。
- 剩余可执行 = 当前承诺量 Q − E − 已关闭量 C；并发待提交分配必须受锁或预留额度保护。
- 可再次退货 = 已实际交付量 − 已过账退货量 − 正在占用退货额度的确认请求量。
- 退货后需要补发/补购时，通过明确补发单或订单修订建立额度；不默认“退 1 个就自动能再发 1 个”。该政策正式使用前需业务确认。

订单本身不产生现存变化；占用何时产生由 D04 决定。若启用占用，需 reservationId、库存维度、占用量、来源行、有效状态；出库时扣现存并释放相应占用一次，关闭/取消释放剩余占用。

## 5. 收货、出库与退货

### 5.1 采购入库

字段：采购来源行及分配量、到货实收数量、货权公司、仓库/库位、质量状态、供应商送货参考号、检验结果引用、数量与价格快照。

待检场景建议：实收过账时进入待检库存；检验放行通过质量转移事件“待检减少、可用增加”，不重复入库。无需检验时直接进入可用库存。若业务选择验收前只登记实物，则必须有明确的收货暂存对象与统一截点，不能两种方案同时增加现存（D04）。

### 5.2 销售出库

字段：销售来源行及分配量、实际拣货库存维度、发货数量、货权公司、收货信息快照、承运信息、实际发货时间。过账校验可发数量；若消耗本订单占用，应允许使用自己的占用，禁止占用在可用计算中被重复扣减。

库存减少与履约增加一次提交。发货不自动代表签收，不自动确认收款；应收触发点由 D06 决定。

### 5.3 退货

| 单据 | 关键字段 | 影响 |
|---|---|---|
| 销售退货 | 原出库行、退货量、原因、退回仓、质量状态、拟抵扣金额 | 实际接收后增加指定质量状态库存；待检不能直接可售 |
| 采购退货 | 原入库行、退货量、原因、出库维度、拟抵扣金额 | 减少有足够现存的对应库存；不能退超实际可退量 |

退货数量与抵扣金额分别校验，原价退还是协商价退须业务规则。只有正式确认的往来调整才改变未结金额；退货单不自动生成已经退款的资金事实。换货拆为退回与补发两条关联业务，不能用正负明细相抵隐藏实物流向。

## 6. 库存事件、调拨和盘点

### 6.1 事件字段与守恒

字段：eventId、postingGroupId、sourceDocumentId/sourceLineId、eventType、ownerCompanyId、warehouseId/locationId、skuId、baseUnitId、qualityStatus、lotId/serialRefs、signedBaseQuantity、occurredAt、postedAt、ruleVersion、reversesEventId。

库存余额键包含货权、地点、产品、基本单位及已启用的质量/批次/序列维度。不把展示名拼接为身份键。事件不可原位编辑；纠错生成反向事件。价格与价值另有成本事件/规则引用，不能以主档最新采购价回算全部历史。

单据行可产生多腿事件，因此去重键应包含单据、行、动作和事件腿身份，不能简单限定一行只能有一个事件。

### 6.2 调拨

调拨申请包含调出/调入仓、货权公司、产品明细、计划量。调出与调入分别有执行单，保存原调拨行及实发/实收量。

- 发出：调出现场 −Q，在途 +Q，同一事务。
- 收货：在途 −R，调入现场 +R，同一事务；累计接收不得超过实际在途额度。
- 在途不是任一现场可用库存；总货权数量的守恒检查同时包含现场和在途，不能遗漏或重复计算。
- 短收先保留在途，确认丢失后通过差异单减少；不能关单时自动清零。多收需明确来源或差异处理。
- 跨货权公司调拨不按普通仓间移动处理，需另定义公司间交易或货权转换流程。

### 6.3 盘点及其他调整

盘点字段：范围、账面截点、账面数量快照、实盘时间/数量、盘点人、复核人、差异原因、调整行。并发业务须选择冻结范围盘点或按事件截点回推两种机制之一；S0 使用冻结盘点范围的方案。

差异量 = 同一截点实盘量 − 账面量。审核只确认差异；过账才改变库存，且只能一次。盘点期间发生未覆盖事件时拒绝按旧快照直接调整。其他入出库必须结构化原因和依据，不接受“其他”作为绕过采购、销售、领料权限的通道。

## 7. 往来、资金、核销与退款

### 7.1 独立对象

| 对象 | 必要字段 | 作用 |
|---|---|---|
| 往来项目 | itemId、companyId、partyId、AR/AP、currency、sourceEventRef、originalAmount、dueDate、ruleVersion | 表达一笔可结算债权/债务，不是资金收付 |
| 往来调整 | adjustmentId、itemId、signedAmount、reason、sourceReturnRef | 改变项目有效应结额，保留原额 |
| 收款/付款单 | fundId、direction、companyId、partyId、currency、amount、accountId、method、occurredAt、evidenceRef | 确认一次实际资金发生，可先形成未分配余额 |
| 核销分配 | allocationId、fundId、itemId、amount、status、reversalRef | 一款多单/一单多款；不生成第二笔收付款 |
| 退款单 | refundId、originalFundId、companyId、partyId、currency、amount、reason、returnRef、evidenceRef | 对原收付的反向资金事实；不是删除原单 |

**资金来源幂等（2026-09-21 收口）**：`fundId` 是资金事件的**独立身份**，不靠业务字段拼接。
外部来源另有各自的去重键，与资金身份分离：

| 来源 | 来源幂等键 | 缺失时处理 |
|---|---|---|
| 银行流水（Excel / API） | 账户 `account_no` + **银行稳定交易号** | 逐条保留，不按金额日期合并，进冲突复核队列 |
| 流水日记账（人工记账） | 账户 + 台账行身份 | 同上 |
| 业务侧（销售出库收款、发票收款） | 不做独立资金记录，只作往来关联 | — |

⚠️ **`主体 + 账户 + 日期 + 金额 + 方向 (+对方)` 只能作为候选匹配条件**，用于提示"疑似同一笔"，
**不得作为唯一身份或自动合并依据**：同一天向同一对象发生两笔同金额收付款完全可能。
「同一笔钱出现在 4 个地方」的处理方式是**一条资金事实 + 多条证据引用**，
而证据之间的关联由人工/规则复核确认，不由弱键自动判定。

**三层信息分离**（违反会造成 API 同步覆盖人工标注，属不可逆数据损坏）：

| 层 | 内容 | 可否被外部同步覆盖 |
|---|---|---|
| 来源事实 | 账户、账号、日期、金额、方向、余额 | 可 |
| 人工标注 | 供应商/客户/报销人/是否开票（来自流水日记账） | **不可** |
| 业务分配 | 核销到哪张应收/应付单 | 不可（业务事实） |

收款用于应收、付款用于应付；供应商退款和客户退款通过原资金单关联。退款不进入普通核销资金池。跨公司、跨往来方、跨币种分配在 S0 下拒绝；未来有需求需明确汇兑/代付/内部结算规则，不能放宽一个校验就上线。

### 7.2 金额约束

对一笔原资金单：确认金额 F，生效退款 R，有效核销 A，正在处理退款的保留额度 H。

`可分配或可申请退款额度 = F − R − A − H`，所有量同币种，结果不得负。

对往来项目：原额 O，有效调整 Δ，有效核销 S。

`未结金额 = O + Δ − S`，S0 **不允许未结负数**；超额形成独立预收/预付或待分配款，**不压成负应收**。

> ✅ **2026-09-21 LQ 拍板**：确认采用上面这条（独立待分配款），
> 否决「用负欠款表达预收」的替代方案。理由：负欠款会让 `未结金额 ≥ 0` 这条不变量失效，
> 核销与退款校验要处处特判负值；而 §7.1 收款单本就允许「先形成未分配余额」，
> 多收沉淀为待分配款与本节自洽，代价仅为给 0.6% 的场景（实测 NEG 93 笔 + 超额收款 26 笔）多一个池子。

- 核销确认同时校验资金剩余额度与项目未结额，锁定两侧后原子提交。
- 取消核销保留反向记录，释放两侧额度，不改变资金 F。
- 已核销款退款前先解核销，且按真实业务确认退货抵扣等调整；不能因退款就自动减少应收。
- 减少往来金额的调整若使已核销超过新应结额，必须在同一受控流程中释放超额核销或拒绝调整。
- 退款申请占 H，取消申请释放 H；退款确认把 H 转为 R，不能两者同时扣同一金额。请求失败重试使用同一业务身份。

### 7.3 完整退款算例（合成）

原应收 1,000，已收并核销 1,000。现退货认可抵扣 200：先解核销 200（A/S 变 800），再确认应收调整 −200（应结 800、未结 0），最后退款 200（F=1,000，R=200，A=800，未分配=0）。实物退回单独增加退货库存；任何一步不得隐式重复资金或库存。

### 7.4 D06 核算触发策略

生产前必须为每类往来项目确定唯一产生事件：订单确认、交付、验收或其他获批节点。项目唯一来源键包含政策版本和源事件，策略切换必须有接续方案，不能新旧节点同时生成全额往来。S0 仅使用明确的人工确认动作来验证分配，不声称该动作是实际财务政策。

**预收预付已定（2026-09-21）**：多收/预付走独立未分配余额，不压成负应收，见 §7.2。
**仍未定**：应收/应付触发节点（待决清单 ④.1 推荐"发货即应收"，尚未正式拍板）、退款方式与"抹零"性质（收款差异还是折扣，影响核销能否结平）、跨币种结算。
**不受金额政策阻塞的部分**：制造数量链（工单→领退料→报工→完工入库→销售出库）不依赖上述任一项，可先行建设。

## 8. 原子性、幂等、权限与失败语义

| 动作 | 一起提交的内容 | 失败时要求 |
|---|---|---|
| 入库/出库 | 单据过账状态、事件、余额、来源执行量、相关占用 | 全部回滚，不留下“单据成功但库存没变” |
| 调拨发出/收货 | 同次移动两腿、在途余额、累计执行量 | 任一腿失败整次失败 |
| 核销/解核销 | 分配记录、两侧已分配结果、审计 | 不允许只释放一侧 |
| 退款确认 | 退款事实、额度保留转释放、原单退款汇总 | 资金事实与额度不得脱节 |

调用键建议为公司+动作+requestId，并记录请求内容摘要：同键同内容返回原结果；同键不同内容返回冲突。另以原单行/动作业务唯一键防止换请求键重复过账。超时后提供按请求键查询结果的能力，不让用户猜是否成功。

**M0 收口后的具体契约（2026-09-21 已实现并有真库证据）**：

| 项 | 契约 |
|---|---|
| 请求键 | **必填**。缺键不得直通执行业务，也**不存在"无键跳过事务"的分支**（否则调用方依赖事务保护时会被静默降级） |
| 动作 | **必填**，并与请求键、载荷摘要一起参与命中判定。同键换动作 = 冲突，不允许用旧键取回旧动作的结果 |
| 操作人 | **必填**（`ErpActor`），写入 `idem_request.created_by`；缺操作人在读库/开事务之前即被拒绝 |
| 大小写 | 请求键比较显式大小写敏感，不依赖库默认排序规则 |
| 重放 | 回放首次 `result_ref`，**不重复执行业务体**；重放**不替代授权**——调用方必须在返回前完成身份与数据范围校验。换人重放记 warn 日志但不拒绝（是否放行属授权策略，不是幂等语义） |
| 失败 | 业务失败 → 请求键与业务写入一并回滚（可安全重试）；并发同键 → 失败方整笔回滚，调用方按键查询结果 |
| 边界 | 只覆盖同一 ERP 事务内可回滚的写入。远程支付等不可回滚的外部副作用必须走「待处理 + 外部唯一号 + 对账恢复」，不能声称被本事务覆盖 |

业务守恒检查在事务内执行，行锁或等效并发控制保护累计额度；版本号不能单独替代跨单据额度保护。若以后接入真实支付或外部服务，采用待处理状态、外部唯一号和对账恢复，不能宣称数据库事务覆盖外部付款。

权限分别校验查看、创建、审核、过账、冲销、退款、关闭及数据范围。知晓 ID 不意味着可以操作；所有关联对象均校验主体和权限。审批人是否可兼任制单人、期间关闭后如何更正由 D08 决定。已关闭期间不得通过随意改 businessDate 绕过限制。

建议错误码：INVALID_STATE、STALE_VERSION、SOURCE_QUANTITY_EXCEEDED、INSUFFICIENT_AVAILABLE_STOCK、UNIT_CONVERSION_MISSING、ALLOCATION_EXCEEDED、REFUND_EXCEEDED、DOWNSTREAM_DEPENDENCY、PERIOD_CLOSED、IDEMPOTENCY_PAYLOAD_CONFLICT。错误附字段/行定位和可修正原因，不返回无权限对象详情。

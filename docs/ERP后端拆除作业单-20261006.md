## 1. 一句话结论

后端不是「残留清理」，而是**一次功能拆除**：要拆的是自建 ERP 的整条业务链（销售订单 → 履约评审 → 生产需求 → 生产任务单 → 报工/检验/完工 → 出库 → 采购 → 审批），
涉及 **12 个 Controller、13 个 Service、1 个 1344 行类的裁剪、约 33 个后端测试、25+ 张表**。

**并且它不能按「前端零调用」直接删** —— 有 **4 个咬合点**：保留的「制程/任务单配置」页依赖 ERP 基础设施包；客户档案的快速建档依赖订单权限码。
这 4 处必须先改造，否则会连带编译失败或拆坏保留功能。

## 3. 咬合点（拆之前必须先改造这 4 处）

### ① `ManufacturingTaskConfigController` 依赖 ERP 基础设施
它注入 `erp/ErpChangeLogWriter` + `erp/ErpActorResolver`，写车间 / 任务配置时记 ERP 审计。
→ **结论：`erp/` 包 8 个类必须保留**（至少 `ErpActor`、`ErpActorResolver`、`ErpChangeLogWriter`）。
→ 连带：`erp_change_logs` 表**不能删**（还在被写），只是操作日志页不再有查看入口。这是「删 UI 但保留写入」的现状，需你知情。

### ② `CustomerController` 依赖订单权限码
`CustomerController:107` 是 `@RequirePermission({"customer.manage", "sales_order.manage"})`（客户快速建档）。
→ 若删 `sales_order.manage`，必须先把这里改成只认 `customer.manage`，否则**客户档案快速建档直接 403**。

### ③ `ManufacturingService` 深依赖 ERP 组件
它注入 `ManufacturingExecutionService`、`ErpApprovalService`、`SalesOrderExceptionService`、`ErpChangeLogWriter`、`ErpIdempotencyService`、`ErpActorResolver`。
→ 裁剪时这些字段要一并摘掉（`ManufacturingExecutionService` / `ErpApprovalService` / `SalesOrderExceptionService` 整体删除，其余保留为基础设施）。

### ④ 客户档案的订单利润
`api/salesOutbound/orderProfit.ts` → `/sales-outbound-profits` 被 `CustomerDetailPanel` 使用。
→ **`SalesOutboundProfitController` 与 `sales_outbound_profits` 表保留**（不在拆除范围）。
→ 若你本意是把这块也去掉，请明说 —— 那要连客户档案的这个卡片一起下线。

# 生产任务配置驱动产品身份与出入库实施契约

> 2026-09-24。本文修正《SKU重设计-任务单配置锚定身份-20260923.md》中“品类＋尺寸＋一出N 足以唯一识别产品”和“其他结构化配置一律不进身份键”的结论。历史分组统计仍可用于评估数据质量，不能作为可售库存合并依据。

> 同日会议补充：销售驱动的流程应先有结构化销售订单及订单明细行，再向生产、采购和发货传递需求。本文的“任务配置确定实物身份”发生在执行阶段，**不能替代上游订单明细，也不要求定制产品在接单时已经拥有最终库存产品身份**。现有 `sales_contracts` / `sales_contract_items` 经 V133 已只读化，不能直接当新订单写入表；现行生产单和 ERP 出库单上的 `sales_order_ref` 是自由文本，不足以建立可靠关联。

订单头 ID 表示客户的这笔交易；订单明细行 ID 表示一个可分别生产、外采、现货交付和分批发货的需求项；产品身份 ID 表示最终可互换的实物。下游单据应引用**订单明细行 ID**，并保留订单版本及当时的需求快照。标准品可在订单明细选现有产品身份；定制品先锁定配置要求，执行过程中确认最终产品身份。现货小单也建立最简订单，但“确认订单并生成出库草稿”应在同一操作中完成，避免业务员重复录入。样品、返工、内部领用等非销售任务可没有销售订单，需显式标记任务来源。

## 1. 三种标识各司其职

| 标识 | 作用 | 唯一性 |
|---|---|---|
| 产品身份 ID | 表示可互换出库的同一种实物，库存按它聚合 | 每种可互换配置一条；不同任务单可以引用同一条 |
| 任务单 / 完工批次 ID | 表示哪张任务单、哪次验收入库生产了这些实物 | 每单、每次入库独立，供追溯 |
| 产品显示名 | 给人阅读、打印、搜索 | 不承担唯一约束，允许重名和改名 |

唯一索引建在**产品身份主数据**上，不建在“品类＋尺寸＋一出N”或任务单上。两张完全相同配置的任务单应引用同一产品身份，不同电压、插头、材质、品牌或会影响交付替换性的可选配置必须成为不同身份。产线限制可选项，但同一实物跨产线生产时可以共用身份；交期、数量、客户、工序、跟单备注不属于产品身份。

## 2. 身份键的生成规则

新建任务单时，从产线可用的产品名称与配置项中选择。配置项必须有**稳定的业务代码**；当前只保存中文选项名称、依靠名称拼键的方式不足以承受改名、重名和跨产线共用。服务端按固定字段顺序生成规范化配置快照，包括产品类别/型号、尺寸、模具排列、形状、材质、电压、插头、品牌、盒高和已选可选配置的稳定代码。可选配置代码排序、去重；空值与“未填写”不能被解释为某个已知规格。首版将所有结构化**产品规格**默认纳入身份；若某项只是工艺说明，经过业务确认后才从身份规则中排除。非标模具、配件缺少足够规格时保留任务专属身份，不能把空配置聚合。

持久化 `identity_rule_version`、规范化配置 JSON、其 SHA-256 指纹以及可读配置快照。数据库以版本＋指纹唯一约束，服务端命中时对比完整规范化 JSON；业务外键始终引用产品身份 ID，不能把指纹或显示名当外键。服务端事务内执行查询/插入，遇到并发唯一冲突后重新读取。产品名称或选项标签调整不改变既有身份；已投产任务的配置变更应记录修订，并在已入库时禁止直接改写旧库存的身份。

“能否在不征求客户意见的情况下直接替换发货”是合并两个配置的判准。早期宁可多分开，不能把不可互换的货合并成一个余额。旧 `ProductIdentityKeys` 的三字段键仅供历史候选分析，不能直接写入可售库存身份。

## 3. 业务链与现有代码落点

1. **任务单**：在任务配置保存时由后端生成或复用产品身份，并将 `product_identity_id`、规范化配置及显示名快照挂在产出项上。页面展示生成结果，用户不手选库存 SKU。若页面改成“先选产线”，产线负责限定产品名称和可选项；工序模板仍由制程规则决定，不能由产品身份反推。
2. **氚云导入任务单**：`production_orders` 及导入快照保持来源记录，不另造一张“正式制造工单”。从已导入字段生成候选身份；字段缺失、冲突或难以判断是否可替换时要求人工确认映射并留审计记录，不能自动归并。已有源端入库记录与本地入库要做去重检查。
3. **报工、质检和入库**：报工仍按工序记完成数量。全部必需工序完成后质检验收；合格入库行只引用任务产出项上的身份，选择仓库并确认合格数量。服务端在一个事务中校验状态、写完工入库事实、批次和不可变库存流水、增加本地可售余额；重复提交与冲正必须幂等并保留审计。当前氚云完工服务让质检另选 `sales_products` 的入口应替换为“任务产出身份展示＋必要时先完成映射”。
4. **销售出库**：先选仓库，再从该仓库本地可售余额按产品身份和单位选货，事务内扣减；出库明细保留身份 ID 和当时显示名。若要准确回答“这次发的货来自哪张任务单”，必须在出库时分配入库批次，并建**当前 ERP 出库单**到批次的分配记录。只查仓库×产品汇总余额只能得到可能的来源，不能证明实际来源；旧 `sales_outbound_finished_goods_allocations` 绑定的是历史台账出库，不宜直接复用。
5. **历史库存**：氚云仓库库存/产品台账继续作为参考样本和对账来源，不自动并入本地可售余额。存量先映射到新身份，核定仓库、单位、期初数量并明确生效日，再一次性开账；未确认的脏数据不得参与销售可用量。

现有 `product_inventory_balances` / `product_inventory_transactions` 和 ERP 销售出库已通过 `sales_products` / `canonical_product_id` 关联。最小改造是让配置生成的产品身份进入这条既有主数据/库存链，并明确标记 `TASK_CONFIG` 来源；不另起一套库存余额。现有“产品库存”主页面读的是氚云台账合并快照，本地可售库存需要单独明确展示来源，避免两种数量混用。

## 4. 实施顺序与验收

| 阶段 | 交付物 | 验收条件 |
|---|---|---|
| A 身份契约 | 稳定产品/配置代码、版本化规范化规则、主数据唯一约束；修正 `ProductIdentityKeys` | 同配置跨单命中同一 ID；材质/电压/可选实物配置不同不合并；重复中文名不冲突 |
| B 任务单接入 | 本地任务产出项和氚云任务映射到身份，页面展示快照 | 任务单建档无需手选库存 SKU；氚云缺字段时明确显示待映射 |
| C 验收入库 | 质检完成后按任务产出身份过账、冲正和批次追溯 | 只过账一次；合格数入指定仓；冲正恢复余额且留痕 |
| D 销售出库 | 仓库可售余额选择、扣减、批次分配 | 无库存不可出；出库/撤销数量正确；可追溯至任务单 |
| E 存量对账 | 氚云历史库存只读映射、差异表、审批后期初开账 | 历史脏值不自动进可售库存；期初不与新完工入库重复 |

首个端到端样例用**浙江利强包装科技／温州仓／全自动气调机**。两张相同配置任务单分别合格入库 2 台和 3 台时，可售余额为同一身份 5 台，但保留两个批次；不同电压或影响交付的可选配置必须形成另一身份。销售出库 2 台后原身份余额 3 台，出库批次能追到对应任务单。

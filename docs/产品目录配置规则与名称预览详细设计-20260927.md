# 产品目录、配置规则与名称预览详细设计

日期：2026-09-27。承接《产品基础目录与配置命名设计-20260927》。本阶段只设计基础目录、版本化配置规则与名称预览，尚未编码。试点范围为全自动气调机产线，其他产线继续使用现有能力。

## 1. 本阶段交付边界

完成后，管理人员在现有“任务单产品与配置”中维护规则；销售和生产在同一任务配置抽屉中填写，能够看到一致的预计入库名、完整规格和未完成项。

预览不创建sales_products记录、不生成正式产品编号、不修改canonical归属、不写库存。名称预览成功不等于产品身份已确认。后续阶段才建设产出身份候选与确认。

首版按基础产品逐个启用规则，不能因为一条产线进入试点就让该产线所有未配置产品停止开单。界面区分“已启用新规则”“仍使用旧配置”。未发布规则不能参与正式业务。

## 2. 当前代码的具体调整点

| 当前位置 | 当前情况 | 本阶段调整 |
| --- | --- | --- |
| ManufacturingTaskConfigController | Controller直接做配置SQL写入，字段主要为名称、启用、制程 | 保留现有URL，抽出主数据Service，增加稳定代码、类型、分组与规则版本返回 |
| ManufacturingTaskConfigPanel | 按workshopName分组；产品与选配两块列表 | 改按workshopId分组；增加基础产品详情抽屉及规则维护 |
| ManufacturingService.taskConfigOptions | 产品和选配主要返回名称字符串 | 增量返回带ID、代码、标签的对象；旧字段在兼容期保留 |
| ProductionTaskOrderDrawer | 固定一套盒型/电气字段，选配无分组 | 以发布规则驱动显示/必填/适用选配，增加后端预览区 |
| SalesOrderView / ErpSalesOrderService | 保存productName和productionConfig，规格摘要主要为尺寸盒高 | 同一配置快照加入基础产品ID、规则版本及后端生成摘要，保存时重新验证 |
| ManufacturingService / 氚云任务查询 | 产出基础名与来源配置，旧任务字段不完整 | 新建试点任务使用发布规则；旧任务只读显示原文，不强制按新规则补齐 |

当前配置页“产线无默认制程时必须显式选择制程”的说明，与产品自动确定制程、无制程可免报工的现状不一致。建设时同步改为准确说明，不能重新要求车间接单手选制程。制程解析仍复用现有解析器，命名规则不决定工序。

## 3. 基础产品与配置项字段

沿用manufacturing_task_config_items作为现有基础选项记录，不另建一份同义产品目录。

| 字段 | 产品名称记录 | 可选配置记录 | 约束 |
| --- | --- | --- | --- |
| id | 基础产品ID | 配置项ID | 保留现有主键 |
| config_code | 如BP-000123 | 如OPT-000456 | 全局唯一，不从中文名或型号拼接；生成后不可修改 |
| config_name | 基础产品显示名 | 配置项显示名 | 可修改，历史快照不回写 |
| workshop_id | 适用产线 | 选配维护产线 | 使用ID关联，不依赖车间名分组 |
| product_type | MACHINE / MOLD / PART | 不适用 | 产品记录必填；多模具机器属于MACHINE |
| model_code | 如LQ750 | 不适用 | 展示与查询字段，不作全局唯一键 |
| option_group_code | 不适用 | 如FILM、FILLING、PACKAGING | 稳定分组代码，标签可调整 |
| sort_order | 基础产品顺序 | 配置组内顺序 | 统一命名排序 |
| active | 新需求可选 | 新需求可选 | 停用不删除历史引用 |
| process_template_id | 产品专属制程 | 不适用 | 未指定沿用产线默认，无制程按现行规则处理 |
| row_version | 乐观锁版本 | 乐观锁版本 | 防止多管理员覆盖保存 |

名称保存前去首尾空格。新增/改名均检查同产线同类型的名称冲突，不能只在新增时检查。发现既有同名记录时列出待整理记录，不在迁移中直接合并或删除。

选配是否互斥、是否影响身份等属于具体产品的规则，不能只在一个全局配置项上固定。例如外配输送台对某产品是独立附件，对另一个套件可能有不同处理。

## 4. 规则版本数据结构

建议增加manufacturing_product_config_rules：

| 字段 | 含义 |
| --- | --- |
| id、base_product_id、version_no | 规则ID、基础产品ID、版本；产品ID＋版本号唯一 |
| status | DRAFT、PUBLISHED、RETIRED |
| rules_json | 字段、适用选配、命名段落等有限规则结构 |
| definition_snapshot_json | 发布时冻结的基础标签、配置项代码/标签及排序 |
| draft_revision | 草稿修订号，用于并发控制 |
| created/updated/published_by、published_at | 维护与发布审计 |

基础产品保存current_rule_id指向当前发布版本，发布过程锁基础产品行，校验并切换指针；原版本标记RETIRED但保留可读取。已发布内容不可原地修改，修改时复制为下一版本草稿。

版本职责分开：本阶段configRuleVersion控制表单和校验，namingRuleVersion控制名称模板。后续identityRuleVersion用于产品复用判断；不能把名称规则升级等同于实物身份改变。

规则使用有限字段与枚举，禁止执行任意表达式、脚本、SQL或自定义代码。首版支持：

- 字段visible / required / applicable及产品类型白名单。
- 正数、小数精度、长度、枚举白名单等校验。
- 选配组单选/多选、最小/最大选择数。
- requires / excludes配置项关系。
- 命名段落开关与固定顺序、哪些字段进入完整规格。
- identityParticipation仅记录未来身份判定建议及确认状态；本阶段不生成库存身份。

互斥关系双向归一，requires校验引用有效且避免循环。未确认的技术关系仅作提示，不擅自写成阻止提交的硬规则。

## 5. 三类表单及规则编辑

### 5.1 机器

保留现有盒形、尺寸、盒高、盒材质、排列、电气、插头、品牌、选配及说明字段。规则明确每个字段是否适用，不适用时不提交残值。

首版不提供任意新增字段编辑器。维护人员从既定字段清单选择显示、必填、顺序和允许值，以免每个机型造出不同字段名。

电压初期可继续使用现有枚举编码与标签映射，后台规范化为相数和电压数值；不直接把“220V”解释成单相。品牌别名与电压错字通过明确映射转换，保留历史原值。

### 5.2 模具

必须有具体模具名称/用途、适配基础产品、模具类型、盒形尺寸、排列、图纸或设计引用。允许草稿暂缺图纸；缺必要适配/设计信息时只能生成不完整预览，不能宣称最终入库名称完整。

上下模具成套与单件区别保存，单位按明确计量设置；不能从名称中猜“个/套”。机器中的多组模具需求使用模具组ID，记录安装随主机或额外交付。

### 5.3 配件

具体配件名称、型号规格、单位；适配机型按配件要求设置。不再强制填写盒形、盒高、电压等不适用字段。

机器/模具/配件都使用ProductionTaskOrderDrawer。额外产出数据结构本阶段预留，支持不了的复杂产出提示待确认，不生成貌似完整的一台标准机器名称。

## 6. 规则发布与业务使用

| 场景 | 版本处理 |
| --- | --- |
| 新需求首次配置 | 绑定当前PUBLISHED版本 |
| 已保存草稿重新打开 | 使用草稿绑定版本；有新版本时提示可更新，不能静默换版 |
| 已保存草稿升级规则 | 显示变化字段、默认值与失效选配；用户确认并重新校验 |
| 订单确认 | 使用绑定版本重新校验并生成快照；版本标签变动不改变已填写要求 |
| 车间从确认订单接单 | 原样引用已确认配置版本，不重新套最新规则 |
| 无销售订单的任务 | 同一规则校验并生成配置快照 |
| 既有氚云任务 | 保留来源配置与原名；未来显式映射才能获得新基础ID和规则版本 |
| 产品/选配停用 | 禁止新需求使用；已确认需求保留历史值。草稿确认需重新核对可执行性 |

规则RETIRED表示已被新规则取代，不等于旧订单无法执行。安全/技术原因禁止使用某配置时，必须显式标记及说明，不能靠改名或停用静默改变客户订单。

发布核对：基础类型完整，配置代码无冲突，必填字段适用，选配引用有效，已确认互斥关系无冲突，命名段落及长度可控，至少一份完整样例及缺字段样例验证通过。发布记录保存差异和操作者。

## 7. 预览接口契约

新增独立只读计算Service：ProductConfigurationPreviewService。读数据与计算，不写业务表。

建议业务接口：POST /api/product-configurations/preview，允许sales_order.manage或manufacturing.manage；使用现有RequirePermission的“任一权限”语义，并确认对应产线/产品可选。销售不用制造主数据管理权限。

管理规则预览使用POST /api/manufacturing/master/task-configs/{id}/rules/{ruleId}/preview，仅manufacturing.template.manage；只能预览当前用户有权维护的草稿。

请求示例：

```json
{
  "baseProductId": 123,
  "configRuleVersion": 1,
  "configuration": {
    "boxShape": "RECT",
    "boxLengthMm": "186",
    "boxWidthMm": "136",
    "boxHeightMm": "60",
    "moldArrangementCode": "ONE_OUT_FOUR",
    "voltageCode": "THREE_PHASE_380V",
    "plugCode": "CN",
    "brandCode": "LIQIANG",
    "optionCodes": ["OPT-001", "OPT-002"]
  }
}
```

示例ID/代码仅说明结构，不是实际种子值。现有表单boxHeight等字段由适配层转换，不在不同页面分别手写转换规则。

返回：baseProductId、configRuleVersion、namingRuleVersion、normalizedConfiguration、namePreview、specificationPreview、completionState、fieldErrors、confirmationItems。completionState为COMPLETE/INCOMPLETE/NEEDS_CONFIRMATION，不含产品编号或“已确认库存产品”结果。

- 字段不全也返回可读预览，如“LQ750全自动推杆｜尺寸未填写｜1出4”，同时标记INCOMPLETE。
- 规格中显式区分未填、不适用、已选择；禁止把缺失泵型解释成默认泵。
- 规则/产品ID不存在或无权限用4xx；普通表单校验问题放fieldErrors，便于前端逐项呈现。
- 预览名称仅显示关键技术选配，完整规格包含全部已确认实物字段；包装/客户/数量不混进机器名。

其他建议端点：GET /api/product-configurations/products?workshopId、GET /api/product-configurations/products/{id}/rule；管理草稿保存、复制、发布使用现有master路径新增rules子资源。所有写端点声明权限并审计，规则发布采用事务和并发修订校验。

预览不作为幂等业务动作登记；保存订单/任务仍沿用业务请求键。接口限输入大小，只查固定数据，不开放数据库查询表达式。

## 8. 前端交互细节

维护页：产线列表→基础产品表（代码、名称、类型、制程、规则版本）→基础产品详情抽屉。详情分“基本信息、字段与选配、命名预览、发布历史”。不再全部在表格内随改随生效。

填写页：基础产品选定后拉规则，按类型显示字段、分组配置。下方预览区列预计名、完整规格、缺项/待确认项。产品编号位置显示“入库前确认”，不能显示一个预览生成的临时SKU让用户误以为已有库存。

请求防抖约300ms；每次更换产品或输入版本递增序号，忽略过期响应。规则读取失败显示重试，提交不能凭旧机型缓存规则继续。提交时后端重新校验，前端预览结果只用于展示。

切换基础产品先提示哪些字段将被清除；只保留两规则明确共享的字段，不自动把旧机型选配带到新机型。切换产品类型卸载字段及残值，选配清除需要可见反馈。

## 9. 快照与兼容建设

新配置快照包含：baseProductId、baseProductCode、productType、configRuleVersion、namingRuleVersion、normalizedConfiguration、optionCodes及当时标签、nameSnapshot、specificationSnapshot、confirmationItems。

当前productName、optionalConfigs等中文字段在兼容期仍保留，由新快照生成兼容输出，避免旧页面读取失败。客户端不能提交互相矛盾的旧字段与新代码；服务端检测冲突并拒绝，不任取一份。

旧草稿没有稳定ID时，仅对产线内唯一明确名称生成迁移候选，要求用户核对后绑定；无法唯一解析就保留待选择。已确认旧订单与已执行任务不批量回写新规则。

迁移只给现有基础项补稳定代码与已确认类型，历史源字段不覆盖。model_code可从明确选项辅助预填，但需核对；不能从旧入库名猜型号后自动建关联。

本阶段不改product_inventory_balances、transactions及sales_products产品身份，不执行库存开账、合并或重命名。迁移版本号在实现时检查当前最大整数版本并分配。

## 10. 验收用例与编码顺序

| 用例 | 预期 |
| --- | --- |
| 同配置的选配勾选顺序不同 | 名称、规范化配置、完整规格一致 |
| 方形长宽录反、圆形直径非正数 | 具体字段提示，不静默交换或替换 |
| 基础名或选配标签修改 | 历史快照不变，稳定ID/代码不变 |
| 全自动/半自动LQ450 | 基础ID与规则明确区分，不靠型号字符串误判 |
| LQ750D多模具机器 | 产品类型为机器，多套配置不压成一个尺寸 |
| 模具/配件 | 专属字段，泛称不被展示为最终完整入库产品 |
| 仅改变木箱包装 | 机器名不改变，包装要求单独可见 |
| 规则升级后打开已确认需求 | 原版本与要求仍可读取，不强制重填 |
| 两人同时修改草稿/发布 | 修订冲突可见，不能后保存覆盖前发布 |
| 销售只具销售订单权限 | 可读产品规则和预览，不能维护规则 |
| 名称预览连续输入 | 旧响应不覆盖新结果 |
| 保存客户端篡改名称 | 服务端按配置重算，不能写入伪造摘要 |
| 历史同编号异名 | 仍列待核对，不因预览被自动归一 |

编码次序：①补主数据代码/类型和workshopId返回；②规则版本Service、权限与发布事务；③统一规范化与预览Service；④管理页与现有抽屉接入；⑤销售/独立任务保存校验与快照；⑥试点样例验证。

通过后再进入“产出清单与库存产品身份确认”阶段。本阶段验收看名称与配置是否可信一致，不以库存已合并或业务链已全部跑通作为完成标准。

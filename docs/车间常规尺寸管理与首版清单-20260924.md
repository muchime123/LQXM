## 0. 为什么需要这个东西

LQ 2026-09-24 定：**「订做」不是人选的，是看盒子尺寸 —— 车间有这个尺寸的模具就不算订做，没有就算订做。**

而 P2 的显示名要带「订做」前缀（`docs/SKU重设计-…-20260923.md` S1 拍板），所以必须有一个
**「车间有没有这个尺寸」的判据**。查下来 ERP 里**没有这份主数据**：

| 查过的地方 | 结论 |
|---|---|
| `packaging_molds` / `packaging_mold_groups`（77 条 / 48 组 / 37 个口径） | 全是**气调机的托盒模具**（141*141、220*130.5、C70.5…），**封口机产线一条都没有** |
| `product_variants`（mold_length_mm / mold_diameter_mm） | 只有 4 条，口径列全空 |
| `manufacturing_task_config_items`（任务单产品与配置） | 只有「产品名称」49 项 +「可选配置」70 项，**没有尺寸** |
| `h3_product_catalog` / `sales_products` | 无口径结构 |

→ 所以按 LQ 的指示：**从库存里「非订做」的名字反推一版常规尺寸，并把它做成可维护的主数据功能。**

### 先排除一个错误假设

用氚云自己的「订做/标准」制程标记去反推尺寸是**行不通**的 —— 同一尺寸两边都有大量单：

| 尺寸 | 标准制程（封口机车间） | 订做制程（订做封口机（5楼）） |
|---|---|---|
| `70` / `70mm` | 55 / 27 | 25 / 39 |
| `250` | 65 | 10 |
| `2014` | 54 | 19 |
| `90mm` | 9 | 22 |

**读法**：氚云的制程名标的是**哪个车间接的单**（5 楼 = 老厂），不是「这个尺寸是不是订做」。
所以「订做」在氚云那里从来没被严格表达过 —— 这正是要把它显性化到主数据的原因。

## 1. 反推口径（可复算）

```
① 取库存名：h3_warehouse_stock.product_name
   排除 名字含「订做」或「定做」的（这些是业务自己标的非标件）
   只保留产线产品（名字含 卷膜/片膜/封口机/气调/贴体/推杆/圆盘/翻盖/称重/模具）
② 抽开头的尺寸 token，用 ProductIdentityKeys.normalizeSize 归一（与身份键同一实现，禁第二套）
   形态四类：A x B（* / × / x / X 混用，可带 mm）｜单值圆口径（70 / 70mm）｜φ/Φ 直径｜
             压掉乘号的四位简写（2014 = 141.2×201.4、2216 = 224.6×160.9、2617 = 174.5×261）
   机型号要排除：1000型不锈钢封口机 / 1080A连续式… / LQ310T…（数字紧跟「型」或拉丁字母）
③ 给每个尺寸投产线票：把 production_orders 的 (production_line, box_size) 归一后计数
```

### 结果

| 指标 | 值 |
|---|---|
| 非订做产线库存名 | **3,077** 个不同名 |
| 抽出尺寸 | **3,014**（98.0%）；抽不到 63 个（机型号、「不配模具」这类） |
| 不同尺寸 | **741** |
| 任务单尺寸覆盖率 | 3,048 / 4,118 = **74.0%** |

### 阈值取舍

| 阈值（该尺寸出现在多少个不同非订做库存名里） | 尺寸数 | 覆盖任务单 | 覆盖率 |
|---|---|---|---|
| ≥1 | **741** | 2,757+291 | **74.0%** |
| ≥2 | 265 | 2,757 | 66.9% |
| ≥3 | 173 | 2,541 | 61.7% |
| ≥5 | 96 | 2,292 | 55.7% |
| ≥10 | 52 | 1,916 | 46.5% |

**取「≥1」** —— 理由：一个尺寸只要在**非订做的**库存名里出现过，就说明车间有这个模具（业务自己标过它是常规）。
用高阈值会**把真常规判成订做**，方向错；多进来的噪声交给管理页人工停用（这正是做管理功能的意义）。

## 2. 设计：`shop_standard_sizes`（车间常规尺寸）

```
id                 bigint      PK
size_key           varchar(60) 唯一  —— 规范化键：`方|128x184` / `圆|250` / `方|2014`
shape_type         varchar(10)        RECT / ROUND
length_mm          varchar(40)        方盒：长（大值）
width_mm           varchar(40)        方盒：宽（小值）
diameter_mm        varchar(40)        圆：直径
shorthand          varchar(20)        压掉乘号的业务简写原文（2014 / 2216 / 2617…）；非简写为 NULL
workshop_name      varchar(100)       NULL = 全厂通用（当前一律 NULL，见下）
observed_line      varchar(100)       分析推断的主要产线（**仅作评审参考，不参与判定**）
evidence_names     int                出现在多少个不同非订做库存名里（证据强度，可排序）
evidence_orders    int                任务单里用过该尺寸的单数（证据强度）
source             varchar(20)        MINED（分析导入）/ MANUAL（人工新增）
active             tinyint(1)        1 启用 / 0 停用
remark             varchar(500)
created_at / updated_at
```

### 三个设计取舍（都有理由）

1. **不按车间分键**，`workshop_name` 统一 NULL。
   模具是**物理实体**：车间有这个模具，哪条线都能用。按「票数最多的产线」写死会**把跨线通用的尺寸判成订做**
   （实测 `111x161`、`166x65`、`125x125`、`170x220` 这些在两条线上都有单）。
   所以：判定只看尺寸；推断出的产线存 `observed_line` 供评审，等真有车间专属尺寸时再启用 `workshop_name`。

2. **简写要单独存**（`shorthand`）。
   `2014` 既是业务简写（= 141.2×201.4），也可能是「2014mm」—— 但业务从不这么写。
   存下来才能让管理页显示成「2014（= 141.2×201.4 方盒）」，也能与库存名对上。

3. **与模具主数据并存，不合并**。
   `packaging_mold_groups` 是**气调机托盒模具台账**（有模具编号、杯胆配件、机型归属），
   本表是**「这个尺寸算不算常规」的判据表**（含封口机口径）。两者口径不同，硬合会互相污染；
   导入时把气调机的 37 个口径也一并纳入本表（作为常规尺寸的一部分），但台账仍归模具模块管。

## 3. 判定与落地

```
建单时：
  customized = 手工覆盖（若业务员勾了）
              ?: !shop_standard_sizes.exists( normalSize(盒子尺寸) )
  → ProductIdentityKeys.derive(品类, 盒子尺寸, 一出N, 可选配置, customized)
  → 写 manufacturing_order_outputs.sku_key / display_name
```

- **自动判 + 可手工覆盖**（LQ 2026-09-24 拍板）：尺寸以外的原因（材料、形状、客户特殊要求）造成的订做，
  由业务员在下单时勾选覆盖。
- **规范化只有一个实现**：前端**不得**自己拼显示名或判订做 —— 预览走服务端
  `GET /api/manufacturing/product-identity`（同一个 util）。

### 已知噪声（管理页人工停用即可，不做过度清洗）

- **贴体膜/铝箔膜宽度**被当成了尺寸：`430高温贴体膜`、`70.5*86.5铝箔片膜`、`106.8*116.8拉手铝箔压纹片膜` —— 这些是耗材膜宽，不是盒子。
- **模具名里的「套 XXX 用 YYY 模具」**：`套250用170模具` 抽到的是 250（盒）✓，但 `套197用84模具` 抽到 197 也是盒 ✓，而 `套280用62x62模具` 会抽到 62x62（**模具自身尺寸**，不是盒）—— 抽错方向。
- **单次出现的自由文本**：约 100 余条只有一个库存名支撑，证据最弱，排序在末。

> 这些噪声都**不阻断**功能：判定错只会让个别单的显示名多带或少带「订做」，且业务员有手工覆盖；管理页随时可停用。

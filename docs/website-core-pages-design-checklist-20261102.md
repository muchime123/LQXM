# 官网核心页面设计实施清单

基线：当前本地 `corporate-website`，包含尚未提交的包材公开入口下线改动。此清单依据 Vue/CSS 与静态快照核对；视觉效果和真实设备验收仍需浏览器验证。保留现有组件、路由和官网独立内容层。

## P0：内容和转化先可用

| 页面 | 现状证据 | 实施动作 | 验收 |
| --- | --- | --- | --- |
| 首页 | `Home.vue` 按 Hero → 企业证明 → 核心设备 → 制造展示 → 场景 → CTA 排列；精选产品来自快照 | 人工审核首屏 Banner、前四张主推设备及公司数字；替换无依据的宣传语。不要仅因区块多而删除 | 首屏明确设备类型与服务对象；主按钮进入产品，次按钮打开真实联系渠道；图片均对应实际业务 |
| 产品中心 | `Products.vue` 默认同时呈现搜索、分类和四项应用筛选；筛选状态同步 URL | 将搜索和设备分类保留在首层，四项条件收进「更多筛选」，移动端用可关闭面板或折叠区；保留现有 URL 参数和清除筛选 | 320–1440px 可完成筛选、清除、翻页与返回；浏览器前进后退保持条件；空结果能恢复全部产品 |
| 产品详情 | `ProductDetail.vue` 已有图库、关键事实、应用、规格、参数和两个咨询按钮；静态内容 45 条 | 逐条审核产品名称、图片、关键参数、卖点与公开型号；无资料时隐藏相应区块，不填假参数；在移动端检查主图与咨询按钮可见性 | 每个已发布 slug 有正确图和名称；询盘能带入产品；所有参数可追溯到审核资料 |
| 联系流程 | 静态版 `InquiryFormModal.vue` 提供 `mailto:`、`tel:`，无在线提交 | 销售人员确认邮箱与电话，实测桌面和手机邮件、电话动作及收信 | 用户明确知道邮件需自行发送；实际收件人收到测试邮件 |

## P1：页面与组件一致性

- **首页信息层级**：保留核心设备和场景；制造展示与企业证明分别承担“实物证据”和“公司事实”，如内容重复再删。首页产品轮播使用共享 `ProductCard.vue`，不另造卡片。
- **产品卡片**：统一 4:3 图片容器、设备分类、名称和整卡点击；检查长名称、缺图、白色机器在浅背景上的辨识度。首页与列表复用同一组件。
- **详情图片**：主图在 `products.css` 使用 4:3；核对纵横构图和缩略图数量。图片不能用通用占位图掩盖大批缺失素材。
- **规格与参数**：`variantCards` 最多显示 6 项；若多数产品缺少经审核的配置，隐藏空区块。公开参数只展示用户选型所需内容。
- **咨询措辞**：静态版按钮应让用户预期会看到联系方式；不使用“提交成功”暗示邮件已送达。多个 CTA 共用 `SiteCTA.vue` 与全局弹窗。
- **方案与关于页**：沿用现有视觉系统，逐条核对方案案例真实性、工厂照片和证书图片。包材仍不作为独立公开页面。

## 跨页面设计规范

| 项目 | 当前依据 | 执行规则 |
| --- | --- | --- |
| 容器 | `tokens.css`: `--max: 1440px`, `--pad: clamp(20px, 3vw, 32px)` | 页面沿用公共容器和左右边距；不要各页硬编码新最大宽度 |
| 留白 | `--section-space: clamp(52px, 4.6vw, 76px)` | 同级区块使用统一纵向节奏；仅 Hero、紧凑信息条例外 |
| 标题 | 现有页面各自使用 H1/H2/H3 | 每页一个可见 H1；章节 H2，卡片标题 H3；隐藏区块不留空白标题 |
| 按钮与状态 | 公共 `.button`、`SiteCTA`、骨架屏与空状态 | 复用已有主次按钮；列表保持加载、错误、空结果三态，操作给出反馈 |
| 卡片与图片 | `ProductCard.vue`、4:3 产品主图 | 首页、列表共用卡片；保持裁切策略与替代文本一致；优先使用真实设备图 |
| 响应式 | `products.css` 在 1100、900、520px 调整布局，详情在 980、640px 调整 | 必须在 320、390、768、1024、1440px 检查；筛选、导航、图库和 CTA 不遮挡内容 |
| 动效 | 首页轮播、`v-reveal`、`prefers-reduced-motion` | 动效不阻止阅读和点击；尊重减少动态效果设置 |

## 不纳入本轮

包材精选系列、新数据库表、CMS 重建、英文站发布和在线询盘服务。当前 `/packaging` 等旧地址继续跳转产品中心；重新上线前需独立审核产品、图片与公开规格。

## 验证顺序

先逐条审核产品快照与联系信息，再在浏览器检查五种宽度，随后实施筛选与页面优化；最后跑官网测试和生产构建。视觉检查的截图与实际问题记录应补充到验收结果，不能用 CSS 断点存在代替真机验收。

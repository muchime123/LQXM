## 2. 共同字段和生命周期

类型记法：ID 为逻辑标识，物理 BIGINT/UUID 后续决定；S(n) 为建议最大字符数；Decimal 为十进制定点数，禁止用二进制浮点做数量换算。API 中 ID 建议按字符串传递以避免大整数精度损失。

必填时点：C=创建草稿，A=启用，B=具体业务动作。空值表示未知/不适用，不能以 0、默认公司或默认“个”掩盖缺失。

| 字段 | 类型/必填 | 约束 | 变更规则 |
|---|---|---|---|
| id | ID，系统生成 | 永久稳定、不可复用 | 不可改 |
| code | S(64)，A | 编码在确认的范围内唯一；不可复用停用编码 | 启用后建议冻结，别名另存 |
| name | S(200)，C | 去首尾空白后非空；名称不是身份唯一键 | 可改，旧单据快照不回写 |
| lifecycleStatus | 枚举，C | DRAFT/ACTIVE/INACTIVE | 初始 DRAFT；转换须校验权限和依赖 |
| version | 整数，系统维护 | 乐观锁；防止静默覆盖他人更新 | 每次成功变更递增 |
| createdAt/createdBy、updatedAt/updatedBy | 时间/操作者，系统维护 | 不接受客户端冒填 | 审计追溯 |
| activatedAt/activatedBy、disabledAt/disabledBy | 时间/操作者，条件必填 | 随状态转换记录 | 保留历次动作日志 |
| changeReason | S(1000)，重要变更必填 | 停用、合并、关键字段变更须说明 | 写审计，不替代业务字段 |

基本动作：创建草稿 → 校验 → 启用 → 停用 → 重新校验后恢复。是否增加独立审核人由 D08 决定。草稿无引用才可删除；已启用或被引用对象保留身份，采用停用。停用禁止新业务引用，历史查看、已有未结单据结清/退货/冲销走明确例外，不能一刀切阻断。

编码建议：SKU/往来方/员工在 ERP 工作空间内唯一，公司独立编码；部门/仓库在所属公司内唯一。D02 未确认前，不建立与全局或公司范围相矛盾的生产唯一索引。编码是否区分大小写必须显式决定，不能依赖数据库默认排序规则。

## 3. 产品：分开型号、SKU、配置和价格

### 3.1 对象边界

- 型号/产品族：展示、知识、通用技术资料，可被多个 SKU 引用。
- SKU：需要分别采购、销售、领用或计存的产品身份。同名不同规格分别识别；是否生成新 SKU 按 D03。
- 配置版本：定制参数和图纸的不可变版本；不把每段自由文本自动变为新 SKU。
- 价格记录：按公司、对象、币种、单位、含税口径和有效期保存；产品主档不承担历史成本账。

### 3.2 SKU 字段

| 字段 | 类型 | 必填时点 | 校验与唯一性 | 变更规则 |
|---|---|---|---|---|
| skuCode/skuName | S(64)/S(200) | A/C | 按共同编码规则；名称允许重复 | 编码冻结，名称留快照 |
| categoryId | ID | A | 有效分类 | 分类改变不重写历史 |
| materialType | 枚举 | A | FINISHED/SEMI_FINISHED/RAW/PART/TOOLING/CONSUMABLE/SERVICE | 有过账后变更须评估影响 |
| specification | S(1000) | A，品类有规格时 | 不以名称+规格文本自动判定同物 | 身份性规格变化通常新建 SKU，D03 |
| identityAttributes | 类型化属性集合 | A，按品类模板 | 属性带单位/枚举/精度；参与身份的字段明确列出 | 有引用后不能原位改变身份属性 |
| modelRef | ID，可空 | 无 | 引用明确的产品族/型号 | 不要求型号与 SKU 一一对应 |
| baseUnitId | ID | A，数量管理产品 | 有效基本计量单位 | 产生数量业务后冻结 |
| inventoryManaged | 布尔 | A | SERVICE 不得为 true | 有库存/未结业务时不能切换 |
| purchasable/sellable/producible | 布尔 | A | 按业务允许多个同时为 true | 停用能力只约束新增业务 |
| quantityScale | 整数 | A | 与单位及业务一致；整数件是否允许小数按 D05 | 精度收紧须查余额和未结量 |
| trackingMode | 枚举 | 库存启用前 | NONE/LOT/SERIAL；实际范围按 D04 | 有库存后不能直接切换 |
| defaultPurchaseUnitId/defaultSalesUnitId | ID，可空 | 对应业务前 | 必须有有效换算，默认不等于强制 | 历史明细不跟随更改 |
| configurationPolicy | 枚举 | 定制业务前 | STANDARD/ORDER_CONFIGURATION/DEDICATED_SKU，D03 | 按版本生效 |
| companyEnablements | 公司业务关系集合 | B | 该公司允许采购/销售/生产/库存使用 | 不以共享 SKU 推导跨公司授权 |

模具可能既是可交易产品又是生产资源，是否需要独立资源实例/资产档案待业务确认；不能仅凭 materialType=TOOLING 就自动作为固定资产。

### 3.3 配置、别名与公司关系

| 对象 | 字段 | 约束 |
|---|---|---|
| 配置版本 | configurationId、skuId、revision、schemaVersion、parameters、drawingVersion、status | skuId+revision 唯一；已用于下达/过账的版本不可覆盖；新修改产生新版本 |
| SKU 公司关系 | skuId、companyId、enabledCapabilities、status | 同一对对象一条当前关系；公司不可用时不接受新业务 |
| 外部/旧编号映射 | sourceSystem、sourceScope、sourceEntity、externalId、targetId、decisionStatus、evidenceRef | 来源范围内唯一；只有 CONFIRMED 可用于明确映射；氚云映射不会自动启用 ERP SKU |

建议编号使用无业务含义的序列/规则，分类变化不要求改码。条形码不是必然等于 SKU 编码，一物多包装码需另建包装映射。

## 4. 单位：文字归一不等于数量换算

| 对象/字段 | 类型 | 必填时点 | 规则 |
|---|---|---|---|
| unit.code/name | S(32)/S(50) | A/C | 编码唯一；名称和符号可有别名 |
| unit.dimension | 枚举 | A | COUNT/MASS/LENGTH/AREA/VOLUME/PACKAGE 等；枚举待品类核对 |
| unit.quantityScale | 整数 | A | 最终交易精度由产品规则约束，不能仅看单位名称 |
| alias.rawText/unitId | S(100)/ID | 别名启用 | 仅同语义写法；歧义值拒绝全局自动映射 |
| conversion.skuId | ID | 换算启用 | 包装换算必须按产品定义 |
| conversion.fromUnitId/toUnitId | ID | 换算启用 | 建议只维护辅助单位到基本单位，减少循环换算 |
| conversion.numerator/denominator | Decimal | 换算启用 | 均 >0；基本数量=交易数量×分子/分母 |
| conversion.effectiveFrom/effectiveTo | 时间 | 启用/可空结束 | 同 SKU、辅助单位的生效区间不重叠；使用 [开始,结束) |
| conversion.revision/status | 版本/状态 | 启用 | 已使用比率不可原位覆盖；变更新建版本 |

实现候选精度：数量及比率 Decimal(24,9)，不是已批准上限；先用真实最大量级、最小计量和比率验证。不可静默截断；不能整除或超出精度时按已确认规则拒绝或舍入，并保存换算前值与差异。串联计算须保留中间精度。

规则例子：

- `公斤` 与 `kg` 可作为质量单位同义写法；`kg/箱` 可能表达每箱重量，必须解析含义，不能直接改为 kg。
- 产品 A 一箱 12 个、产品 B 一箱 24 个，不能配置全局“箱→个”。
- 每卷重量不固定的材料需要双计量/实测规则；不能填一个固定比率假装闭合（D05）。
- 正式单据必须保存交易单位、基本单位、比率版本、比率值和两种数量；后续换算变更不重算历史单据。

## 5. 公司、组织、员工与仓库

| 对象/字段 | 类型 | 必填时点 | 约束/变更规则 |
|---|---|---|---|
| company.code/name | S(64)/S(200) | A/C | 编码唯一；名称不是上下级关系键 |
| company.legalIdentifier | S(100)，可空 | 需主体识别时 | 标识类型、国家/地区共同解释；不能假设所有主体同一格式 |
| company.parentId | ID，可空 | 无 | 禁止自己为父、禁止循环；集团层级不等于自动共享资金库存 |
| department.companyId | ID | A | 归属必须明确；UNMAPPED/CONFLICT 不能启用到正式业务 |
| department.code/name | S(64)/S(200) | A/C | companyId+code 唯一；跨公司同名允许 |
| department.parentId/unitType | ID/枚举 | 类型 A | 上级同公司且无环；DEPARTMENT/WORKSHOP |
| employee.code/name | S(64)/S(100) | A/C | 员工编码唯一，姓名不唯一 |
| assignment.employeeId/companyId/departmentId | ID | 任职启用 | 部门所属公司与任职公司一致 |
| assignment.role/isPrimary | S(100)/布尔 | 任职启用 | 多任职允许性和主岗范围待 D08；至少不允许同范围多主岗重叠 |
| assignment.effectiveFrom/effectiveTo | 日期 | 开始必填 | 区间不倒置；调动追加任职版本，不覆盖旧单责任 |
| warehouse.companyId/code/name | ID/S(64)/S(200) | A | 管理公司+编码唯一；管理主体与库存货权分开 |
| warehouse.locationAddress/custodianId | 地址/ID | A，按场景 | 地址完整度按业务确定；保管员须有效 |
| location.warehouseId/code | ID/S(64) | 库位启用 | 仓库内编码唯一；是否启用库位由 D04 |

员工主档与登录账号、角色授权分离；在职不自动获得业务权限。离职撤销访问，但历史单据中的员工 ID 和姓名快照保留。

组织跨公司迁移原则上建立新归属及有效期，不原位改变已使用部门/仓库的公司使历史库存变成另一个主体。仓库存货属于谁须在库存维度或业务关系表达，不能只从仓库所属公司推断。

## 6. 往来方、公司关系与经销角色

### 6.1 身份与交易角色

建议采用“往来方身份 + 各公司交易角色”，D02 未确认前仅是概念方案。一个对象可以同时是客户和供应商；应收应付不因同身份自动抵消。内部车间属于组织；关联公司若参与真实交易，可有受控往来角色，须关联内部公司身份。

| 对象/字段 | 类型 | 必填时点 | 约束/变更规则 |
|---|---|---|---|
| party.code/displayName | S(64)/S(200) | A/C | 编码唯一；同名可共存，提示重复证据但不自动合并 |
| party.kind | 枚举 | A | ORGANIZATION/PERSON；内部车间不能冒充供应商身份 |
| party.legalName | S(200) | 组织实名业务时 | 与显示名分开；保留别名和有效历史 |
| identifier.type/jurisdiction/value | S(50)/S(50)/S(100) | 需要该标识时 | 经核实的主体标识按组合查重；税号不无条件等于所有身份键 |
| identifier.verificationStatus | 枚举 | 有标识时 | UNVERIFIED/VERIFIED/CONFLICT；冲突进入人工判定 |
| companyRole.partyId/companyId/role | ID/ID/枚举 | 交易角色启用 | CUSTOMER/SUPPLIER；同组合一条关系，不跨公司默认为可交易 |
| companyRole.settlementCurrency | 币种代码 | 金额业务前 | 支持币种范围待确认，不默认所有公司一致 |
| companyRole.paymentTerms | 受控条款引用 | 赊销/赊购前 | 只是默认条款；单据保留当时约定 |
| companyRole.salesOwnerId | 员工 ID，可空 | 需业绩归属时 | 有效归属区间；变更不回写历史业绩 |
| dealerRelation.partyId/companyId/channelId | ID | 经销关系启用 | 是公司范围内渠道关系；是否独立角色待 D02 |
| dealerRelation.effectiveFrom/effectiveTo | 日期 | 开始必填 | 历史单据保存关系版本；不覆盖历史渠道 |

### 6.2 联系点、收付款与开票资料

| 对象 | 字段及必填时点 | 校验和历史规则 |
|---|---|---|
| 联系人 | partyId、name（创建）；phone/email 按联系需要 | 电话不唯一，保留原文与规范值；不能用手机号单独决定身份 |
| 地址 | partyId、purpose、country/region、detail；发货前校验收货地址 | 空壳 JSON 判无有效内容；地址版本变更不改已确认单据 |
| 收付款账户 | partyId、accountName、accountNumber、bank、currency；使用前核实 | 账号按字符串保留前导零；展示脱敏、字段权限受控；同账号不自动合并主体 |
| 开票资料版本 | partyId、title、taxIdentifier、address/phone/bank、revision、status | 按实际开票场景要求字段；同户名不合并；税务格式校验另行确认 |
| 别名 | partyId、aliasText、sourceScope、evidenceRef、decisionStatus | 多对象同别名合法；歧义不自动匹配 |

账户、税号等更正必须记录核实依据；无需在一般主档中采集与业务无关的身份证或银行信息。

### 6.3 合并及停用

重复主档先给候选，不自动合并。合并需：证据 → 选择保留身份 → 检查公司角色/账户/未结业务冲突 → 授权确认 → 记录不可循环的指向。历史单据保留原 ID 和快照，通过明确的身份关系查询，不批量改写已过账记录。合并失败整体回滚；不把“改名”当成合并。

## 7. 维护动作与接口契约草案

不在此确定 URL 或现有 Controller 归属。后续 API 应实现以下行为：

| 动作 | 输入重点 | 成功结果 | 拒绝条件 |
|---|---|---|---|
| 保存草稿 | 对象字段、预期 version | 对象 ID、新 version | 编码冲突、字段格式错、旧版本覆盖 |
| 启用 | ID、version、必要时审批依据 | ACTIVE、审计记录 | 缺启用字段、引用不可用、归属冲突、无权限 |
| 停用 | ID、version、原因 | INACTIVE、受影响业务提示 | 未按规则处理阻断项 |
| 发布新版本 | 原对象、差异、生效时间、原因 | 新版本，不覆盖旧版本 | 有效区间重叠、身份变化未分新对象 |
| 查询业务可选项 | 公司、动作、日期、权限范围 | 当时可用对象 | 禁止只按 ACTIVE 不校验公司角色 |
| 合并候选确认 | 源/目标、版本、证据、原因 | 关系与审计 | 循环、身份冲突、并发变更 |

校验必须同时落在服务端和存储约束中；前端禁用按钮不算约束。建议错误使用稳定代码并带字段定位：CODE_CONFLICT、STALE_VERSION、REQUIRED_FOR_ACTIVATION、REFERENCE_INACTIVE、OWNERSHIP_CONFLICT、CONVERSION_MISSING、EFFECTIVE_RANGE_OVERLAP。中文提示用于解释修正办法，敏感数据不进入错误日志。

| M11 | 草稿保存空壳地址后尝试发货 | 草稿允许，发货要求有效地址时拒绝 |
| M12 | 两人以同 version 更新主档 | 一人成功，另一人收到版本冲突 |
| M13 | 停用客户后查询旧单并处理原单退款 | 历史可查；新订单禁止；退款按已有业务例外和权限校验 |
| M14 | A 公司可用往来方被 B 公司选择 | 没有 B 公司交易角色时拒绝 |
| M15 | 导入新的氚云别名/产品快照 | 不自动改 ERP 主档或启用状态，对应 T18 |
| M16 | 已发生业务的 SKU 修改基本单位 | 拒绝原位修改，要求明确转换方案 |
| M17 | 创建 A→B→A 的组织父子关系或身份合并链 | 拒绝循环 |
| M18 | 两个启用单位换算版本生效时间重叠 | 拒绝发布，保留旧版本 |

# 官网设计减负复核（2026-10-28）

本次以“官网内容独立于内部档案”为判定标准。只删除经调用链确认的功能代码，不清理官网内容记录、文件、历史迁移或内部档案。

| 设计 | 源码证据 | 判定与处理 |
| --- | --- | --- |

| 旧官网工作台 | `WebsiteDashboardController` 直接读取 `ProductCatalogService`、内部产品、包材、模具和自媒体 Repository；以内部“在售”“在用”状态计算官网发布准备度 | 下线。该统计口径与官网内容独立目标冲突，且没有独立业务数据。旧 `/website/dashboard` 书签重定向到方案管理。 |
| Banner、页面区块、解决方案、询盘 | 均有官网专属表、公开读取或管理入口；公开页面仍读取页面区块和 Banner | 保留。可视化编辑器删除后，Banner 管理页默认显示 HERO，首页轮播仍由该页面维护。页面区块暂保留现有数据与 API；后续若需要频繁编辑，可建简单字段表单。 |

## 后续控制原则

1. 新官网内容采用独立记录、独立媒体引用、明确发布状态。后台与官网共享认证和通用 UI 即可。
2. 不再增加 iframe 编辑协议、自动同步、跨内部档案的发布准备度规则。
3. 对只服务于旧设计的接口和组件，在调用方迁走后整链删除；官网专属业务数据和已发布文件不得随界面删除。
4. 本次未执行数据库迁移或数据修改。工作区原有的官网解耦在途改动需单独验证，不能由这次代码删减视为已验收。

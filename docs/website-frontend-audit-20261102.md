# 利强包装官网前端专项审计（代码与构建）

范围：本地 `corporate-website/`，以当前工作区为准，包含尚未提交的包材下线改动。未做真实浏览器、移动设备或搜索引擎抓取验收。

## 已确认

| 范围 | 证据 | 判断 |
| --- | --- | --- |
| 工程 | 独立 Vue/Vite 工程；`src/router/index.js` 装配页面 | 保留一套前端，不重建 |
| 内容来源 | `src/api/http.js` 生产默认走 `src/api/snapshot.js`；`public/content/` 有 45 个产品和 45 个详情，139 个官网媒体文件 | 静态首版不依赖开发代理或内部档案 API；内容仍需业务审核 |
| 包材 | 当前工作区将 `/packaging`、`/supplies`、`/molds` 转到 `/products`，移除导航和详情适配卡片；`Packaging.vue` 仍保留 | 暂停公开，不恢复全规格列表；后续精选系列设计需另行验收 |
| 联系 | 静态模式的 `InquiryFormModal.vue` 显示邮件、电话，不提交无接收端的在线表单 | 联系方式真实归属与接收人仍需人工核验 |
| 语言 | `index.html` 为 `zh-CN`；大部分页面文案直接写在 Vue 组件或中文快照中 | 不能把当前构建作为英文站发布 |
| SEO | `useSeo.js` 在客户端设置标题、canonical 和结构化数据；站点地图只有少量列表路由 | 产品详情抓取与社交分享预览尚未验证；需预渲染或等效静态 HTML 方案 |

## 逐页面改造清单

| 页面 | 现状 | 优先处理 |
| --- | --- | --- |
| 首页 `Home.vue` | Banner、精选产品、场景、公司实力、服务等区块较多；存在设备与包材并列的旧文案 | P1：核对每个区块的真实图片与销售目的；先突出主推设备、应用场景、工厂实力和联系入口，删去重复区块而不编造业绩 |
| 产品中心 `Products.vue` | 搜索、设备分类和四项侧栏筛选同时可见；数据从官网快照/API 适配层读取 | P1：默认突出搜索与设备分类；将应用、容器、工艺、产能放入可展开筛选，核对手机端操作；修正仍称 `website_enabled` 的旧注释 |
| 产品详情 `ProductDetail.vue` | 支持官网媒体、介绍、规格、参数、询盘；仍保留 API 模式的档案图片回退代码 | P0：静态首版核对每条产品名称、图片、参数与询盘入口；确认切换后再移除 legacy 档案图片回退；P2：产品详情静态预渲染与 SEO |
| 解决方案 `Solutions.vue` / `SolutionArticle.vue` | 官网快照提供分组数据；文章接口会按 slug 查找 | P1：逐条检查真实内容、失效文章链接、空状态与场景到产品的引导 |
| 关于利强 `About.vue` | 官网公司快照、历程及静态资质图片 | P1：核实公司事实、证书图片和联系方式；资质只展示已确认内容 |
| 联系入口 | `/contact` 转至关于页锚点；全局弹窗静态版使用 `mailto:` 和 `tel:` | P0：在预览域名实测手机与桌面联系动作；P1：设计独立联系页时避免伪提交表单 |
| 包材 `Packaging.vue` | 代码仍含规格展开列表，但已不在公开路由 | 暂停；取得代表系列、授权图片和审核文案后，再设计精选展示，不新增数据库表 |
| 404 | 独立页面 | 预览部署时验证深链接刷新与旧路由跳转 |

## 跨页面风险与验收

1. **内容准确性**：当前 45 条产品快照的名称、简介、技术参数和主图需要销售与产品负责人逐条抽查；不能把占位宣传句当作已审核事实。
2. **域名与双语言**：当前 canonical、robots 和 sitemap 均固定中文域名。英文内容、英文构建、语言标记与对应页面齐备前，不绑定英文正式域名；详见 `website-bilingual-deployment-plan.md`。
3. **搜索抓取**：Vite SPA 的路由 SEO 在浏览器执行后才生效。部署预览后必须用抓取工具检查产品详情 HTML、canonical、结构化数据和分享卡片；必要时为公开路由预渲染。
4. **联系方式**：静态模式打开邮件客户端不等于询盘送达。上线前由业务人员确认公开邮箱、电话和海外可用联系渠道，并做实际收信测试。
5. **视觉与性能**：代码审计不能替代真机检查。需在桌面及常见手机尺寸查看首页、产品筛选、详情图库、弹窗、方案页和关于页；同时检查首屏图片体积及加载。

## 执行顺序

先完成中文设备产品内容审核和预览部署检查，再精简首页与筛选交互；包材保持下线。英文站按独立内容审核与构建门槛推进。CMS、包材新模型和在线询盘服务均不阻塞中文首版静态预览，但不能以当前邮件跳转冒充在线表单。

# 销售订单执行中的交期变更

本阶段支持：销售订单已经确认，关联生产任务已接单／生产中，或采购订单已确认／收货中时，客户交期的受控调整。客户确认、执行方复评、销售审批缺一不可。

## 操作顺序

1. 在销售订单明细或生产需求／采购订单入口登记“无法履约”异常。该明细暂停新建执行单据和出库办理，实际到货仍可记录。
2. 销售打开订单详情，在该异常行点击“申请数量／交期变更”。已有执行单据时保持原数量，只修改交期，填写客户确认依据。
3. 车间或采购打开“销售需求履约评审”，在“已确认订单的变更复评”中点击“复评变更”。核对关联单据的状态、数量、累计报工量和已入库／收货量，填写执行协调安排，并勾选“已核对全部关联单据”。报工量为各工序数量合计，不代表整机完工台数。
4. 销售审批人在订单详情核对客户确认依据、执行方意见和“复评时单据快照”，批准变更。
5. 系统更新销售明细交期、递增订单版本、解除这条异常；未完成生产任务的需求交期同步更新。采购订单详情显示当前销售需求交期和订单版本。

## 日期的含义

| 字段 | 变更审批后的处理 |
| --- | --- |
| 销售明细要求交期 | 更新为客户确认的交期；留空则继承订单头交期 |
| 未完成生产任务的需求交期 | 同步当前销售要求 |
| 生产计划开始／完成日期 | 保留，执行方根据复评安排管理排产 |
| 已完成／关闭／取消任务的需求交期 | 保留历史值 |
| 采购预计到货日期 | 保留供应商执行计划，独立于客户要求交期 |
| 报工、质检、入库、收货事实 | 保留原记录 |

## 测试建议

请在测试订单上验证以下情形，不要随意修改真实客户订单。

- **生产中调整交期**：确认一条自产订单，生成生产任务并接单；登记异常，只改变销售交期；车间核对并复评、销售批准。检查订单版本加一、生产需求交期同步、原报工及计划日期保留。
- **采购已确认后调整交期**：对关联采购订单登记异常；采购填写与供应商协调的依据；销售批准。采购详情应显示新销售需求交期，采购预计到货日期保持原值。
- **复评后发生报工／收货**：执行方通过复评后再发生报工或收货，刷新销售详情，应看到“执行情况已变化”。审批会被拦截，点击“重新送复评”，重新核对后才能批准；期间异常保持打开。
- **漏填协调意见**：有下游单据时不勾选确认或不填协调安排，复评通过应被拒绝。
- **历史记录保护**：已完成的生产任务可以参与交期复评，但其历史需求交期和已完成事实保持原值。
- **越界情况**：已有下游单据时改变数量，或者存在审批中的下游单据、任何关联出库记录，复评通过应被拦截。

## 尚未支持

已有执行单据的数量／产品配置变更、已发货后的商业变更，以及变更导致的返工、取消采购、退货和费用处理，需要后续专门流程。本阶段不会自动改写这些记录。重新送复评时，上次意见与快照写入审计日志，当前申请重新等待执行方复评。

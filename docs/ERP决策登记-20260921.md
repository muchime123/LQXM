| 13 | 编码策略 | **非空编码终身占用**（`UNIQUE(code)`），停用不复用、可恢复原对象；草稿可无编码 | **09-21 收口** |
| 14 | 审计契约 | `row_change_log.operator_id` **必填**（姓名快照同记）；审计与业务**同事务**，双向回滚 | **09-21 收口** |

| 16 | 出厂检验环节（U4 收口） | **无人工检验动作**（车间仅做出厂前调试，无签字/打勾）。`manufacturing_inspections` + 返工机制**保留不删**；当全单不存在 `requires_inspection=1` 的工序时，**必做工序全部报工即自动放行至 `PENDING_RECEIPT`**（当前 14 道工序全 = 0 → 全自动）。开关 = `manufacturing_operations.requires_inspection`（改一处即切换，**无需改代码**）。⚠️ 自动确认**不写检验记录**（`manufacturing_inspections` 保持 0 行，`inspection_at/by` 保持 NULL）；记录的语义是「工序完成事实」不是「内控检验」——页面/报表**不得**表述为"已检验合格"，不适用"检验不能自检自"的内控要求 | **09-21 拍板**｜✅ **09-21 已落地**（代码 + `V318` + 7 用例全绿，`MO00000018` 已解冻；详见 `检验环节处置方案-20260921.md` §9） |
| 17 | 领料 / BOM / 材料单位 | **不建**。车间自采自存、独立核算、无客户，领料发生在车间自己账内 → 利强侧**不建领料单、不建材料库存账、不建 BOM 主数据**。完工入库视角 = **仓库收货**（历史源：内部车间作为"供应商"出现在采购入库，**3,331 单**、明细 35,173 行，工单关联率仅 19% → 上线门槛）。将来若纳入按**新增流程**做，**不在首批表上预留 BOM/材料字段** | **09-21 拍板**｜详见 `车间自治下的领料定位-20260921.md` |
| 18 | M0 契约与业务写入的绑定 | **幂等模板与审计写入器必须与「业务写入」绑定同一个 DataSource + 同一个事务管理器**（同一份实现、两个绑定，不复制逻辑）。当前状态：业务表在 `product_archive`（含制造域）→ 用 `archiveIdempotencyService` / `archiveAuditWriter`，契约表以 `erp.idem_request` / `erp.row_change_log` **限定名**访问（同一 MySQL 实例，仍是一条连接一个事务）；`erp` schema 内业务 → 用 `erpIdempotencyService` / `erpAuditWriter`。⚠️ **新增写路径先问「我的业务表在哪个库」** —— 选错不报错，只是幂等与审计静默失效。⚠️ 连带约束（U9）：拆 DB 账号后，主库账号必须被授予 `erp.idem_request` / `erp.row_change_log` 的 INSERT 权限，否则**所有主库写路径**会在写幂等键时失败 | **09-21 落地**｜见 `config/ErpContractConfig.java`、`车间执行段落地记录-20260921.md` §3 |
| 19 | 审计载荷完整性 | ① `row_change_log.changed_fields` **不得静默降级**：载荷里只要有一个 `LocalDateTime`/`LocalDate` 而 `ObjectMapper` 未注册 Java 8 时间模块，整条载荷就变成 `{"_serializationError":…}` —— 行还在、「改前改后」全丢。**不变量：`_serializationError` 行数恒为 0**（已加回归断言）。② `target_table` **统一带 schema 限定名**（`product_archive.manufacturing_orders` / `erp.party`），两侧表可能重名，裸表名会让「改了哪张表」产生歧义。③ 客户端写动作**必须携带请求键**：同一次提交的重试复用同一个键，新的一次提交换新键（前端在打开弹窗时生成、失败保留、成功后丢弃） | **09-21 收口**｜见 `车间执行段落地记录-20260921.md` §4.3 |

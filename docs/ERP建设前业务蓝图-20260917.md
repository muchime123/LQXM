# ERP 建设前业务蓝图

版本：v0.1 · 2026-09-17  
状态：可评审的设计草案；不是已批准的生产业务规则或数据库实施方案。

## 1. 已确认的建设原则

**已导入的氚云数据 = ERP 设计的参考样本与口径验证场，不是未来 ERP 的生产数据层。**

本文件的规则分三类：

- **已确认**：用户在本次会话明确给出的方向。
- **建议**：本蓝图提出的设计方案，可以继续用于原型和验证，不代表业务已批准。
- **待确认**：会影响正式数据结构、记账结果或岗位职责的业务选择。

已确认的是数据定位与继续开展建设前准备。以下范围、流程和核算方案均为建议，不能因文档落地而视为已经拍板。

### 1.1 历史口径与 ERP 规则的边界

| 历史样本处理方式 | 对未来 ERP 的含义 |
|---|---|
| 历史回款以氚云销售出库为可信依据 | 不意味着未来由出库单累计字段代替收款单和核销关系 |
| 产品信息与仓库明细组合成库存快照 | 不意味着未来库存余额继续由导入快照驱动 |
| 历史采购价可作为价格参考 | 不等于已经选择库存计价方法，也不等于生产成本或销售成本 |
| 不导入停更的氚云盘点表 | 不意味着未来 ERP 不需要盘点和差异调整 |
| 导入时容忍脏值并告警 | 不意味着正式业务录入、审核和过账也允许同样问题 |
| 原系统名为“采购入库”的表包含内部车间 | 不意味着这些记录全部属于外部采购业务 |

旧文档中的“权威来源”“事实层”“正式主数据”等措辞限定在其历史台账上下文；不能据此直接认定现有表是 ERP 正式模型。本蓝图不改变现有业务运行行为。

### 1.2 建议的数据分区

1. **历史样本区**：源文件、批次、原文、解析结果及质量问题。保留来源身份，不因 ERP 主档变化改写原文。
2. **设计验证区**：脱敏案例、规则版本、预期结果、实际结果、人工裁决。验证过程不影响生产余额。
3. **ERP 正式业务区**：经确认的主数据、新单据、业务分配关系、库存事件和核销记录。

三个分区先按职责隔离；是否分库、分 schema 或采用独立表，待技术设计确定。正式业务不能依赖氚云重新导入才能正确运行。历史映射只能作为可追溯的参考关系，不自动升级为正式主档身份。

## 3. 建议的建设范围与推进门槛

### 3.1 第一条验证闭环

建议先用**一个待选公司主体、一个待选仓库、一组标准库存商品**验证：

采购订单 → 收货入库 → 库存 → 销售订单 → 销售出库 → 收付款及分配 → 退货与冲销。

选择标准商品的目的是先验证数量、金额、状态和关系。公司、仓库及商品组由业务选定，当前不指定真实对象。它是验证切片；如果第一期上线包含自制商品，生产链必须同步满足上线条件，不能借试点范围省略正式生产业务。

### 3.2 阶段和退出条件

| 阶段 | 交付物 | 完成条件 |
|---|---|---|
| G0 业务准备 | 本蓝图、主数据字典、决策登记、验收用例 | 试点范围及影响试点模型的关键规则有业务结论 |
| G1 沙箱闭环 | 标准商品端到端原型、事件与分配模型 | 本文适用用例通过；重新计算余额与汇总结果一致 |
| G2 生产及复杂业务 | BOM/工艺/领退料/完工、调拨、实际开票等 | 每条纳入上线的业务有责任人、规则、异常处理和验收证据 |
| G3 上线准备 | 正式主档、期初、未结单据、切换与恢复方案 | 业务签认期初和未结事项；切换、对账、恢复演练通过 |

薪酬、完整会计总账、设备维护等是否纳入不从现有菜单推断。税务申报或会计政策另行专业确认；此处只定义业务信息与关系，不作法规或会计准则结论。

## 4. 主数据字典初稿

下表是概念对象，尚未决定物理表名。稳定内部 ID 用于关联；名称、电话、外部编码用于描述或识别证据，不能单独保证身份。

| 对象及粒度 | 建议的关键字段 | 核心约束 | 责任岗位（待指定人员） |
|---|---|---|---|
| 公司：一个经营/核算主体 | 内部 ID、编码、名称、状态 | 单据明确所属主体；部门不代替公司 | 管理负责人、财务 |
| 部门/车间：一个组织单元 | 公司、上级、编码、类型 | 内部车间与供应商角色分开 | 行政、生产 |
| 员工：一个自然人员工身份 | 内部 ID、组织、任职有效期、状态 | 同名不合并；离职不删除历史责任 | 人事 |
| 往来方：一个可识别交易对象 | ID、类型、名称、主体标识、客户/供应商角色 | 电话、名称相同不自动合并；个人对象允许无企业税号 | 销售、采购、财务 |
| 经销关系：一项渠道关系 | 往来方、渠道、有效期、适用主体 | 建议与往来方分开；关系变化不覆盖历史归属 | 销售 |
| 联系人/地址：往来方的一个联系点 | 归属、联系人、电话、结构化地址、有效状态 | 历史单据保留当时的收货快照 | 销售、采购 |
| 产品 SKU：一个可区分的交易/库存对象 | ID、编码、名称、规格、类型、基本单位、状态 | 同名不同规格不合并；非库存服务不得写实物数量账 | 产品、采购、生产 |
| 定制配置：产品的一版业务配置 | 产品、配置版本、参数、图纸版本 | 是否产生新 SKU 待确认；已执行订单保留版本 | 技术、生产 |
| 单位换算：产品的有效换算规则 | 基本单位、辅助单位、比率、精度、有效期 | 无明确换算不得跨单位相加；历史明细保存当时比率 | 仓库、产品 |
| 仓库/库位：一个存放地点 | 公司、仓库、库位、状态 | 存放地点与货权主体分别表达 | 仓库、财务 |
| 开票资料：往来方的一版资料 | 主体、税号、地址、银行资料、有效状态 | 同户名不自动合并；单据使用当时快照 | 财务 |
| BOM/工艺：产品的一版制造定义 | 版本、组成、用量、损耗、工序、有效期 | 已下达工单锁定版本；变更有记录 | 技术、生产 |

建议物料分类至少区分成品、半成品、原材料、零部件、模具、耗材和服务；具体库存属性、资产属性及编号规则待业务确认。名称拼接不充当永久业务主键。

## 5. 单据、状态与业务影响

### 5.1 共同规则（建议）

- 单据生命周期：草稿 → 待审核 → 已审核；驳回回到可编辑状态。执行进度另记未执行/部分执行/全部执行/关闭，避免用一个状态混表达审批和履约。
- 草稿、驳回、未过账单据不产生库存或资金业务影响。审核与过账是否同一步按单据明确，不能默认全系统相同。
- 已产生下游影响的单据禁止直接覆盖数量、金额或删除；采用有原单引用的退货、退款、冲销或更正单。
- 数量和金额关系落到明细行。允许一单多次执行、多个来源汇总，但累计执行不得超过允许额度；超量容差待确认。
- 收款和付款各是一份事实，核销是独立分配关系；修改分配不生成第二笔资金事实。
- 发票申请不等于实际开票，订单不等于已经出入库，完成报工不等于已经通过检验入库。

### 5.2 单据影响矩阵

| 单据/动作 | 库存影响 | 资金/往来影响 | 必须保存的关联 |
|---|---|---|---|
| 销售订单审核 | 是否占用按 D04 决定，不减少现存 | 应收确认时点按 D06 决定 | 客户、公司、订单明细 |
| 销售出库过账 | 可发库存减少一次 | 不自动视为已收款 | 订单行、实际出库行 |
| 销售退货入库 | 指定退货状态库存增加 | 退货抵扣与退款分别记录 | 原出库行、退货原因 |
| 采购订单审核 | 不增加现存 | 不视为已付款 | 供应商、公司、订单明细 |
| 采购收货/验收入库 | 收货、待检、可用状态须区分；实物只记一次 | 应付确认时点按 D06 决定 | 采购行、收货/检验结果 |
| 采购退货出库 | 对应库存减少 | 退款与应付抵扣分开 | 原入库行、退货原因 |
| 收款/付款确认 | 无 | 一笔资金事实；可形成未分配余额 | 往来方、公司、账户、凭据 |
| 核销/取消核销 | 无 | 分配或释放可核销金额，不重复收付 | 资金单、往来项目、分配金额 |
| 调拨发出 | 调出可用减少、在途增加 | 同主体不视为销售；跨主体另行定义 | 调出行、目标仓、货权主体 |
| 调拨收货 | 对应在途减少、调入库存增加 | 差异单独处理 | 原调拨行、实收数量 |
| 生产领料/退料 | 材料仓与在制耗用关系变化 | 不直接作为供应商付款 | 工单、材料行、批次（若启用） |
| 完工入库 | 合格产成品库存增加 | 成本结转规则按 D07 决定 | 工单、检验、产出行 |
| 盘点差异过账 | 按审核差异调整 | 差异原因及价值处理留痕 | 盘点范围、账面截点、实盘数 |
| 实际开票/红冲 | 无 | 开票余额改变，不重复生成收款 | 申请、实际发票、业务分配 |

## 6. 口径字典初稿

| 口径 | 建议定义及边界 | 未决事项 |
|---|---|---|
| 现存数量 | 指定截点已过账库存事件净额，按货权主体、地点、产品、基本单位及启用维度分组 | 批次、序列号、库位的启用范围 |
| 可用数量 | 建议为可用质量状态的现存减有效占用；待检、冻结、在途不重复扣减或计入 | 占用产生/释放时点、负库存政策 |
| 在途数量 | 已调出未完成收货或差异处置的数量 | 丢失、短收、分批收货处理 |
| 数量换算 | 交易数量 × 单据保存的换算比率 = 基本数量，按已确认精度舍入 | 产品适用比率、变动换算需求 |
| 单据金额 | 按明细金额、折扣、费用和税额规则汇总；不能混用含税与未税基数 | 舍入顺序、尾差、币种 |
| 可分配收款 | 已确认收款减有效分配及已退款等占用；退款与解核销须在同一规则下校验 | 预收款、跨客户/跨公司分配是否允许 |
| 未结往来 | 已确认往来项目，经退货、调整和有效核销后的剩余金额 | 应收应付确认事件 |
| 库存价值 | 正式期初价值与按确定方法计价的库存事件形成 | 移动加权/批次等方法、费用分摊 |
| 生产成本 | 材料、人工、制造费用等确定范围按工单/产品归集 | 实耗、损耗、委外、在制品分摊 |
| 开票进度 | 实际有效开票及红冲分配净额；申请金额只表示需求 | 合并开票、部分开票、超额规则 |
| 历史归属 | 单据保留发生时主体、业务员及关键价格快照；当前主档用于最新查询 | 转交业务归属和提成调整规则 |

数量守恒与金额守恒分别验证；不同单位、币种和公司不能未经转换直接汇总。所有参与核算的规则需记录版本或有效期，以便复算历史结果。

## 7. 样本问题转为入口与过账约束

| 问题 | 历史样本区 | ERP 正式业务建议 |
|---|---|---|
| 空壳地址 JSON | 保存原文、标有效内容为空 | 按场景要求有效地址；不以字符串非空判断通过 |
| 同名或同电话 | 作为候选证据，不自动认定唯一身份 | 引用确定的主档 ID；合并主档需审核与历史追溯 |
| 产品编码冲突 | 记录冲突与人工结论 | 编码唯一性按确认范围约束；冲突禁止新建或过账 |
| 未知单位/无换算 | 标记无法合计 | 阻止依赖换算的库存过账 |
| 缺价/金额不平 | 保留原始数值并告警 | 明确零价原因与权限；超过容差阻断过账 |
| 备注中的“调整库存” | 作为场景证据 | 选择结构化原因，关联盘点/报损等依据 |
| 文本引用单据 | 保留原文及候选关系 | 用单据及明细 ID 关联，名称仅展示 |
| 解析规则变化 | 保留原始文件、解析版本和差异 | 验证区可重放；不能用“源时间未变”掩盖规则变化 |

不是所有字段都全局必填：要求随单据和动作变化。例如草稿可缺字段，发货前必须满足收货信息和出库条件。

## 8. 验收案例基线

以下都是**为验证规则设计的合成数值**，不是氚云真实交易。待挑选真实样本后补充脱敏来源和映射；当前不声称已经通过测试。

| ID | 场景及输入 | 预期结果 |
|---|---|---|
| T01 | 零期初，采购入库 10 个；销售出库 4 个 | 库存 6 个；重算事件净额仍为 6 |
| T02 | 订单 10 个，分两次出库 4、6 个 | 执行进度先部分后全部；第三次出库被阻断（零超量容差假设） |
| T03 | 收款 1,000 元，向两笔同公司同客户往来分配 600、300 | 有效分配 900，未分配 100；再分配 101 被阻断 |
| T04 | 取消 T03 的 300 元分配 | 收款仍为 1,000，有效分配 600，未分配 400 |
| T05 | 入库请求成功后网络超时，使用同一请求键重试 | 返回同一结果；库存事件和余额只增加一次 |

## 10. 上线与技术设计准备

### 10.1 期初和未结事项

- 正式主档经责任人确认后启用；不能将所有历史字符串自动转成可用主档。
- 库存期初按共同截点盘点并核定价值；明确货权、在途、待检、寄存和在制品范围。
- 未结应收应付、未分配收付款、未完成订单、生产工单逐项确定接续方式。
- 防止重复：同一业务已计入期初的部分，不得再以历史单据重放一次；未完成单据仅接续剩余部分。
- 记录期初批次、确认人、来源和差异处理；上线后更正采用可追溯调整。

### 10.2 技术设计检查项

- 单据编号与内部 ID 分离；外部来源键及请求幂等键分别处理。
- 库存事件、余额更新和业务执行量保持事务一致；核销防止并发超额。
- 多维库存键根据 D03/D04/D05 决定，不沿用历史名称拼接键。
- 权限覆盖页面、接口、列表、详情、审核及数据范围；审计保存前后值、原因和操作者。
- 已审核记录保留快照和版本；基础档案停用不破坏历史引用。
- 对账同时验证明细、汇总、事件和余额，备份必须有恢复演练证据。
- 用样本规模测分页、批量提交和重算性能；响应时间目标及并发量由使用场景确定，不凭空承诺。

# P2-C 流水账户稳定关联：隔离验收（2026-10-27）

## 范围

候选 V442 为 `h3_cashflow_entries` 增加不可为空的 `account_id`、索引与到账户主档的外键；按相同 `external_source + account_name` 对历史流水回填。导入确认时先取得唯一账户 ID，随后在来源流水的 upsert 中同步写入 `account_id`。日记账账户汇总、月报、流水列表及来源结存检查按 `account_id` 查询，原 `account_name` 仍保留为来源名称。

本阶段只建设稳定关联基础。**账户改名操作仍未开放**：氚云 Excel 导入仍以 sheet 名确认来源账户，必须另行设计来源别名与重命名兼容，不能凭本次查询反证就允许在正式库改账户名。手工新增流水、修改、作废及导入差异人工匹配也未在本阶段开放。

## 验收

- 正式库只读预检：8,751 条流水全部唯一匹配账户，孤儿 0、歧义 0；正式表仍无 `account_id` 列。
- 在 `product_archive_p2c_isolated` 执行同内容候选 SQL（隔离执行时文件编号为 V418，随后因并行迁移占号改为 V442）：8,751/8,751 条回填，涉及 28 个有流水账户；35 户账户主档保持原样。编号变化不影响 SQL 内容；正式部署前仍须核对版本队列。
- 2026 年 35 户、420 个逐月末的旧名称口径与新 ID 口径：笔数和净收支全部一致。
- 隔离实例 18085 的 P1 回归 34/34；账户 687 临时更改主档显示名时，日记账与氚云历史台账的账户汇总均保持原期初、收支、期末及 3,211 条全年流水笔数；测试后已恢复名称。来源行的原账户名未改。
- 隔离库导入式 upsert 对同一来源键只保留一行，`account_id` 稳定；无效账户 ID 触发外键错误 1452；事务回滚后测试流水为 0。
- 2026-11-04 再次运行只读后验：8,751/8,751 条关联，使用 28 户账户，非法关联 0；外键与非空约束均存在。后验脚本为 `tools/verify_cashflow_account_id_postflight.py`，可在正式迁移后指定 `DB_SCHEMA` 复用。
- 后端编译、打包及 `CashflowJournalReviewServiceTest,H3CashflowSourceRowNumberTest` 通过。

## 部署边界

候选迁移仅在隔离库执行，正式库未执行，正式运行实例未部署此分支。部署前须停止或隔离资金流水导入写入，重新运行 `tools/preflight_cashflow_account_id.py`，备份目标表和账户表，再按正常 Flyway 顺序迁移并复核 8,751 条与 P1 34 项。MySQL DDL 不提供整份脚本事务回滚；若预检失败或出现部分迁移，停止部署并制定恢复方案，不能用 `repair` 或手工登记版本绕过。

本分支目前不是手工记账成品。下一阶段需要先让手工流水与导入流水拥有明确的来源、稳定内部 ID、幂等和审计契约，再开放财务录入入口。

## 3. 落地内容（V332）

1. **工序字典**：4 条同名复用（模具加工、采购/下料、控制板面板、组装调试 → 补氚云 UUID 与排序，受 `operation_name` 唯一键约束不能重插）；7 条新建；旧 11 条置 `active=0`（不删）。
2. **制程路线**：新建 7 条（`external_source='H3YUN'` + 氚云 UUID）；3 条在用、4 条停用；旧 7 条全部置 `active=0`。
3. **路线明细**：22 行照氚云子表落库（序号 / 是否尾道 / 系数 1 / `component_name`+`component_form` 同值照抄）；氚云那条空壳子行（称重机车间序号 1，无工序名）**不落**（无 `operation_id` 可绑，且业务上无意义）。
4. **车间默认制程**：称重机车间 → NULL；封口机车间 → 封口机车间；半自动气调机车间 → 半自动气调机；全自动气调机车间 → 全自动气调机。
5. 旧工序/旧模板一律**停用不删**，保住 4 张在产工单的工序快照与 `source_template_operation_id` 引用。

**幂等**：全部按 `external_source='H3YUN' + external_id`（氚云 UUID）判存在，可重复执行；实录复跑 15 条 INSERT 全部 0 行。
**应用方式**：本次由 JDBC 探针直接落库（未登记 `flyway_schema_history`）；下次应用启动时 Flyway 会再跑一遍 V332，因幂等而无副作用。

## 5. 待确认项（未决，勿当成已对齐）

1. **无制程产线下单**：称重机车间（氚云：是否有制程=否）现在没有默认制程，建单会被拒。**实际报错文案已实测更正**（2026-09-23 10:13 LQ 在车间执行页抽屉里建单复现）：`ManufacturingService.create()` 抛的是 **「产品未关联制程，且车间未设置默认制程」**（HTTP 400），不是本文原先写的「请选择生产车间以确定产品或车间默认制程」——后者只在 `workshopId` 为空时才出现，而抽屉里产线是必选。需定：允许**无工序建单**（照氚云"无需报工/外购"语义），还是明确该产线不走生产任务单。
   **量化证据（09-23 补，源 = 氚云《生产任务单管理》全量 5,691 行，导入批次 157）**：
   - `产线选择(必填)` 分布：封口机车间 5,057 / 全自动气调机车间 400 / 半自动气调机车间 234 / **称重机车间 0 张**。
   - `选择制程(必填)` × 产线 交叉：封口机车间 5,057 张里 = 同名制程「封口机车间」2,110 + 「订做封口机（5楼）」2,025 + 「返单封口机/模具加工（5楼）」738 + **「无需报工」180** + 空 3；全自动 392 张选同名制程；半自动 231 张选同名制程；另有 **11 张产线与制程不同名**的零星单（疑人工选错，全自动 8 / 半自动 3）。
   - `是否有制程=否` 恰好 **180 张**，与上表「无需报工」那 180 张完全重合，**全部落在封口机车间产线**。
   - 结论：**「无制程」在氚云里是一个被人显式选出来的制程值（无需报工），不是漏配**；而称重机车间是**历史 0 单的空产线**（3 个产品名称配置齐备，但从未下过任务单）。因此「称重机车间建单失败」当前**不阻塞任何真实业务**，真实要覆盖的是「无需报工」这 180 张的语义。
2. **产品名称 → 制程路线 的映射无载体**：氚云三张表里没有这个字段（`manufacturing_task_config_items.process_template_id` 全为 NULL），封口机车间 20 个产品名称目前一律走「封口机车间」路线。若业务上要按产品分路线，需业务给出映射表。
3. **封口机车间路线只有 1 道工序**（模具加工，且是尾道），与同车间另两条路线的工序量差异大，导出件如此；建议与车间核对是否导出不全。
4. **《制程表》的「库存数量」列**：11 行里 3 行值为 2（模具加工、表面处理/氧化、表面处理/喷塑），语义不明，已照抄入 `manufacturing_operations.source_inventory_quantity`，待确认是否废弃。
5. **氚云子表三列同值**：`数据标题 / 零部件表单 / 零部件名` 取值完全相同，已同时落 `component_name` 与 `component_form`；若业务上本应区分（例如"零部件"≠"工序"），需重新给口径。
6. **氚云是「按单选制程」，ERP 是「按产线默认制程」—— 这个差异由 09-23 实测新增**（见 §5.1 交叉表）：氚云表单里 `产线选择(必填)` 与 `选择制程(必填)` 是**两个独立必填字段**，同一产线可分派到不同制程（封口机车间即有 4 种走法）。ERP 建单抽屉只有「产线」，制程由 `manufacturing_workshops.default_process_template_id` 推出（见 `ManufacturingTaskTemplateResolver.resolve`）→ 结果：**封口机车间那 735 张「订做封口机 / 返单」历史单，在 ERP 里会一律套用「封口机车间」路线（仅 1 道工序）而不是各自的 3~4 道工序路线**。LQ 09-23 已定「制程跟随产线」（提交 `a8ea617` 文案修正），因此这里需要确认的是：这个压平是**认可**（旧路线随老厂停用、今后不再区分），还是**需要把「制程」也做成建单必选项**（照氚云）。

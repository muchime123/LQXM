## 3. 落地内容（V332）

1. **工序字典**：4 条同名复用（模具加工、采购/下料、控制板面板、组装调试 → 补氚云 UUID 与排序，受 `operation_name` 唯一键约束不能重插）；7 条新建；旧 11 条置 `active=0`（不删）。
2. **制程路线**：新建 7 条（`external_source='H3YUN'` + 氚云 UUID）；3 条在用、4 条停用；旧 7 条全部置 `active=0`。
3. **路线明细**：22 行照氚云子表落库（序号 / 是否尾道 / 系数 1 / `component_name`+`component_form` 同值照抄）；氚云那条空壳子行（称重机车间序号 1，无工序名）**不落**（无 `operation_id` 可绑，且业务上无意义）。
4. **车间默认制程**：称重机车间 → NULL；封口机车间 → 封口机车间；半自动气调机车间 → 半自动气调机；全自动气调机车间 → 全自动气调机。
5. 旧工序/旧模板一律**停用不删**，保住 4 张在产工单的工序快照与 `source_template_operation_id` 引用。

**幂等**：全部按 `external_source='H3YUN' + external_id`（氚云 UUID）判存在，可重复执行；实录复跑 15 条 INSERT 全部 0 行。
**应用方式**：本次由 JDBC 探针直接落库（未登记 `flyway_schema_history`）；下次应用启动时 Flyway 会再跑一遍 V332，因幂等而无副作用。

## 5. 待确认项（未决，勿当成已对齐）

1. **无制程产线下单**：称重机车间（氚云：是否有制程=否）现在没有默认制程，`ManufacturingService.create()` 会抛「请选择生产车间以确定产品或车间默认制程」。需定：允许**无工序建单**（照氚云"无需报工/外购"语义），还是明确该产线不走生产任务单。（同一问题也覆盖「无需报工」场景。）
2. **产品名称 → 制程路线 的映射无载体**：氚云三张表里没有这个字段（`manufacturing_task_config_items.process_template_id` 全为 NULL），封口机车间 20 个产品名称目前一律走「封口机车间」路线。若业务上要按产品分路线，需业务给出映射表。
3. **封口机车间路线只有 1 道工序**（模具加工，且是尾道），与同车间另两条路线的工序量差异大，导出件如此；建议与车间核对是否导出不全。
4. **《制程表》的「库存数量」列**：11 行里 3 行值为 2（模具加工、表面处理/氧化、表面处理/喷塑），语义不明，已照抄入 `manufacturing_operations.source_inventory_quantity`，待确认是否废弃。
5. **氚云子表三列同值**：`数据标题 / 零部件表单 / 零部件名` 取值完全相同，已同时落 `component_name` 与 `component_form`；若业务上本应区分（例如"零部件"≠"工序"），需重新给口径。

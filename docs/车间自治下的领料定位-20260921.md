# 车间自治下的领料定位与数量闭环修订

日期：2026-09-21
触发：LQ 澄清「生产端的领料、材料单位、BOM 都在各车间内部由车间自己管理，我们这边不清楚；各车间相对独立，不太能统一设计」
落点：决策登记 #4 修订、新增 #17、U5/U6/U7 消解

---

## 1. 核实事实

| # | 事实 | 证据 |
|---|---|---|
| F1 | **车间自采自存**，料不进利强仓库 | LQ 2026-09-21 确认 |
| F2 | ERP 侧根本没有"料"这种东西 | `material_items` **0 行**；`material_inventory_balances` / `material_inventory_transactions` **0 行**；`manufacturing_material_movements` **0 行** |
| F3 | 车间已建模，带默认工艺路线 | `manufacturing_workshops` **4 行**：称重机车间 / 半自动气调机车间 / 封口机车间 / 全自动气调机车间（`default_process_template_id` 部分已填） |

> F5 + F6 组合解释了整个现象：车间自己买料、自己生产、再把成品"卖"给利强 → **利强记采购入库**。所以料永远不出现在利强的账上。

---

## 2. 结论一：领料段移出首批

领料是**车间内部的用料行为**，发生在车间自己的账里。利强侧没有这个事实，也不承担这个事实。

→ **不建领料单、不建材料库存账、不建 BOM 主数据。**

---

## 3. 为什么这不是妥协

1. **BOM 没有消费方。** BOM 的用途只有两个：算"应该领多少"、归集材料成本。领料不做 → 没有实际用量可比对；成本账首批不做（决策 #10）→ 没有归集对象。**建了没人用。**
2. **物料主数据没有来源。** 车间用自己的叫法买料，利强既不采购也不经手，既无法给料编码，也无从维护名称归一。
3. **历史 0 行 → 将来加是「新增流程」，不是「改造流程」。** 与序列号决策 #3 完全同构：因为历史领料单本来就不存在，将来若要求车间纳入统一采购，新开一张表即可，**无需迁移任何历史行**。所以现在在既有表上预留 BOM / 材料字段**没有收益**，只会变成僵尸列（`formal_*` 五表已有前车之鉴 → 勿复用勿删）。
4. **单位不需要"统一"，因为不需要"共存"。** U5 原问法是"材料单位怎么定"，隐含要建一套材料单位体系；没有材料主数据，这个问题从前提上就不成立。

## 4. U5 / U6 / U7 处置

| # | 原问题 | 处置 |
|---|---|---|
| U5 | 材料单位与小数精度 | ✅ **消解**。不引入材料数量字段。通用技术约定（数量/比率一律 `Decimal(24,9)`、禁二进制浮点、`nEq` 容差 1e-9）保留为规范 |
| U6 | 工单/BOM 或领料依据 | ✅ **消解**。不建 BOM 主数据 |
| U7 | 损耗与退料规则 | ✅ **消解**。无领料则无退料、无损耗计量 |

---

## 5. 结论二：完工入库有历史源，视角必须是「仓库收货」

F6 说明一件事：**"车间完工 → 利强收货"这条流程一直在跑**，只是没在 ERP 里正规化。这既给了首批一个可对拍的样本，也确定了两件事：

- **登记主体 = 仓库（收货方），不是车间。** 它是**入库事实**，与领料的发起方向相反：领料是车间发起、仓库经手；收货是车间交付、仓库确认。所以 ERP 的入口应落在**仓库岗**。
- **单证形态 = 入库单，不是"完工报告"。** 车间交付 + 利强收货确认，两个动作分开。
- ⚠️ **F7 的 19% 是上线门槛**：ERP 若要求收货行强制绑定生产工单，历史数据无法直接迁移消化。要么接受历史弱关联，要么上线前补绑。

## 6. 修订后的数量闭环

原文（决策 #4）：`领料 → 报工 → 完工入库`
**修订为：`工单 → 报工 → 车间交付收货 → 销售出库`**

| 段 | 历史源 | 状态 |
|---|---|---|
| 工单 | 氚云生产工单 5,691 单；`manufacturing_orders` | 有源 |
| 报工 | 氚云报工（工序构成 14,367 行）；`manufacturing_work_reports` | 有源 |
| 车间交付收货 | `purchase_receipts` 内部车间 **3,331 单** | **有源**（此前误判为"要从零建车间界面"） |
| 销售出库 | `sales_outbounds` | 有源 |

→ **四段全部有历史样本。** 首批工作量从"从零建车间操作界面"变成"**把已在跑的流程正规化 + 补工单绑定**"。

---

## 7. 需要如实记录的缺口

数量闭环里**唯一没有源的就是"料"**，而它现在是**有意不纳入**的（§2）。这意味着：

- ERP 的库存数量账只覆盖**成品**（机器 / 模具 / 片膜 / 卷膜），**不覆盖材料**；
- 因此**不得声称"材料成本 / 毛利可算"**——与决策 #10（首批不做金额账、页面不得显示正式库存价值与毛利）一致；
- 若将来要算材料成本，前置条件两步，且**都在车间侧**：① 车间把料的采购纳入利强主体或提供料主数据；② 一次材料期初盘点。**这两步不是 ERP 能单方面解决的**，且第 ② 步会再触发一轮"单位口径统一"，成本不低。

---

## 8. 将来若要纳入，怎么新增

因为历史 0 行，这张表**可以随时新增，不影响任何既有表**：

```
workshop_material_issue（新表，现在不建）
  workshop_id              -- 哪个车间
  material_item_id         -- 利强口径的料（前置：先建料主数据）
  quantity + unit          -- 仓库单位
  issued_at / operator     -- 谁领、何时
  manufacturing_order_id   -- 可选，不强制
  local_name / local_unit  -- 车间本地叫法（原样存，不解析）
```

→ **所以现在不在 `manufacturing_orders` / 任何首批表上预留 BOM 或材料字段。** 预留 = 僵尸列。

---

## 9. 边界纪律（写给后来的人）

> **利强 = 经营主体 + 成品仓。车间 = 独立采购 + 独立生产 + 独立核算。**
> 两者之间走的是**收货 / 交付**关系，**不是领料关系**。
>
> 任何"把车间内部用料拉进 ERP"的需求，本质上是在要求车间把**内部核算并入利强** —— 那是**主体合并**问题（法务 + 财务），不是建模问题。

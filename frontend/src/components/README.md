# Components Ownership

组件是否应该独立拆分，**不应该只根据"是否被多个页面复用"**。

即使只在一个页面使用，只要满足以下任一条，就应该保持为独立组件：

## 拆分判断标准（5 条）

1. **拥有独立业务职责** —— 如"账号列表""分析图表""更新记录""导入预览"，业务边界清晰
2. **拥有独立状态** —— 有自己的 ref/reactive/computed/watch，不依赖父组件的大量局部状态
3. **可以单独测试** —— 输入 props + 输出 emits，能够独立编写单元测试
4. **影响父页面可读性** —— 代码行数 > 200 行，或模板嵌套层级 > 5 层，抽离后父组件更清爽
5. **有独立的编辑 / 列表 / 预览 / 统计功能** —— 天然就是完整的业务子模块

## 页面定位：编排层

页面（`views/*.vue`）应该是**轻量编排层**，只做以下事情：

- 维护页面级全局状态（筛选条件、选中项、当前激活的抽屉/弹窗）
- 组合子组件，传递 props，监听 emits
- 调用 API，在子组件之间分发数据
- 页面级样式布局（间距、分栏、sticky header 等）

```
MediaAccountView（编排层，< 500 行）
├── MediaAccountToolbar      （搜索、筛选、操作按钮）
├── MediaAccountTable        （账号表格、列配置、分页）
├── MediaAccountDetail       （账号详情抽屉）
├── MediaUpdateTimeline      （更新记录时间线）
├── MediaAnalyticsPanel      （数据分析面板/抽屉）
└── MediaImportDialog        （导入预览弹窗）
```

## 目录规范

- `common/`：跨页面通用组件（预览、空状态、加载、弹窗、页面布局、搜索、分页、状态标签等）
- 业务模块目录（`product/`、`company/`、`media/`、`certificate/`、`document/`、`packaging/`）：
  - **只被该模块页面使用的业务组件** → 放在对应模块目录
  - **跨模块复用的** → 提升到 `common/`

## 反模式：超级组件

任何单文件 .vue 超过 **500 行** 或 **50 KB** 都应审视是否需要拆分。

以下情况绝对不能强行合并子组件回父页面：

- 子组件有独立的编辑/列表/预览/统计功能
- 子组件有超过 10 个 ref/computed 的独立状态
- 合并后父组件超过 800 行
- 子组件可作为独立单元被测试

（历史教训：强行合并 product 子组件回父页面，引发大量模板/声明冲突，维护成本指数级上升）

## 代码复用的其他层级

组件拆分 ≠ 所有东西都要拆成组件，对应层级的复用继续放在：

- API 请求 → `src/api/`
- 可复用逻辑（状态+行为）→ `src/composables/`
- 格式化、校验、下载、文件处理 → `src/utils/`
- 常量和选项 → `src/constants/`
- 全局样式 → `src/styles/`
